# Q0.9.1 — Existing Execution Path Audit

Read-only audit performed before any Q0.9 code was written. Confirms the exact call chain a real backtest must follow, so the new backend adapter reuses it exactly rather than reinventing it.

## The chain

```
StrategySpec (frontend, matches spec_engine/schema.py's dict shape 1:1)
  -> validate_spec(spec)                          [spec_engine/schema.py]
  -> quant_lite_risk_config(**kw) -> RiskConfig    [spec_engine/quant_lite_risk.py]
  -> run_spec_backtest_mtf(df_signal, df_exec, spec, risk)  [spec_engine/execution_mtf.py]
       -> compute_all() + evaluate_entry()          [spec_engine/indicators.py, interpreter.py]
       -> from engine import summarize              [quant_engine/engine.py, local import]
  -> (trades_df, equity, stats)
```

## Entry point

`run_spec_backtest_mtf(df_signal, df_exec, spec, risk)` — `quant-engine/spec_engine/execution_mtf.py:48`. Pure library function, **no CLI, no `__main__` block**. Returns `(trades_df, equity, stats)`. Raises `ValueError` if `validate_spec(spec)` returns errors.

`sys.path` bootstrap required before importing it (every existing caller does this identically):
```python
sys.path.insert(0, <scripts dir>)
sys.path.insert(0, <quant-engine dir>)
sys.path.insert(0, <quant_engine (sibling, min) dir>)
```
This is required because `execution_mtf.py:220` does `from engine import summarize` as a **local import**, resolved against `quant_engine/engine.py` (the sibling min-package), not a relative import.

## Strategy representation

`spec_engine/schema.py` defines no dataclasses — the spec is a plain dict, validated by `validate_spec(spec) -> list[str]`. The frontend's `StrategySpec` TypeScript type (`frontend/types/quant-lite.ts`) already matches this dict shape field-for-field (confirmed by comparing against `q06_cross_engine_test.py`'s literal `SPECS`), so **no strategy-mapping layer was needed** — the frontend `strategy` object is passed to the engine almost verbatim (see `Q0.9_RESULT_CONTRACT.md`).

## Risk wiring

`quant_lite_risk_config(**kw) -> RiskConfig` (`spec_engine/quant_lite_risk.py:35`) pins `use_breakeven`/`use_trailing`/`use_partial` to `False` after applying caller kwargs — this is the 4th positional arg (`risk`) to `run_spec_backtest_mtf`. Q0.9 passes `risk_pct`, `spread_price` (fixed `0.30`, Q0.6's own value), `contract_size` (fixed `100`), and `start_balance` (= the request's `initialCapital`) through unchanged.

## Market data

No shared "market data DAO" exists — every prior script (`q06_cross_engine_test.py`) opens `quant_engine/market.db` directly, read-only, via `sqlite3.connect(f"file:{DB_PATH}?mode=ro", uri=True)`. Only `_EXNESS`-suffixed symbols have 1-minute candle + `candle_spread` data — `run_backtest_job.py` (Q0.9's new runner) restricts real execution to exactly those 6 symbols, matching the frontend's server-side `dataCoverage.ts` gate.

## What Q0.9 added, and where

A single new file, `quant-engine/scripts/run_backtest_job.py`, is the **only** new code on the Python side. It replicates the exact `sys.path` bootstrap and data-loading pattern above, adds a config-file/result-file CLI wrapper around `run_spec_backtest_mtf`, and does nothing else — no engine logic was duplicated or modified. `execution_mtf.py` itself is byte-for-byte unchanged from Q0.6.
