# Q1.4 COMPLETE — Cross-Platform Code Generation & Parity

**Verdict: Q1.4 PASS.**

Quant Lite can now generate real MQL4, MQL5, and Pine Script v5 source directly from a completed backtest's exact strategy specification — using the pre-existing, already-solid generators (reused, not rewritten), wrapped in a real API/UI, with two genuine security defects found and fixed along the way.

## 1. Existing codegen audit

`codegen_mql4.py`/`codegen_mql5.py`/`codegen_pine.py` were already mature and parity-conscious — all 10 indicators, AND-only entry logic, closed-bar semantics, ATR/PIPS SL/TP, risk-based sizing, and zero BE/trailing/partial code, all pre-existing and verified correct by direct reading + 73+42 automated checks. Full detail: `Q1.4_EXISTING_CODEGEN_AUDIT.md`.

## 2. MQL4 status

Verified: all 10 indicators generate correctly, closed-bar only (shift≥1), AND-only entry, ATR/PIPS SL/TP, risk-based sizing via tick-value mechanics, magic-number position identity, zero BE/trailing/partial. 6 golden strategies generated, deterministic, brace-balanced. No compiler available — static validation performed (documented, not hidden).

## 3. MQL5 status

Same verification as MQL4, plus indicator-handle lifecycle (init/release) and `MqlTradeRequest`-based order submission confirmed correct. Identical determinism/security results.

## 4. Pine status

Verified: `calc_on_every_tick=false`, no `lookahead_on` anywhere, Supertrend's inverted trend-sign convention correctly flipped to match Python/MQL, risk-based `qty` sizing via `syminfo.pointvalue`, SL/TP anchored to `strategy.position_avg_price` (the real fill, not the signal bar's close) with distance frozen at signal time — all confirmed by direct code reading.

## 5. 10-indicator verification

All 10 (EMA, SMA, RSI, ATR, MACD, BB, STOCH, ADX, DONCHIAN, SUPERTREND) verified in all 3 languages — 73 automated checks passing (`q14_indicator_matrix_test.py`), covering spec validity, generation success, and absence of position-management code per indicator per language.

## 6. Entry parity

AND-only semantics confirmed identical across Python/MQL4/MQL5/Pine (`&&`/`and` chains). No OR logic anywhere — the schema has no field for it, structurally impossible to express, not merely unimplemented. Closed-bar indexing explicit and verified: MQL reads shift 1 (current closed) / shift 2 (prev), never shift 0; Pine relies on its default non-repainting mode. No look-ahead found.

## 7. SL/TP parity

ATR-mode (`atr * mult`) and fixed-PIPS mode both verified identical in formula across all 4 surfaces. Same-bar SL/TP ambiguity is a documented `PLATFORM-DIFFERENCE` (a live broker's real order matching has no such ambiguity to resolve) — not a generator defect.

## 8. Position sizing

Audited: Python uses `contract_size`-based sizing; MQL4/MQL5 use tick-value-based; Pine uses `syminfo.pointvalue`-based. All three express the same *intent* (risk this % of equity per trade) via each platform's own real, necessarily-different unit-conversion mechanics — declared `PLATFORM-DIFFERENCE`, documented in-code (pre-existing) and in `Q1.4_PARITY_MATRIX.md`, never hidden.

## 9. BE/trailing/partial status

Confirmed absent from all three generators, structurally — not disabled, never built. Verified by keyword-scanning all 18 golden artifacts: zero matches for `breakeven`/`trailing`/`partialclose` anywhere.

## 10. Golden strategies

6 strategies (EMA, RSI, MACD, Bollinger, multi-indicator, fixed-PIPS SL/TP) × 3 languages = 18 real artifacts generated, all deterministic (byte-identical across repeat generation), all brace-balanced, one manually code-reviewed in full per language. Full detail: `Q1.4_GOLDEN_STRATEGIES.md`.

## 11. Cross-language parity matrix

`Q1.4_PARITY_MATRIX.md` — every supported feature is `EXACT` across all 4 surfaces; the only 2 `PLATFORM-DIFFERENCE` rows (same-bar SL/TP tie-break, position-sizing unit conversion) are inherent and pre-documented, not new findings; every `UNSUPPORTED` row is schema-structurally impossible to express.

## 12. Negative tests

Unsupported language, unsupported indicator, and an attempted OR-logic smuggle (via a bogus `entry_long_or` field) all correctly rejected or ignored — never silently approximated. Confirmed live via 4 automated tests against the real API.

## 13. Determinism

Same spec → same generator → byte-identical code, confirmed for all 3 languages via 12 automated tests against the real live API (`strategySpecHash`/`resultHash` also identical across repeat calls) — not just the offline script-level check.

## 14. Provenance

Every generation response carries `strategySpecHash`, `resultHash`, `generatorVersion`, `targetLanguage`, `generatedAt` — verified present and correctly typed/shaped via 6 automated tests; verified free of secret-like substrings.

## 15. API

`POST /api/quant-lite/codegen` — synchronous, server-authoritative validation (reuses Q0.9's `validateStrategySpecServerSide`), no filesystem paths/shell commands/template paths in the contract, spawns the real generator via the same secure `spawn(shell:false)` pattern as the backtest adapter. Verified live end-to-end.

## 16. UI

"Generate Code" panel added to the Results page (only after a completed backtest), offering MT4/MT5/Pine Script buttons, client-side blob download (deterministic filename from strategy name + language, no server-side file storage, nothing to "escape"), and the exact required disclaimer copy — verified live in the real browser: real backtest → real completed MACD result → Generate MT5 → real 200 OK API call.

## 17. Security

Two genuine template-injection vulnerabilities found via active testing and fixed this sprint (indicator-id code injection, name string-literal breakout) — full detail and before/after evidence in `Q1.4_SECURITY_VALIDATION.md`. No shell execution, no arbitrary filesystem access, no server-side execution of generated code, no secrets in output.

## 26. Known limitations

- No MetaEditor/MQL4/MQL5 compiler or TradingView Pine compiler is available in this environment — static validation (brace balance + manual review) was used per the sprint's own explicit fallback, not an actual compile pass. Documented, not silently claimed.
- The two security fixes (id/ref validation, name sanitization) close every injection vector found by this sprint's testing, but were not exhaustively fuzzed — a determined, more sophisticated attacker probing further edge cases was not attempted (out of proportion for this sprint's scope).
- The "Generate Code" UI does not currently gate on a per-generator "passed validation" flag (Part 19's "only show languages whose generator passed validation") beyond the fact that all 3 currently pass — if a future generator regressed, the UI would need a real health-check wired in, not assumed evergreen.
- Filename sanitization for downloads is client-side only (deterministic, safe, but not server-verified since no file ever touches the server's persistent filesystem in this design).
