# Q0.9 — Backtest API Contract

## `POST /api/quant-lite/backtest`

Creates (or reuses) a real backtest job. Returns immediately — the job runs asynchronously.

**Request body** (`BacktestRequest`, `frontend/types/quant-lite.ts` — unchanged from Q0.7/Q0.8):
```ts
{
  strategy: StrategySpec,       // indicators, entry_long/entry_short, risk
  symbol: string,                // must be one of the 6 real-execution symbols
  timeframe: string,             // must be "1h" (see Q0.9_EXISTING_EXECUTION_PATH.md)
  dateRange: { start: string, end: string },
  initialCapital: number,        // 100 - 10,000,000
  riskPct: number,               // 0.1 - 10
}
```
No filesystem path, shell command, or arbitrary code is ever accepted in this body — every field is a plain string/number validated against a closed set of rules (`services/quant-lite/backend/validateBacktestRequest.ts`).

**Response** (`ApiResponse` envelope, `data: CreateBacktestJobResponse`):
```ts
{ jobId: string, status: "QUEUED" | "RUNNING" | "COMPLETED", requestHash: string, reused: boolean }
```
HTTP 202 on a genuinely new job; HTTP 200 when an identical in-flight/completed job is reused (Q0.9.26 idempotency); HTTP 400 on validation failure; HTTP 422 on a data-coverage failure.

## `GET /api/quant-lite/backtest/{jobId}`

Polls job status. `jobId` is validated against a strict UUID regex before touching anything (`services/quant-lite/backend/jobStore.ts::isValidJobId`) — a malformed id returns 400, never touches the filesystem.

**Response** (`data: GetBacktestJobResponse`):
```ts
{
  jobId, status, createdAt, startedAt?, completedAt?, durationMs?,
  result?: BacktestResult,          // present only when status === "COMPLETED"
  error?: BacktestJobError,         // present only when status === "FAILED"
}
```
404 if no job exists with that id (never existed, or the job store was cleared).

## Conventions followed

Both routes use this codebase's existing `withContext` + `ApiResponse` pattern exactly as every route under `app/api/private/**` does (confirmed via `services/backend/Middleware.ts`, `ApiResponse.ts`). The dynamic `[jobId]` route parses the id from `ctx.path` rather than a `params` argument — `withContext`'s `RouteHandler` type has no `params`, so this follows the same workaround already used by `app/api/private/chart-templates/[id]/route.ts`.

## Client wiring

`frontend/services/quant-lite/QuantLiteBacktestService.ts` — `createBacktestJob()` / `getBacktestJob()` wrap these two routes. `frontend/app/quant-lite/backtest/BacktestSetupForm.tsx` calls `createBacktestJob()` and navigates immediately; `frontend/app/quant-lite/results/[id]/ResultsView.tsx` polls `getBacktestJob()` every 1.5s while `QUEUED`/`RUNNING`.
