# Q0.5 — Complete

## Objective

Determine which of the three existing Python backtest engines
(`runner.py`, `execution_mtf.py`, `execution_tick.py`) should become the
canonical execution engine for AT24 Quant Lite — audit and
cross-validation only, no engine modification.

## Tests executed

- Identical-window cross-engine test: MACD Crossover + Bollinger Mean
  Reversion, full-year 2024, `XAUUSD_EXNESS`, `quant_lite_risk_config()`,
  all three engines, each run twice (6 total runs, one — `execution_tick`
  — replaying the full 34,194,748-tick real 2024 stream each time).
- Full trade-ledger reconciliation and first-material-divergence
  analysis (MACD Crossover).
- Real-price-action causal investigation (direct `market.db` query of
  the divergent trade's underlying 1h candles).
- Controlled synthetic scenario (`scripts/q05_synthetic_tests.py`) —
  independent confirmation of the root cause, plus basic-entry/exit,
  multiple-position, and missing-data scenarios for the two
  synthetic-data-capable engines.
- Determinism check across all 6 engine×spec combinations.

## Major findings

1. **A genuine look-ahead bug was found in `execution_mtf.py` and
   `execution_tick.py` (both this program's own newer work), absent
   from `runner.py`.** Both treat a signal bar as "closed" the instant
   an execution-timeframe timestamp reaches that bar's own *start* —
   because `market.db` candles are left-labeled — rather than waiting
   for the bar's actual close, one full bar-period later. Confirmed
   three independent ways: real-data trade-ledger reconciliation, direct
   price-action verification against `market.db`, and a controlled
   synthetic scenario purpose-built to isolate the effect.
2. This means some unknown portion of the dramatic PF improvement this
   program has reported since Q0.3 (`runner.py` → `execution_mtf.py`/
   `execution_tick.py`) is a look-ahead artifact, not purely better
   spread/SL-TP modeling as previously believed. Not quantified this
   sprint — flagged for Q0.6.
3. The three engines are all individually deterministic (6/6 repeat-run
   checks passed) — the bug is consistent and reproducible, which is
   exactly what made it traceable to a specific, fixable cause rather
   than an unexplainable anomaly.
4. `execution_tick.py` cannot run any synthetic test scenario — its
   execution data is sourced live from external zip files with no
   injection point, a structural testability limitation independent of
   the bug above.
5. The 1,764-strategy library is unaffected by this specific bug — it
   was built via `runner.py`, which doesn't have it.

## Canonical-engine decision

**B. CANONICAL WITH REQUIRED FIXES — `execution_mtf.py`**, contingent on
fixing the signal-bar-closed timestamp check and re-verifying against
this sprint's own MACD/Bollinger comparison before it is trusted. Full
reasoning, scorecard, and required-fix list in
[`Q0.5_CANONICAL_ENGINE_DECISION.md`](Q0.5_CANONICAL_ENGINE_DECISION.md).
No engine retired; `runner.py` and `execution_tick.py` both remain
useful (research-reference and research-only/spot-verification,
respectively).
