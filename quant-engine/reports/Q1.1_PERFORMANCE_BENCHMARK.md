# Q1.1 — Performance Benchmark (1m / 5m, Full History)

Real runs through `run_backtest_job.py` (the exact code path the API uses), MACD Crossover strategy, EURUSD_EXNESS (cleanest symbol - measures engine/data-volume cost, not gap-related short-circuiting). Memory is peak working-set sampled via ~0.5s-resolution `tasklist` polling (no `psutil`/`resource` module available in this environment - see the script header for detail); a coarse measurement, not a profiler-grade one.

## 1-minute signal timeframe

| Window | Trades | Elapsed | Peak Memory |
|---|---|---|---|
| 1 month | 413 | 18.9s | 225.8 MB |
| 3 months | 1,000 | 24.7s | 342.5 MB |
| 6 months | 2,041 | 14.0s | 414.8 MB |
| 1 year | 5,105 | 39.9s | 814.9 MB |
| Full history (~2.6 yr) | 7,618 | **81.6s** | **1,711.8 MB** |

## 5-minute signal timeframe

| Window | Trades | Elapsed | Peak Memory |
|---|---|---|---|
| 1 month | 154 | 5.4s | 127.9 MB |
| 3 months | 496 | 12.9s | 190.1 MB |
| 6 months | 992 | 16.4s | 264.4 MB |
| 1 year | 2,176 | 42.3s | 470.1 MB |
| Full history (~2.6 yr) | 5,477 | 70.0s | 1,039.4 MB |

All 10 runs **completed successfully** - no timeout, no failure, no orphan process. Every run finished well inside the existing hard timeout (`QUANT_LITE_BACKTEST_TIMEOUT_MS`, default 180s / Q0.9) - the slowest (1m full history, 81.6s) used well under half the budget.

## Observations

- Runtime does not scale purely with wall-clock window length - it tracks trade count / real market activity in that window (6-month 1m ran faster than 3-month 1m: 14.0s vs. 24.7s, because the 6-month window happened to land on a calmer stretch with fewer signal-bar closes; per-trade Python-side bookkeeping is a real cost, not just data loading).
- Memory scales roughly linearly with data volume/trade count in both series - full-history 1m at ~1.7GB is the single most memory-intensive case measured.
- 1m is consistently 1.1-1.7x slower than 5m at the same window, as expected (12x more signal bars to evaluate, though not the full 12x in wall time since indicator computation is vectorized over the whole series).

No optimization was attempted, per instruction - these are the numbers as measured.
