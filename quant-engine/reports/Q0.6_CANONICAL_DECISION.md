## Decision

**A. `execution_mtf.py` = CANONICAL.**

Q0.5 withheld canonical status pending exactly one, specific, named
condition: fixing the confirmed look-ahead defect and re-verifying. That
condition is now met, verified three independent ways (synthetic
before/after proof, real-data convergence with `runner.py`, real-data
divergence from still-buggy `execution_tick.py`), with no new defect
surfaced in the process.

## Required reasoning

- **Look-ahead fix correctness:** proven, not asserted — a controlled
  synthetic scenario shows the engine now enters using the real
  post-jump price at the bar's real close time, not the stale pre-jump
  price at the bar's start (`Q0.6_LOOKAHEAD_FIX.md`). Independently
  confirmed on real 2024 `XAUUSD_EXNESS` data: post-fix, `execution_mtf.py`
  converges sharply toward `runner.py` (which never had the defect) on
  both test specs, most strikingly for Bollinger (PF 0.99 vs. 1.00,
  nearly identical).
- **Deterministic behavior:** confirmed, 2/2 repeat-run checks pass for
  both specs (`Q0.6_DETERMINISM.md`), unaffected by the fix as expected.
- **Execution semantics:** signal detected on the spec's own timeframe,
  fills/SL/TP/position-management resolved at 1-minute granularity
  against real market data — unchanged by this sprint, already sound
  per Q0.3/Q0.5.
- **Spread model:** real, time-varying per-minute average spread from
  `market.db`'s `candle_spread` table — unchanged by this sprint,
  already the strongest of the three engines' spread models for
  practical (non-tick) use.
- **SL/TP precision:** 1-minute resolution, same-minute ties resolved
  conservatively (SL-first) and counted rather than hidden — unchanged,
  already sound.
- **Speed:** unaffected by the fix — each full-year run completes in
  ~6-10 seconds (confirmed this sprint), versus `execution_tick.py`'s
  ~15-25 minutes for the same window. This remains the deciding
  practical factor for library-scale (1,764+ strategy) use.
- **MTF behavior:** this was the one confirmed defect; now fixed and
  verified. The underlying signal-timeframe/execution-timeframe split
  architecture itself was never in question and is untouched.
- **Quant Lite parity:** `quant_lite_risk_config()` used throughout this
  sprint's testing; breakeven/trailing/partial-close confirmed
  structurally OFF (the fix does not touch this code path at all — see
  `git diff`, no lines near the risk-management block were changed).
- **Comparison with `execution_tick.py`:** now diverges sharply
  (MACD PF 1.15 vs. 1.71; Bollinger PF 0.99 vs. 0.27) — correctly so,
  since `execution_tick.py` retains the identical unfixed defect
  (confirmed present, untouched, at `execution_tick.py:105`). This
  divergence is evidence the fix worked, not a concern about
  `execution_mtf.py`.
- **Comparison with `runner.py`:** now closely aligned (Bollinger nearly
  identical; MACD materially closer than pre-fix, with the residual gap
  fully attributable to already-documented, legitimate spread/resolution
  differences, not an unexplained anomaly).

## Remaining issues

- `execution_tick.py` still has the identical defect this sprint fixed
  in `execution_mtf.py`. It was deliberately not modified this sprint
  (explicit instruction: do not touch it merely to make numbers match).
  It can no longer serve as an independent correctness oracle until it
  receives the same fix in a future sprint.
- The residual MACD gap between `runner.py` (PF 1.07) and fixed
  `execution_mtf.py` (PF 1.15) was not decomposed into its spread-vs-
  resolution components this sprint — not required for the canonical
  decision (both contributing factors are already independently
  documented and understood), but would be a reasonable follow-up if
  ever needed for a specific candidate's evidence package.
- No slippage model, no functioning commission model, no session
  filter, no broker minimum-stop-distance check — all pre-existing,
  shared limitations across all three engines, unrelated to this
  sprint's fix, already documented in Q0.3.

  `EURUSD_EXNESS` data) is worth considering, but is explicitly not
  started or scheduled by this sprint.
