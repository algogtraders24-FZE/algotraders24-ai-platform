# Q0.9 COMPLETE — Real Backtest API & Execution Bridge

**Verdict: Q0.9 PASS.**

The Quant Lite UI (Q0.8) now runs against a real backend that invokes the actual, audited `execution_mtf.py` engine per request — no mock, no static sample, no fabricated data. Every claim below is backed by a live test against the real running system (script, HTTP API, or browser), documented in full in `Q0.9_REAL_EXECUTION_VALIDATION.md`.

---

## 1. Existing execution path

Audited before any code was written (`Q0.9_EXISTING_EXECUTION_PATH.md`). Confirmed: `run_spec_backtest_mtf()` is a pure library function with no CLI; every real-data caller shares one `sys.path` bootstrap + raw-SQLite pattern; the frontend's `StrategySpec` type already matches the engine's dict shape field-for-field, so no strategy-mapping layer was needed.

## 2. API architecture

`POST /api/quant-lite/backtest` (create/reuse a job) + `GET /api/quant-lite/backtest/{jobId}` (poll). Built on this codebase's existing `withContext`/`ApiResponse` convention exactly as every other route under `app/api/private/**`. Full contract: `Q0.9_BACKTEST_API.md`.

## 3. Request contract

`BacktestRequest` (unchanged from Q0.7/Q0.8) — strategy, symbol, timeframe, date range, capital, risk%. No filesystem path, shell command, or code ever accepted.

## 4. Validation

Server-side, authoritative, two independent layers: TypeScript (`validateBacktestRequest.ts`, ported rule-for-rule from `schema.py`) for a fast 400, and Python's real `validate_spec()` inside `run_backtest_job.py` as defense in depth — verified both reject the same malformed spec with the same error strings.

## 5. Data coverage

`dataCoverage.ts` gates symbol (must be one of 6 `_EXNESS` symbols with real 1-minute data), timeframe (1h only — the only audited regression case), and date range (against the same real coverage dates already shown in the UI) before a job is even created. Verified live: an out-of-range date request never reaches the engine, returns `DATA_UNAVAILABLE`.

## 6. Job lifecycle

`QUEUED -> RUNNING -> COMPLETED/FAILED`, persisted as one JSON file per job under `quant-engine/output/jobs/` (Q0.9.21's explicit "don't add a new database" instruction). Full detail: `Q0.9_JOB_LIFECYCLE.md`.

## 7. Execution adapter

`executionAdapter.ts` — the only process-spawning code in `frontend/`. `child_process.spawn` with `shell: false`, array args only, server-generated file paths only. Full detail: `Q0.9_EXECUTION_ADAPTER.md`.

## 8. Process isolation

Verified live with 3 concurrent real jobs across 3 symbols: exactly `MAX_CONCURRENT_BACKTESTS` (2) ran at once, results were fully isolated (no cross-job data), config/result scratch files cleaned up per job.

## 9. Timeout

Hard timeout, `SIGTERM` then `SIGKILL` after a grace period. Verified live at an artificially short 800ms: job `FAILED`/`BACKTEST_TIMEOUT` at 838ms, zero orphaned `python.exe` processes afterward.

## 10. Concurrency

`MAX_CONCURRENT_BACKTESTS` (default 2, env-configurable), in-memory FIFO queue. Known limitation: single-instance only (documented, not solved — correct for the current deployment).

## 11. Result contract

`resultMapper.ts` maps the engine's raw stats+trades into the frozen `BacktestResult` type. Real capability gained: `winningTrades`/`losingTrades`/`largestWin`/`largestLoss`/`averageTrade` are now computed for real from the actual ledger (previously hardcoded `null` in Q0.8's mock). Full detail: `Q0.9_RESULT_CONTRACT.md`.

## 12. Ledger

Full real trade-by-trade ledger returned per job, `balanceAfter` computed as a running cumulative sum matching the engine's own internal `balance` variable exactly.

## 13. Equity curve

Trade-by-trade balance observations (not the full per-minute series) — consistent with the existing `EquityCurveChart` component's Q0.8 design, which already derives its plot from the trade ledger, not a separate series.

## 14. Evidence validation

No separate "evidence validation layer" exists elsewhere in this program to route through (confirmed: nothing in the M-Series evidence engine applies to Quant Lite backtests). The result is labeled honestly throughout — `LEGACY-BACKTEST-EVIDENCE` badging on the pre-existing library is untouched (Q0.9.27); fresh Q0.9 results carry no "Verified"/"Validated" claim anywhere in the UI, only real computed metrics plus the always-visible execution-assumptions disclosure.

## 15. Provenance

`requestHash` (deterministic, semantic-fields-only), `resultHash` (SHA-256 over stats+trades), `engineVersion`, real data-row counts loaded, generation timestamp. Full detail: `Q0.9_PROVENANCE.md`. Determinism proven by an automated test (identical config run twice → byte-identical output).

## 16. Persistence

One JSON file per job, reusing the exact pattern Q0.6 already used for its own output — no new database, no Prisma migration.

## 17. Frontend integration

`QuantLiteBacktestService.ts` rewritten to call the real API. `BacktestSetupForm.tsx` now creates a real job and navigates immediately (Q0.8's fabricated `STAGES` cycling is gone). `ResultsView.tsx` now polls the real job and renders genuine `QUEUED`/`RUNNING`/`COMPLETED`/`FAILED` states. Verified end-to-end in the real browser: built a brand-new RSI(14)<30 strategy from scratch in the Builder UI, ran it through Setup → real Running state → Results showing 138 real trades, +1.68% return, a real equity curve, and an honest trade table (`SL`/`TP` price columns showing "Not available", exactly as the engine's actual data supports).

## 18. Error handling

7-code taxonomy (`BacktestJobErrorCode`) with distinct UI treatment per code, "Try Again" retry flow, itemized validation detail lists surfaced to the user. Full detail: `Q0.9_FAILURE_CATALOG.md`.

## 19. Security

No shell, no client-controlled file paths, jobId validated by strict UUID regex before every filesystem/route touch, two-layer validation. Verified live against malformed JSON, path traversal (encoded + literal), shell/SQL-injection-looking jobIds, missing fields — every case rejected safely, filesystem confirmed untouched. Full detail: `Q0.9_SECURITY.md`.

## 20. MACD regression

**Exact match** to Q0.6's own recorded numbers (208 trades, 43.75% win rate, PF 1.15, +19.61% return, $11,961.23 final balance, identical first-trade entry price/time to the fraction of a cent) — reproduced three independent ways: the standalone script, the automated test suite, and the live HTTP API. Full detail: `Q0.9_REAL_EXECUTION_VALIDATION.md` §1.

## 21. Real strategy E2E

A never-before-run EMA20/EMA50 crossover (automated) and a hand-built RSI(14)<30 strategy (real browser UI, built live in this session) both produced real, internally-consistent, non-cherry-picked results — including one genuinely negative result (-3.16% return), proving nothing is being curated to look good.

## 22. Failure tests

Data-unavailable, invalid-strategy, unsupported-symbol, timeout, and 6 distinct security-injection cases all verified live against the real running system, each producing the correct structured failure — never a fabricated success. Full detail: `Q0.9_REAL_EXECUTION_VALIDATION.md`.

## 23. Performance (measured, not optimized per Q0.9.45)

- Full year (2024), 1h signal + ~580K rows of 1m exec data, MACD strategy: **~22-25 seconds** end to end (API call → COMPLETED).
- 7-month EMA crossover: **~10 seconds**.
- API request/job-creation latency: **10-25ms** (validation + hash + job record write).
- Idempotent re-fetch of a completed job: **~8ms**.
- No optimization was attempted on `execution_mtf.py` or the data-loading query, per explicit instruction.

No raw user strategy content is logged beyond what's already in the job record itself (no separate log stream was added this sprint — the job record *is* the observability record, consistent with the "small, safe change" scope).

## 31. Known limitations

- Single-instance job store and concurrency counter — correct today, would need a real shared store (e.g. Postgres via the existing Prisma schema) for a future multi-instance deployment.
- No authentication/ownership on jobs — consistent with Quant Lite's existing free, no-login scope; not a Q0.9 regression.
- No garbage collection on job JSON files — fine at current volume.
- Real execution currently supports only 6 symbols (all `_EXNESS`) and only the 1h signal timeframe — the only combination with an audited regression case. The Builder UI still allows selecting other symbols/timeframes (unchanged from Q0.8, since the Builder is not engine-specific), but Backtest Setup now surfaces a clear, honest warning and the backend rejects unsupported combos with a structured error rather than silently degrading.
- `BACKTEST_FAILED` error code is defined but not currently distinguished from `ENGINE_ERROR` in practice.
- A verification command mid-session inadvertently printed `.env.local`'s contents (including real API keys/tokens) into this session's tool output while confirming a temporary env-var revert. The file itself was never modified beyond the intended add/remove of one test line, and it remains gitignored/uncommitted — but the values are now visible in this conversation's transcript. Recommend treating those specific credentials as exposed if this transcript could be read by anyone who shouldn't see them.
