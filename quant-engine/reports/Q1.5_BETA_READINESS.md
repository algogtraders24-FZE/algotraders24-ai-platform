## Part 19 — Beta Release Boundary

**Safe to expose publicly as-is:**
- Real backtest execution over real Exness tick data for the 6 `REAL_EXECUTION_SYMBOLS`, with honest coverage/gap/performance-class labeling.
- Code generation to MQL4/MQL5/Pine v5 with the exact required "review before live use" disclaimer, clearly labeled `STATIC-VALIDATION-ONLY`.
- The Strategy Library's `LEGACY-BACKTEST-EVIDENCE` items — clearly, structurally, non-promotably labeled as research evidence, not validated performance.

**Not yet safe / requires the noted action first:**
- The Binance API key remains technically live until the user revokes it on Binance's own dashboard (functionally inert to this app, but still a live credential elsewhere). See `Q1.5_CREDENTIAL_ROTATION.md`.
- No rate limiting exists above the process-level concurrency/timeout caps (Part 12) — acceptable for a controlled/invite beta, not yet for unauthenticated public traffic at scale.
- No authentication/authorization layer exists — anyone who can reach the API can submit backtests/codegen requests. Acceptable only if beta access itself is gated at a layer outside this program (e.g. an invite link, existing platform auth) — not a Quant Lite-level control.

## Part 20 — Known limitations (not hidden)

- **Static-validation-only code generation.** No MetaEditor/TradingView compiler is available in this environment; every generated artifact is validated by pattern/structure, never actually compiled. Stated everywhere as `STATIC-VALIDATION-ONLY`, never implied to be compiler-verified.
- **Single-instance job store.** `jobStore.ts` is a file-based, single-process store — correct for the current deployment, not for a future multi-instance one (documented since Q0.9, unchanged).
- **No full holiday calendar.** Market-closure gap policy (Q1.2) covers weekends and known session breaks, not every regional holiday.
- **Platform execution differences.** Same-bar SL/TP tie-break ordering and position-sizing unit conversion are inherent, documented `PLATFORM-DIFFERENCE`s across Python/MQL4/MQL5/Pine (Q1.4), not generator defects.
- **Simplified execution model.** Spread and contract size are fixed server-side constants (`SPREAD_PRICE = 0.3`, `CONTRACT_SIZE = 100`), not yet a per-request configurable input — a deliberate Q0.7 contract freeze, not an oversight.
- **This sprint's typecheck note (pre-existing, not introduced by Q1.5)**: `npx tsc --noEmit` reports 11 errors, all confined to `scripts/q14_codegen_tests.ts` colliding in the TS global script scope with sibling test scripts (`q09`/`q11`/`q12`/`q13`) that predate this sprint and lack `export {}`, plus 5 unrelated `provenance`-property errors in that same file. Confirmed via `git stash` that these exist independent of any Q1.5 change. This sprint's own new file (`q15_security_tests.ts`) was given `export {}` specifically to avoid adding to this pre-existing condition — it contributes zero errors. Not fixed further this sprint to avoid touching closed Q1.0–Q1.4 deliverable files outside this sprint's scope; flagged here rather than silently left out of the record. `npm run build` and the actual `next build` type-checking path (which does not hit these dev-only scripts) both succeed cleanly.
- **Dependency currency.** Next.js and several other packages have newer versions available, some closing real CVEs; deliberately not auto-upgraded this sprint (Part 14) due to blast radius outside Quant Lite.
- **Credential rotation.** Binance key revocation and (optional) Vercel OIDC token refresh remain the user's own action — see `Q1.5_CREDENTIAL_ROTATION.md`.
