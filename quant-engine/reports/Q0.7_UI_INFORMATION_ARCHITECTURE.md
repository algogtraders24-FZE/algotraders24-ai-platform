# Q0.7 — UI Information Architecture

Design-only. No React pages, components, or routes were created this
sprint. `frontend/` was inspected read-only for context (Part 1 of
`Q0.7_PRODUCT_PIPELINE.md`) and was not modified.

---

## Screen 1 — Quant Lite Home

**Purpose:** explain what the free tool does, before asking the user to
commit to anything.

**Contains:**
- Create Strategy (→ Screen 2)
- Strategy Library (→ Screen 6)
- Backtest (→ Screen 3, likely reached *from* a saved strategy rather
  than as a cold-start entry point)
- Learn / Assumptions (→ links directly to the execution disclosure
  content, `Q0.7_EXECUTION_DISCLOSURE.md`)
- Upgrade to Quant Pro (→ Screen 8)

## Screen 2 — Strategy Builder

**Sections**, mapped directly to the Part 4 spec model (nothing here can
express more than the engine actually supports):
- Strategy name
- Market (symbol — constrained to what `market.db` actually has
  imported, not a free-text field)
- Timeframe
- Entry conditions (AND-only — the UI must not offer an "OR" toggle
  that doesn't exist in `interpreter.py`)
- Exit conditions (SL/TP only — no "close on opposite signal" option,
  since the engine doesn't support it)
- Risk (risk %, SL/TP mode and distance)
- Advanced assumptions (a fixed, read-only summary of the execution
  disclosure — not a settings panel, since none of breakeven/trailing/
  partial/slippage/commission are user-configurable in Quant Lite)

## Screen 3 — Backtest Setup

**Fields:** Symbol, Timeframe, Date range (bounded by actual data
coverage per symbol — see Part 5 of the pipeline doc), Initial capital,
Risk %, and a clearly-labeled, **non-editable** "Quant Lite Execution
Model" panel showing the disclosure content — not hidden in a tooltip,
not collapsed by default.

## Screen 4 — Backtest Running

**Shows:** current stage (e.g. "Loading price data" → "Running
backtest" → "Calculating results"), the data range being processed, and
the strategy name. **Must not fabricate a progress percentage** — the
engine has no meaningful sub-stage progress signal today (a single
function call, not a streamed/chunked process); an honest indeterminate
spinner/stage-label is correct, a fake progress bar counting to 100% is
not.

## Screen 5 — Backtest Results

**Top-level (always visible, never below the fold):** Return %, Profit
Factor, Win Rate, Max Drawdown, Total Trades.

**Below:** equity curve, full trade list, the execution-assumptions
panel (same content as Screen 3, repeated — a result must always carry
its own assumptions, never rely on the user remembering what they set),
and any warnings (e.g. a truncated date range, or an
`account_blown=True` result explicitly called out, not buried in a
metric).

## Screen 6 — Strategy Library

Every row carries the `LEGACY-BACKTEST-EVIDENCE` label, unconditionally
— per the Q0.5/Q0.6 finding that this library's stored metrics predate
the canonical engine and the account-blown fix, this label is not
optional styling, it's a correctness statement. **Never** labeled
"Verified," "Validated," or "Guaranteed" anywhere in this screen —
those words are reserved (by the M-Series' own vocabulary discipline,
`M0.1_product_model_freeze.md`) for a real Evidence/Validation chain
this library has never gone through.

Filters: indicator, market, timeframe, profit factor, return,
drawdown, trade count — filtering narrows *which* legacy records are
shown, it never implies any of them have been validated by the act of
filtering.

## Screen 7 — Strategy Detail

Shows: the strategy's actual rules (indicators + conditions, rendered
human-readably from the spec dict — not just raw JSON), the historical
evidence (with its `LEGACY-BACKTEST-EVIDENCE` label carried through),
the full assumptions panel, known limitations (a static list — e.g.
"this result predates the current execution engine" for library
entries), and the exact backtest configuration that produced the shown
numbers (Part 5's input contract, populated with the real values used).

## Screen 8 — Upgrade

Explains what Quant Pro eventually adds (per
`Q0.7_LITE_PRO_BOUNDARY.md`) — a comparison/marketing surface only. No
Quant Pro functionality is implemented behind this screen; it is purely
informational, pointing at a product that doesn't exist as usable
software yet.

## Part 9 — UI result-honesty rules

The UI must **never**:
- Hide max drawdown, or bury it below other, more flattering metrics.
- Hide or truncate a losing period on the equity curve.
- Imply profitability through visual design (e.g. defaulting to a green
  color scheme regardless of whether the result is a loss).
- Hide the execution-assumptions panel behind an extra click on the
  results screen (Screen 5) — it must be visible without navigation.
- Mix a Screen 6/7 legacy library result with a freshly-run Screen 5
  backtest in the same visual treatment — they must remain visually and
  textually distinguishable at all times (different label, e.g.
  `LEGACY-BACKTEST-EVIDENCE` vs. an unlabeled fresh run — Quant Lite has
  no "validated" tier to promote a fresh run into either, so a fresh
  run's own label should be something equally honest, e.g. "Backtest
  Result" without implying validation beyond what §Screen 5 already
  discloses).
- Present a stale library metric as if it reflects current, canonical
  engine behavior — it doesn't (Q0.5/Q0.6 established this concretely).

**If a metric is unavailable** (e.g. average trade / largest win /
largest loss, per Part 6 of the pipeline doc, not currently computed by
the engine): show **"Not available"**, never **"0"** — a literal zero
would misrepresent an uncomputed value as a computed one showing no
result.

## Part 10 — Strategy library UI treatment

The existing 1,764 rows appear in Screen 6/7 as discovery/research
material only — never regenerated, never modified (`strategy_library.db`
stays exactly as-is, per every prior sprint's explicit instruction).
Filtering (indicator, market, timeframe, PF, return, drawdown, trade
count) is a **query convenience**, not a validation mechanism — the UI
copy around the filter controls should say so explicitly (e.g. a
persistent, unobtrusive note: "Historical results shown here are
research evidence from a prior engine version, not validated
performance"), not just rely on the per-row label to carry that meaning
alone.
