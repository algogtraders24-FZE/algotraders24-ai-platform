# Q0.7 — Complete

## Objective

Move from engine stabilization (Q0.6) toward productization: define
exactly how the Legacy Engine becomes a usable AT24 Quant Lite free
product — pipeline, spec/risk/result contracts, execution disclosure,
UI information architecture, free-tier and Quant Pro boundaries, API/
provenance design, error states, resource limits, and a test plan. No
implementation — a contract-freeze sprint, per explicit instruction.

## Part 1 finding: no existing entry point

Confirmed by direct inspection: zero product-facing entry points exist
anywhere in `quant-engine/` (every script is a standalone `demo_*.py`/
`scripts/*.py`), and zero references to `quant_lite`, `execution_mtf`,
or `spec_engine` exist anywhere under `frontend/` — no route, no API
call, nothing to reuse or extend. **"No production Quant Lite entry
point currently exists,"** stated as instructed.

## Product pipeline

`USER → Strategy Creation → Validation → Specification → Quant Lite
Risk Config → Canonical execution_mtf.py → Deterministic Backtest →
Evidence Calculation → Result Validation → Report → Save/Export` — every
stage's input/output/validation/failure/user-visible-behavior defined in
[`Q0.7_PRODUCT_PIPELINE.md`](Q0.7_PRODUCT_PIPELINE.md), grounded in
what the engine actually does today (confirmed by source inspection,
not assumed).

## Canonical engine integration point

`quant_lite_risk_config()` → `execution_mtf.py::run_spec_backtest_mtf()`
— a plain function call today, no async boundary, no persistence. The
future integration point (design only):

```
Quant Lite Product Entry -> Canonical execution_mtf.py ->
quant_lite_risk_config() -> Deterministic Backtest -> Evidence/Report
```

`use_breakeven=False`, `use_trailing=False`, `use_partial=False`
remain pinned exactly as Q0.4 established; `RiskConfig`'s global class
defaults remain untouched — reconfirmed, not re-verified by new tests
this sprint (no engine code was run or changed).

## Strategy builder scope

10 indicators (all implemented, audited per-indicator in
`Q0.7_PRODUCT_PIPELINE.md` Part 3), AND-only conditions, SL/TP-only
exits, fixed risk-% sizing, single-position-only. OR logic,
close-on-opposite-signal, session filtering, and multi-symbol strategies
are explicitly out of scope (UNSUPPORTED/FUTURE) — not because Quant
Lite chooses to exclude them, but because the engine genuinely cannot
do them today.

## Backtest scope

Symbol/timeframe/date-range bounded by actual `market.db` coverage
(8 symbols currently). Real, time-varying spread; no slippage; no
commission; 1-minute SL/TP resolution; no breakeven/trailing/partial.
Full input contract in `Q0.7_PRODUCT_PIPELINE.md` Part 5.

## Result/report scope

`summarize()`'s existing 8 fields are ready today with zero new engine
code. Win/loss counts, average trade, largest win/loss, and a
standalone final-equity field are **not yet computed anywhere** —
trivial additions, not built this sprint, must not be shown until they
exist. SL/TP price levels are **not currently stored** per trade — a
real gap for any "show me the stop" UI requirement.

## UI screens

8 screens defined (Home, Strategy Builder, Backtest Setup, Backtest
Running, Backtest Results, Strategy Library, Strategy Detail, Upgrade)
in [`Q0.7_UI_INFORMATION_ARCHITECTURE.md`](Q0.7_UI_INFORMATION_ARCHITECTURE.md),
plus honesty rules (never hide drawdown, never show "0" for an
uncomputed metric, always distinguish legacy library results from fresh
runs) and full component/state/error-table detail in
[`Q0.7_UI_IMPLEMENTATION_PLAN.md`](Q0.7_UI_IMPLEMENTATION_PLAN.md).

## Free-tier boundaries

Strategy creation, the 10 supported indicators, basic backtesting
(canonical engine, Quant Lite risk config), the strategy library
(labeled, filterable, not "validated"), core metrics, equity curve,
trade list, execution assumptions. Full detail and open items in
[`Q0.7_LITE_PRO_BOUNDARY.md`](Q0.7_LITE_PRO_BOUNDARY.md).
