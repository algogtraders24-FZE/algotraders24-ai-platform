# Q0.7 — Quant Lite / Quant Pro Boundary

## The two products are architecturally separate, not tiers of one codebase

**Quant Lite** is built entirely on the Legacy Engine
(`quant-engine/`, `quant_engine/`) audited and stabilized across
Q0.2–Q0.6: `spec_engine`'s schema/indicators/interpreter, the canonical
`execution_mtf.py`, and `quant_lite_risk.py`'s forced-off risk
configuration.

**Quant Pro** is a **separate project already under active development
elsewhere in this repository**: `at24-quant-engine/`, confirmed to exist
with its own independent sprint numbering (its own `Q0.1`/`Q0.2` docs,
unrelated to this program's `Q0.1`–`Q0.7`). This audit does not open,
read the contents of, or take any architectural cue from that project —
per every sprint's explicit "DO NOT TOUCH `at24-quant-engine/`"
instruction, reaffirmed again this sprint.

**This separation is deliberate, not a placeholder to be merged later.**
Copying Quant Pro architecture into the Legacy Engine, or vice versa,
is explicitly out of scope for Quant Lite's productization.

---

## Quant Lite

- Simple: one symbol, one timeframe, AND-only conditions, SL/TP-only
  exits — the actual ceiling of what `spec_engine` supports today
  (Part 4, `Q0.7_PRODUCT_PIPELINE.md`), not an artificially reduced
  slice of something larger.
- Free.
- Deterministic — proven, not assumed (every determinism check across
  Q0.3–Q0.6 passed).
- Educational/basic-research oriented — the 1,764-strategy library
  (clearly labeled `LEGACY-BACKTEST-EVIDENCE`) and the wizard-based
  strategy builder are discovery tools, not an institutional research
  platform.
- Canonical legacy execution model: `execution_mtf.py`, 1-minute
  execution resolution, real spread, no slippage/commission modeling,
  no breakeven/trailing/partial-close.

## Quant Pro (not built — this section describes the boundary, not a
commitment to any specific future scope)

Per the sprint brief's own framing, reserved for:
- A separate, more advanced execution engine (not this program's
  `execution_mtf.py`/`execution_tick.py`, and not `at24-quant-engine/`
  by assumption either — genuinely undetermined, out of scope to decide
  here).
- Advanced validation (the M-Series' own Evidence → Validation →
  RiskAnalysis → TrustStatus chain is the existing precedent for what
  "advanced validation" already means elsewhere in this codebase, per
  `M0.1_product_model_freeze.md` — referenced as prior art, not assumed
  as Quant Pro's literal architecture).
- Robustness analysis (the existing `spec_engine/robustness.py`
  walk-forward evaluator is a real, working piece of exactly this
  category — already flagged in `QUANT_LITE_PRODUCT_BLUEPRINT.md` §6 as
  a natural Quant Pro-tier feature, reused rather than rebuilt).
- Monte Carlo / perturbation analysis (does not exist anywhere in this
  codebase today — would be new work, not a hidden existing capability).
- Tick-level execution as the default (not `execution_tick.py`'s
  current form necessarily, but the *category* of capability it
  represents — real, working, but too slow for library-scale use and
  currently untestable with synthetic data, per Q0.5's findings).
- Institutional/portfolio-level research, multi-symbol strategies,
  session filtering as a real feature (not just a `RiskConfig` field
  nobody reads) — all confirmed unsupported anywhere in the current
  engine (Part 4, pipeline doc).

## What Quant Lite explicitly does NOT get (Part 11's list, restated as
a boundary, not a feature backlog)

Advanced tick replay, advanced robustness scoring exposed to free
users, Monte Carlo, walk-forward optimization (`robustness.py`'s
walk-forward *evaluation* stays internal/research-only, not a
user-facing Quant Lite feature — per this sprint's instruction, "do not
implement them"), multi-fidelity engine comparison, institutional
research tooling, advanced execution models. None of these are
implemented this sprint, for either product.

## The one place the boundary is intentionally soft: `robustness.py`

Per `QUANT_LITE_LEGACY_AUDIT.md` §8 and
`QUANT_LITE_PRODUCT_BLUEPRINT.md` §6, the walk-forward evaluator is real
working code with genuine value, but this sprint does **not** decide
whether it ships as a Quant Lite feature (contradicts "basic" per Part
11) or a Quant Pro one (matches the "advanced robustness" reservation
above). Left as an explicit open question for a future sprint, not
resolved by assumption here.
