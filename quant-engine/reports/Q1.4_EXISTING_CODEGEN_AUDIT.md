# Q1.4 Part 1 — Existing Codegen Audit

## Files audited

`quant-engine/spec_engine/codegen_mql4.py` (280 lines), `codegen_mql5.py` (344 lines), `codegen_pine.py` (170 lines), `template_builder.py` (215 lines, a separate zero-AI spec-building wizard — not a code generator, out of this audit's direct scope but confirmed compatible).

## Verdict: EXISTING and REUSABLE — no rewrite needed

All three generators were found to be mature, already parity-conscious, and functionally complete for Quant Lite's frozen 10-indicator/AND-only/SL-TP-only contract. Confirmed by direct code reading and by generating real output for every indicator type and 6 golden strategies (73 + 42 automated checks, all passing).

## EXISTING (already implemented, verified correct)

- All 10 indicator types (EMA, SMA, RSI, ATR, MACD, BB, STOCH, ADX, DONCHIAN, SUPERTREND) in all 3 languages.
- AND-only entry condition compilation (`&&`/`and` joins) — matches the frozen contract exactly, no OR logic anywhere.
- Closed-bar semantics: MQL4/MQL5 read shift=1 (last closed bar) for "current" and shift=2 for "prev" — **never shift=0** (the still-forming bar) in any signal/indicator read. Pine uses its default `calc_on_every_tick=false` non-repainting mode with no `lookahead_on`. No look-ahead found in any of the three.
- SL/TP: ATR-based (`atr * mult`) and fixed-PIPS modes, both implemented in all 3 languages, matching `execution_mtf.py`'s own `sl_dist`/`tp_dist` formula exactly.
- Risk-percent-based position sizing in all 3 languages, using each platform's own real broker mechanics (tick-value for MQL4/MQL5, `syminfo.pointvalue` for Pine) — see `Q1.4_PARITY_MATRIX.md` for why this is a genuine, documented, unavoidable **PLATFORM DIFFERENCE** vs. the Python engine's simplified `contract_size` model, not a bug.
- Cross-platform indicator-math parity already engineered by whoever built this, with inline comments explaining each fix: MetaTrader's built-in MACD signal buffer is SMA-smoothed (a MetaTrader quirk) — both MQL4 and MQL5 recompute the EMA-smoothed signal manually from the raw MACD line to match `indicators.py`/Pine exactly. Stochastic uses `slowing=1` (not the default 3) so `MODE_MAIN` is the raw %K, matching `indicators.py`. Donchian excludes the current bar's own high/low from its own channel in all 3 languages. Supertrend's trend-sign convention is explicitly flipped in Pine (`ta.supertrend`'s `direction<0`=uptrend is the opposite of `indicators.py`'s `+1`=uptrend).
- Breakeven/trailing/partial-close: **absent from all three generators entirely** — not disabled, never built. Confirmed by keyword-scanning all 18 golden artifacts for `breakeven`/`trailing`/`partialclose` — zero matches anywhere.

## MISSING (not built, and correctly out of scope)

- OR-logic, multi-symbol, session logic, opposite-signal exits, advanced order types, tick-specific logic — none exist in the generators, matching the frozen spec's own ceiling. Confirmed structurally impossible to express (the schema has no field for any of these — `Q1.4_PARITY_MATRIX.md`).
- A `POST /api/quant-lite/codegen` endpoint, provenance metadata, and UI integration — none existed before this sprint. Built this sprint (`Q1.4_COMPLETE.md`).

## INCORRECT (real bugs found and fixed this sprint)

Two genuine security defects were found via testing (not assumed) and fixed — see `Q1.4_SECURITY_VALIDATION.md` for full detail:

1. **Indicator `id` values were embedded unquoted as raw MQL/Pine identifiers with no format validation** — a crafted `id` like `"i1; Print(1); int x"` injected arbitrary compilable code into every line referencing that indicator. Fixed in `schema.py::validate_spec()` — indicator ids (and condition `left`/`right` refs) are now required to match a safe identifier pattern, rejected outright otherwise.
2. **The free-text strategy `name` field was embedded unescaped into both source comments and quoted MQL string literals** — a `"` in the name broke out of `req.comment="..."` into executable MQL. Fixed with a `_sanitize_name()` helper added to all three generators, stripping unsafe characters before any embedding.

Both fixes are additive/defensive only — no existing indicator math, entry logic, SL/TP logic, or position-sizing logic was changed. The Q0.9 MACD baseline and `template_builder.py`'s own self-test (which runs at import) were both re-verified unaffected.

## REUSABLE

100% of the existing generator logic was reused as-is beyond the two security fixes above. No generator was rewritten. `run_codegen_job.py` (new, this sprint) is a thin process-boundary wrapper around the existing `generate_mql4`/`generate_mql5`/`generate_pine` functions — it does not duplicate or reimplement any of their logic.
