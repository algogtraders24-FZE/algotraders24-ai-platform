# Q0.8 COMPLETE — Quant Lite UI Implementation

Status: **COMPLETE**. First real, working UI for AT24 Quant Lite, built strictly on the frozen Q0.7 contracts and the Q0.6 canonical execution engine. No backend exists yet, so the UI runs against a clearly-isolated mock service that returns only real, previously-verified data (never fabricated numbers).

> **Q0.9 UPDATE**: The mock backend described throughout this document (`QuantLiteBacktestService.runBacktest()` always returning the static Q0.6 sample result) has been **replaced** with a real backend — see `Q0.9_COMPLETE.md`. `createBacktestJob()`/`getBacktestJob()` now call a real API (`app/api/quant-lite/backtest/**`) that spawns the actual `execution_mtf.py` engine per request and returns genuine, freshly-computed results. Every "mock"/"no backend exists" statement below describes the Q0.8 state and is now historical — kept for the record, not corrected in place.

---

## 1. UI Architecture Implemented

- Top-level route group `frontend/app/quant-lite/**`, self-composed with the existing `Navbar` + `Footer` (matches the pattern already used by `/pricing` and `/products` — no shared marketing `layout.tsx` exists to hook into).
- Client/server split follows the existing app's convention: static/SSG pages are server components; anything reading `sessionStorage` (Backtest running state, Results) is a client component.
- State is passed between screens via `sessionStorage` only (`QuantLiteBacktestService`) — no new persistence layer, no new backend dependency, matches Q0.7's explicit permission to use isolated mock data for dev UI states.
- Built entirely on the existing design system: `components/ui/*` (Card, Badge, Button/ButtonLink, EmptyState, Skeleton, StatField) and `financial-typography.ts` conventions. No new component library, no new charting library.

## 3. Components Created

`frontend/components/quant-lite/`: `MetricTile`, `EquityCurveChart`, `TradeTable`, `ExecutionAssumptionsPanel`, `LegacyEvidenceBadge`, `StrategyRuleSummary`. All built on top of existing `components/ui/*` and `components/workspace/StatField.tsx`, not new primitives.

## 4. Strategy Builder Functionality

- Add/remove indicators from all 10 supported types (`INDICATOR_META` in `data/quant-lite-constants.ts`), each with its real parameter set.
- Add/remove BUY and SELL entry conditions, AND-only combination (matches the canonical engine's actual capability — no OR logic offered since the engine doesn't support it).
- SL/TP and risk-preset selection, pinned to Quant Lite's execution baseline (breakeven/trailing/partial-close always OFF, shown as disabled/explained in the UI, not hidden).
- Client-side validation (`validateStrategySpec.ts`) — explicitly usability-only, not authoritative; real enforcement stays server-side once a backend exists.
- Live strategy rule summary (`StrategyRuleSummary`) reflects the spec being built in plain language.

## 5. Backtest Setup

Symbol/timeframe/date-range selection constrained to `SYMBOL_META`'s real, audited coverage windows (from Q0.5/Q0.6) — the UI cannot request a symbol or date range the engine doesn't actually have data for.

## 6. Running State

Cycles through real named stages (`STAGES` array) via `setInterval`. **No fabricated percentage progress bar** — per the explicit sprint requirement — since the mock service (and, later, a real backend) has no meaningful way to report true sub-task progress.

## 7. Results Page

- Every metric tile (`MetricTile`) renders **"Not available"**, never `"0"`, when a value is `null`.
- Distinguishes `"percent"` (signed/directional: Return, Drawdown) from `"rate"` (absolute, unsigned: Win Rate) formatting — a real bug caught and fixed during manual browser testing (Win Rate was incorrectly showing a `+` prefix).
- Execution assumptions panel and the "historical simulation, not a guarantee" disclaimer are always visible above the fold, never gated behind an extra click.
- `accountBlown` state, when true, is surfaced as an explicit red warning, not silently absorbed into the metrics.
- Provenance (engine version, generated-at timestamp) always shown.

## 8. Equity Curve

Custom lightweight inline SVG (`EquityCurveChart`), deliberately not built on the existing canvas-based Native Chart Engine (that engine is reserved for candlestick/live market data, not equity curves). Renders only from real trade-by-trade balance data in the result — no synthetic smoothing or interpolation.

## 9. Trade Table

Full per-trade ledger (entry/exit time, direction, P&L, exit reason) rendered from the real 208-trade Q0.6 MACD ledger sample — not summarized or truncated silently.

## 10. Strategy Library

Read-only browse/filter over a 32-strategy sample pulled directly from `strategy_library.db` (no mutation, no regeneration). Every card and detail page carries the `LegacyEvidenceBadge` labeled **`LEGACY-BACKTEST-EVIDENCE`** — never "Verified," "Validated," or "Guaranteed" — plus an explicit note that this evidence predates the canonical `execution_mtf.py` engine and the account-blown fix, so it is not directly comparable to a fresh Quant Lite backtest.

## 11. Strategy Detail

Shows the same honest metric tiles, the strategy's actual rule spec, and the execution assumptions panel, plus a "Run Fresh Backtest" CTA into the Builder — no claim of current validity.

## 12. Upgrade Section

Static, informational only. No payment flow, no subscription logic, no Quant Pro implementation — matches the sprint's explicit exclusion.

## 13. API / Backend Integration Status

**No backend exists.** Per Q0.7's audit and re-confirmed at the start of this sprint, there is no safe existing Quant Lite API entry point to integrate with. `QuantLiteBacktestService` is a clearly-isolated client-side mock (file header and inline comments state this explicitly) that returns real, previously-computed Q0.6 data — never invented numbers — with a simulated delay to exercise the Running state honestly. This is not presented to the end user as a live/authoritative backend.

## 14. Mock Data Status

All mock data is real: the 32-entry library sample and the 208-trade MACD result both come directly from `strategy_library.db` and `quant-engine/output/q06/MACD_Crossover__execution_mtf__run1.json` via the read-only conversion script `quant-engine/scripts/q08_gen_frontend_data.py`. Nothing was fabricated or hand-invented.

## 24. Known Limitations

- No real backend/API — the entire data layer is a mock service over static, pre-computed real data. Running a *new* backtest from the Builder always returns the same Q0.6 MACD sample result, not an actual fresh simulation.
- No persistence beyond `sessionStorage` — results are lost on tab close/browser restart.
- No automated test suite (unit/integration/e2e) for the new UI; verification was manual/browser-based only.
- Client-side validation is usability-only and must not be treated as authoritative once a real backend exists.
- Strategy Library sample is 32 of 1,764 entries — a representative slice, not the full set.
