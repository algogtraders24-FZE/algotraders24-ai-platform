# Q1.11 Phase 2/3 — VPS HTTP Execution Service

## Built: `quant-engine/service/quant_lite_execution_service.py`

A FastAPI service, modeled directly on `mt5-bridge/bridge.py`'s own already-proven-in-production pattern (same auth style, same health-endpoint philosophy, same `fastapi>=0.110.0`/`uvicorn[standard]>=0.29.0` version floors from that service's own `requirements.txt`).

## Endpoints

| Endpoint | Auth | Purpose |
|---|---|---|
| `GET /health` | None (matches `mt5-bridge`'s own reasoning: liveness/config status only, safe to poll without a credential) | Reports whether the secret is configured, the engine script is present, and `market.db` is present — never a fabricated "ok" |
| `POST /backtest` | Bearer token required | Submit a backtest request |
| `GET /backtest/{jobId}` | Bearer token required | Poll job status/result |

## What it does NOT do — verified, not just claimed

Not a second engine. Every real backtest is fulfilled by spawning the **exact same, unmodified** `run_backtest_job.py` (`asyncio.create_subprocess_exec`, `shell` never invoked, fixed argv array: `python run_backtest_job.py --config <server-path> --out <server-path>`) — identical to what `executionAdapter.ts` already does locally, just running here. No indicator math, no risk logic, no result computation exists anywhere in this new file.

**Cannot accept a filesystem path, shell command, Python code, or arbitrary engine argument from the request body** — by construction: the only two file paths that ever exist in a request's lifecycle are built from a server-validated UUID under a fixed `JOBS_DIR` root; the request body's own allowed top-level keys are an explicit whitelist (`jobId`, `requestHash`, `strategy`, `symbol`, `timeframe`, `dateRange`, `initialCapital`, `riskPct`) — anything else is rejected with a named error before the request goes anywhere near the subprocess boundary.

## Authentication

Copied deliberately from `mt5-bridge/bridge.py`'s `_require_secret()`: `hmac.compare_digest` (constant-time), fail-**closed** if `QUANT_LITE_EXEC_SECRET` isn't configured (503, not a silent bypass), `401` for missing/wrong token, the secret itself never appears in any response body or log line.

## Preserved from the existing local adapter, unchanged

`MAX_CONCURRENT_BACKTESTS=2` (via `asyncio.Semaphore`), `BACKTEST_TIMEOUT_MS=180000`, `STDERR_TAIL_LIMIT=4000`, `SPREAD_PRICE=0.3`, `CONTRACT_SIZE=100` (both server-pinned — never accepted from the request body, same trust boundary as today), SIGTERM-then-SIGKILL-after-grace-period on timeout (no orphan process), idempotent request-hash reuse (`reused: true`), `stderrTail` captured server-side only and **never** returned by `GET /backtest/{jobId}` (explicit whitelist response body, same discipline as `app/api/quant-lite/backtest/[jobId]/route.ts`), the `INVALID_STRATEGY` error-code fix from Q1.7 carried through unchanged.

## Local end-to-end test, before any VPS handoff

Run and verified live on this local machine (same directory-structure assumptions as the VPS target, so this is a real functional test, not just a syntax check):

| Test | Result |
|---|---|
| `/health` | Correctly reports `enginePresent`/`marketDbPresent`/`secretConfigured` all `true` |
| No bearer token | `401` |
| Wrong bearer token | `401` |
| Empty request body | `400`, named field-by-field errors |

| Idempotent resubmission (same `requestHash`) | Same `jobId` returned, `reused: true` |
| `stderrTail` in `GET` response | Never present — confirmed absent |
| 2 concurrent jobs (different symbols) | Both completed correctly, zero cross-contamination — job 1 (XAUUSD RSI) matched Q1.7/Q1.10's own 227-trade baseline exactly, job 2 (EURUSD RSI, same period) correctly returned its own distinct 0-trade result |
