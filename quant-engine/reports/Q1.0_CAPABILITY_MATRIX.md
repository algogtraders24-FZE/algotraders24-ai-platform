# Q1.0 — Final Capability Matrix

> **Q1.1 UPDATE**: this matrix's symbol/timeframe support is unchanged and still accurate. Q1.1 added a real, quantified per-request coverage-and-gap-policy layer on top of it (`quant-engine/reports/Q1.1_GAP_POLICY.md`, `services/quant-lite/backend/coveragePolicy.ts`) - every request now gets a specific SUPPORTED/SUPPORTED_WITH_WARNING/RESTRICTED/DATA_UNAVAILABLE assessment for its exact date range, not just a whole-symbol label. The sprint brief that requested this update referred to it as `Q1_CAPABILITY_MATRIX.md`; no such file was ever created in this program (this file, `Q1.0_CAPABILITY_MATRIX.md`, is the one that exists) - treated as a naming discrepancy, updated here.

## Methodology

Two independent axes were tested separately, then combined:

- **Timeframe compatibility** is an `execution_mtf.py` mechanics property — the engine's indicator computation (`spec_engine/indicators.py`) and entry evaluation (`interpreter.py`) are symbol-agnostic; nothing in the engine branches on which symbol is loaded. Tested once, thoroughly, on the most-audited symbol (XAUUSD_EXNESS): all 7 candidate signal timeframes (1m, 5m, 15m, 30m, 1h, 4h, 1d), 2 independent strategies each (EMA20/50 crossover, RSI14 oversold/overbought), 2 runs each for determinism. `quant-engine/scripts/q10_timeframe_sweep.py`.
- **Symbol coverage** is a real-data-availability property — tested directly per symbol, at the one timeframe already regression-proven since Q0.6/Q0.9 (1h): all 8 candidates (6 `_EXNESS` + 2 legacy), same 2 strategies, 2 runs each. `quant-engine/scripts/q10_symbol_sweep.py`.

A timeframe proven compatible on the representative symbol is applied across every symbol whose own data-coverage test passed — this is a documented generalization, not a claim that all 42 symbol×timeframe combinations were individually live-tested. Anyone wanting to verify a specific combination beyond this can re-run either sweep script directly.

All 7 completed, all deterministic, all well within a usable response time (max 34s at the longest tested window) — no timeframe required a PERFORMANCE-LIMITED classification.

BTCUSD_EXNESS's noticeably lower EMA trade count (23 vs. 80-111 for others) is explained, not anomalous: its 2024 test window overlaps a real 155-day data gap (2024-07-29→2025-01-01, see `Q1.0_DATA_COVERAGE_AUDIT.md`), so roughly half the requested year had no data to trade on at all. The engine correctly used only the real data present — it did not fabricate a full year's worth of activity.

Both legacy symbols failed instantly and cleanly with `DATA_UNAVAILABLE` — confirmed live, not merely inferred from the schema — because neither has any 1-minute execution data (`Q1.0_DATA_COVERAGE_AUDIT.md` Part 2).

## Single source of truth

`frontend/data/quant-lite-capability.ts` is now the only place symbol/timeframe support is declared. `services/quant-lite/backend/dataCoverage.ts` (API enforcement) and `app/quant-lite/builder/StrategyBuilderForm.tsx` / `app/quant-lite/backtest/BacktestSetupForm.tsx` (UI selectors/warnings) all import from it — no duplicated lists remain.
