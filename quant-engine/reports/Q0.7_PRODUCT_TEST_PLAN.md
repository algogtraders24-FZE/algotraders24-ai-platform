# Q0.7 — Product Test Plan

No automated test suite exists for any of this (Q0.5's own audit
confirmed zero pytest/unittest coverage anywhere in `quant-engine/`).
This plan defines what a future implementation sprint should build, and
notes — honestly, per this program's own standard — which parts already
have real evidence from prior sprints versus which are genuinely
untested.

| # | Test | What it verifies | Current status |
|---|---|---|---|
| 1 | Valid strategy | `validate_spec()` accepts a well-formed spec | **Proven** — every wizard-built spec, self-tested at import (`template_builder.py::_self_test()`) |
| 2 | Invalid strategy | `validate_spec()` rejects an unknown indicator type/op, or a bad ATR reference, with a specific error list | **Proven** — exercised by design throughout Q0.2-Q0.6's own test scripts |
| 3 | Missing data | Engine returns a well-formed empty result (`"not enough signal bars"`), not a crash, when `len(sig) < 50` | **Proven** — this exact path fires routinely during `robustness.py`'s fold-based walk-forward evaluation |
| 4 | Invalid date range | A requested range outside actual `market.db` coverage is rejected or truncated with a clear warning | **NOT TESTED** — no validation of this kind exists anywhere yet; this is a genuine gap, not just an untested-but-present feature |
| 5 | Unsupported indicator | A spec naming an indicator type outside the 10 supported ones is rejected | **Proven** — `validate_spec()`'s `VALID_INDICATOR_TYPES` check, exercised throughout this program |
| 6 | Risk config | `quant_lite_risk_config()` forces BE/trailing/partial OFF regardless of kwargs passed | **Proven this sprint's predecessor (Q0.6)** — zero partial-close rows, zero SL-price-mismatches (proof breakeven/trailing never fired) across 404+ real SL exits |
| 7 | Deterministic backtest | Same spec + data + config → identical result on repeat runs | **Proven repeatedly** — every determinism check from Q0.3 through Q0.6 passed, most recently 6/6 in Q0.6 |
| 8 | Result calculation | `summarize()`'s metrics are internally consistent (e.g. `final_balance = start_balance + sum(pnl)`) | **NOT independently tested** — no dedicated assertion exists checking this invariant; it has held in every observed run but was never adversarially tested |
| 9 | Trade ledger | Every trade row has consistent, sane fields (entry before exit, PnL sign matches direction × price move, etc.) | **NOT independently tested** as a formal invariant check — spot-verified manually during Q0.5's ledger reconciliation, not as an automated assertion |
| 10 | Equity curve | Matches the trade ledger's cumulative PnL at every point | **NOT independently tested** as a formal check |
| 11 | Export/report | Not applicable yet — no report/export feature exists (Part 2 of the pipeline doc, "Save/Export" stage is explicitly undesigned) | **NOT APPLICABLE — feature doesn't exist** |
| 12 | Strategy library labeling | Every one of the 1,764 rows carries `LEGACY-BACKTEST-EVIDENCE`, never a stronger claim | **Design requirement, not yet implemented in any UI** — no UI exists to test |
| 13 | Execution disclosure | The disclosure text (`Q0.7_EXECUTION_DISCLOSURE.md`) accurately describes current engine behavior | **Content verified against source this sprint** (every claim in the disclosure doc traces to a specific, cited engine behavior) — not yet tested as *displayed* UI copy, since no UI exists |
| 14 | Error handling | Each error state in `Q0.7_UI_IMPLEMENTATION_PLAN.md`'s table triggers the right user-facing message, never a raw traceback | **NOT TESTED** — no API/UI layer exists yet to test against |
| 15 | Free-tier limits | Resource limits (Part 17) actually enforced | **NOT IMPLEMENTED, NOT TESTED** — recommendations only, no infrastructure built |

## What this table means in practice

Tests 1, 2, 3, 5, 6, 7 have **real evidence already**, accumulated
across Q0.2–Q0.6's own audit work — a future implementation sprint
should formalize these into actual assertions (pytest or equivalent)
rather than re-deriving the evidence from scratch, since the underlying
engine behavior is already proven correct.

Tests 4, 8, 9, 10, 14, 15 are **genuine gaps** — either the feature
doesn't exist yet (11, 12 partially, 14, 15) or the invariant has never
been formally checked (8, 9, 10) or the validation doesn't exist at all
(4). These should be prioritized in whichever sprint actually implements
the product surface, not deferred indefinitely as "probably fine."

No automated test suite was built this sprint — per instruction, this
is a plan, not an implementation. `quant-engine/scripts/q0*_*.py`
remain the closest thing to a test suite this program has (manual,
ad-hoc, but real and evidence-producing), consistent with every prior
sprint's own finding that this is a gap worth closing eventually.
