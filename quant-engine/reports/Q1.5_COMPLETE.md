## 4. Real finding #1 — undeclared-ref validation gap (fixed)

`"NaN"`/`"Infinity"` (and any typo) were syntactically valid identifiers but not checked against declared indicator ids, producing generated code referencing an undefined variable. Fixed in `schema.py`'s `_validate_ref()` by requiring the base id to actually be declared. Full regression re-run confirmed zero behavioral impact on anything that previously worked (MACD baseline unchanged, 42/42 golden strategies, 73/73 indicator matrix). Detail: `Q1.5_CODEGEN_SECURITY.md` Part 11.

## 5. Real finding #2 — internal traceback leaking to the client (fixed)

Both `run_backtest_job.py` and `run_codegen_job.py` had a generic exception handler that placed the **full Python traceback — including this machine's absolute source file paths** — into the `details` field, which both `executionAdapter.ts` and `codegenAdapter.ts` forward verbatim into the client-facing error response. Fixed: the traceback now goes to stderr only (captured server-side, confirmed never returned to the client); the client gets a fixed, non-identifying detail string. Verified via a live 200 OK sanity call, `ast.parse()` syntax checks, and the full Q0.9 (22/22) and Q1.5 (67/67) regression suites. Detail: `Q1.5_SECURITY_AUDIT.md` Part 13.

## 6. Test-script self-correction — not a product bug

The first draft of `q15_security_tests.ts` flagged `req.comment="` as a dangerous substring, but that prefix legitimately appears in every generated MQL5 file regardless of content, producing false failures on benign names. Corrected to check whether the **raw, unsanitized** name survives byte-for-byte into output — the actual signal of a real breakout — verified via direct curl inspection of generated code before and after the fix.
