## 11. API security

Backtest-path re-probed live this sprint with the same attack classes (path traversal, shell-like input, template injection, NaN/Infinity, Unicode, oversized input) — all correctly rejected or safely handled, server still healthy afterward. Client cannot forge metrics, coverage, status, evidence, or performance data anywhere — confirmed via code review of the typed, server-authoritative response contracts.

**One real bug found and fixed**: `run_backtest_job.py` correctly emits `INVALID_STRATEGY` for a strategy that fails `schema.py`'s validation (e.g. an undeclared condition ref like `"NaN"`), but the Node-side error-code allowlist (`executionAdapter.ts`) and the Results page's `ERROR_COPY` map had never been updated to recognize this code — every such failure silently downgraded to the generic `UNKNOWN_ERROR`. **Not a security gap** (the job still correctly failed either way — defense-in-depth was never bypassed) but a real classification/UX defect. Fixed in `types/quant-lite-job.ts`, `executionAdapter.ts`, and `ResultsView.tsx`; verified live (now correctly shows `INVALID_STRATEGY`) and full regression re-confirmed clean.

## 20. Known limitations (not hidden)

- **No authentication/authorization** — Quant Lite remains fully public, `AUTHORIZATION = NOT YET IMPLEMENTED` (unchanged since Q1.6).
- **No account-level backtest history** — jobs are ephemeral/file-based, not tied to a user account.
- **No rate limiting beyond process-level concurrency/timeout caps** — `MAX_CONCURRENT_BACKTESTS=2`, 180s/20s timeouts are the only throttle; a determined client could still send an unbounded number of distinct, legitimately-shaped requests. A generic (non-Quant-Lite-specific) oversized-request-body characteristic was also observed this sprint (a several-MB junk field is accepted rather than rejected) — low severity, shared across both Quant Lite API routes and not unique to this product, documented here rather than fixed under this sprint's hardening-not-features mandate.
- **Compiler verification unavailable** — no MetaEditor/TradingView compiler in this environment; every generated artifact is `STATIC-VALIDATION-ONLY`, stated plainly.
- **No slippage, no commission modeling** — stated explicitly in the Execution Assumptions panel on every relevant screen.
- **No tick-level replay, no Monte Carlo, no walk-forward optimization, no advanced robustness testing** — these are the explicitly-scoped Quant Pro boundary, not Quant Lite gaps to close.
- **Historical-data limitations / coverage restrictions are real** — RESTRICTED and DATA_UNAVAILABLE are genuine, server-computed, and shown honestly, not smoothed over.
- **14 documented, deferred dependency vulnerabilities** — none with direct Quant Lite runtime exposure, all requiring changes outside this sprint's safe blast radius.

None of the above blocks beta — per this sprint's own rule, disclosed limitations are not release blockers.
