# D2.3 Known Limitations

Honest inventory of what D2.3 does not cover, as of freeze. None of these blocked the Final Production Verification Audit's Production Ready determination — they're documented so D2.4 (or a future maintenance pass) starts from an accurate baseline, not a rediscovery.

## Carried-over Low findings from the Final Production Verification Audit (not fixed, deliberately deferred)

1. **Retry duplicates the user turn.** `app/dashboard/assistant/page.tsx`'s `handleRetry` re-sends the last user message through the normal send path, persisting it as a new turn rather than replacing the failed response in place. Minor conversation-history noise, not a correctness bug.
2. **Redundant database index.** `WorkspacePreference.userId` carries both a `@unique` constraint and a separate `@@index([userId])`. Harmless write-overhead, not fixed pre-freeze to avoid an unnecessary migration in the freeze window.
3. **A type-precision looseness.** `MarketAnalysisOutcome`'s `provider-error.cause` is typed optional even though its only real producer always sets it. No runtime impact today; a future refactor could silently leave `cause` unset without a type error.

## Newly noted while writing this snapshot

4. **`Article.disclaimer`'s Prisma schema-level default text is stale.** The column default reads `"This is not financial advice. Trading involves risk."` (the pre-D2.3.S4 string), while the application always explicitly sets the current canonical `AI_DISCLAIMER_TEXT` on every insert (`content-generator.service.ts`) - so the stale default is never actually reached by the real pipeline. Worth a one-line schema fix in a future migration for hygiene; zero user-facing effect today.

## Deliberately out of scope for D2.3

- **AI Trading Signals** (`app/dashboard/signals/page.tsx`) is explicit mock data (`services/ai/signal.service.ts`'s own header: "signal service (mock only)"). It was not one of the Final Audit's five audited entry points (AI Assistant, Intelligence Panel, Publishing, Research Assistant, Market Analysis) and uses a different UI convention (a categorical BUY/SELL/WAIT badge, not AI-authored prose) than the S4 compliance policy targets. Flagged, not silently touched - a real candidate for D2.4 or an earlier maintenance pass if it needs to move off mock data.
- **AI Financial News** (`app/dashboard/news/page.tsx`) is likewise explicit mock data, same reasoning.
- **Publishing is website-channel only.** `services/ai/publishing/publisher.service.ts`'s `SUPPORTED_CHANNELS` lists Telegram/Twitter/LinkedIn/newsletter/RSS as a reference for a future multi-channel pass; `runJob()` for those channels remains a documented placeholder, not implemented.
- **Gold/Silver (XAUUSD/XAGUSD) live coverage depends on which provider is actually configured and reachable in a given deployment.** Twelve Data supports them; Alpha Vantage's `CURRENCY_EXCHANGE_RATE` endpoint has been confirmed to reject them on at least one previously-tested key/tier. This is provider/plan-dependent, not a code limitation - see `docs/market-data-layer.md`'s troubleshooting section.
- **Candle (time-series) data has no service-level stale-cache fallback.** Only live snapshots/context get the S3 resilience fallback; `MarketDataService.getTimeSeries()` has no service-level cache at all (each provider caches its own series independently). Documented as a non-goal in `services/market-data/market-data.service.ts`'s own comments, not an oversight.
- **Concurrent identical requests are not coalesced.** Two simultaneous requests for the same symbol both hit the upstream provider before either populates the cache. Noted as future work in `docs/market-data-layer.md` since Sprint D2.2; unchanged in D2.3.

## Verification limitations (process, not product)

- **The live AI-compliance verification script (`scripts/validate-ai-response-compliance.ts`) could not complete a full 30-response run during S4** due to the Gemini free-tier account's real daily/per-minute quota (20 req/day on the primary model). 8 real responses were reviewed and found fully compliant, including the two most adversarial live-market prompts tested. The script itself (with retry/backoff/pacing) is a durable, reusable asset - a full run is one `npm run validate:ai-response-compliance` away whenever quota allows or a paid key is used.
- **Browser-based UI verification throughout D2.3's later sprints (S2-S4, Final Audit) was done without dashboard login credentials** (none were available in the working environment). Verification instead relied on: live API smoke-tests where feasible, the deterministic validate-script suite, `tsc`/`lint`/`build`, and careful code-level tracing. Genuine end-to-end click-through testing against the live authenticated dashboard is worth doing once credentials are available, even though nothing in this process surfaced evidence of a problem it would catch.
