# D2.3 Database Snapshot

Historical baseline of `prisma/schema.prisma` at D2.3 freeze. 24 models. This snapshot only calls out the models D2.3 added or materially changed — the full schema is the authoritative source for everything else (auth, billing, agents, knowledge base, workflows).

## Models added or changed in D2.3

### `WorkspacePreference` (new, D2.3-P7)
One row per user (`userId @unique`). Persists: active workspace `profile` (default/scalper/day_trader/swing_trader/investor), last-active `symbol`, chart interval, ordered `favoriteMarkets` (registry-validated canonical symbols), `collapsedPanels`, sidebar state, theme. Soft-deleted via `deletedAt`, indexed on `userId` and `deletedAt`.

### `Article` (new, D2.3.S1, `@@map("articles")`)
Real, DB-backed Publishing state — replaces the pre-D2.3 hardcoded mock array. `status` enum (`draft | scheduled | published | failed`); once `published`, the service layer enforces read-only (revision = `duplicateAsDraft()`, never an in-place edit — the seam is there for a future version-history table but this pass doesn't need one). `history` is an append-only JSON log (`{action, actor, timestamp, metadata?}[]`). `disclaimer` is a plain `String` column, always explicitly set by `content-generator.service.ts` at creation time from the canonical `AI_DISCLAIMER_TEXT` constant (see Known Limitations for a schema-level default-value note). Unique on `(userId, slug)`; indexed on `userId`, `(userId, status)`, `deletedAt`.

## Migration discipline

All D2.3 schema changes shipped as hand-written SQL migrations under `prisma/migrations/`, not `prisma migrate dev` auto-generation against the live dev database (see `project_sprint15c_workflow` memory: `prisma migrate dev` has a known pgvector-reset trap in this environment). Every new table follows the established soft-delete (`deletedAt`) + explicit index convention already used platform-wide.

## Known, accepted schema-level gap

`WorkspacePreference.userId` carries both a `@unique` constraint (which Postgres also uses for equality lookups) and a separate, redundant `@@index([userId])`. Harmless — flagged in `D2.3_KNOWN_LIMITATIONS.md`, not fixed pre-freeze (a schema migration for a purely cosmetic index carries more freeze-window risk than the finding warrants).
