# D2.8.0 — Market Data Capability & Evidence Audit

**Status:** Documentation-only audit. Zero production code changed.
**Baseline:** commit `525a001`.
**Companion document:** `docs/market-data-layer.md` (Sprint D2.2's original provider-layer architecture doc) — this document supersedes it as the *capability* reference; the D2.2 doc remains accurate for provider priority/caching/resilience mechanics and is not duplicated here.

## 1. Executive Summary

AT24's market-data layer reliably provides **OHLC price data, volume (where the source provider reports it), and derived technical indicators** across forex, commodities, crypto, and select Indian equities/indices. It does **not** currently provide bid/ask (in the active snapshot pipeline), spread, tick data, trade-direction/buy-sell delta, order-book depth, or any form of real execution telemetry (slippage, latency, fill probability). These are not partially-implemented — they are architecturally absent: the platform's own `MarketDataCapability` type is `"quote" | "candles"` only, by explicit design ("no 'orderbook'/'trades' capability exists because nothing in this codebase reads one" — `types/canonical-instrument.ts`).

One genuine, real capability was found that is **not currently reachable in production**: Alpha Vantage's `CURRENCY_EXCHANGE_RATE` endpoint returns real bid/ask for EURUSD (confirmed working) and XAU/XAG (currently rejected by the configured API key/tier). This bid/ask is parsed and would be usable — but it flows only into the older `MarketContextResult.evidence[]` text-claim array, never into the canonical `MarketSnapshot.bid`/`ask` fields the Intelligence Engine V2 / native chart pipeline actually consumes, because `AlphaVantageProvider` does not implement `SnapshotProvider`. The three providers that *do* implement `SnapshotProvider` (Twelve Data, Binance, Angel One) never populate `bid`/`ask` at all. Net effect: `MarketSnapshot.bid`/`ask` are structurally unreachable today despite the type declaring them.

One genuine fabrication risk was found and confirmed **dead** (unreachable from any live route, page, or service — verified by a repository-wide reference search): `services/ai/trading/liquidity-analysis.service.ts`'s `getLiquidity()` computes fake "buy-side"/"sell-side"/"equal highs/lows" liquidity zones as a fixed ±0.5%/1%/1.5% offset from the current price — no real order-book or structural basis whatsoever. It belongs to an orphaned, pre-D2.2 prototype call chain (`market-analysis.service.ts` → `getIndicators`/`getLevels`/`getLiquidity`/`getBias`/`getSetup`/`getRisk`/`getConfidence`, all taking only `price`/`changePercent`) that predates the real `MarketDataService`/`TradingCopilotService` architecture and was superseded, not deleted. It is not wired into any current route (confirmed: the live `/api/private/trading-copilot/analyze` route uses the real, MarketDataService-backed `TradingCopilotService`, an entirely separate implementation). Flagged in §13/§15 for a future cleanup sprint — not touched in this documentation-only sprint.

Every other "warning" in the product today (liquidity zones unavailable, buy/sell delta unavailable, execution risk not integrated, order-book liquidity unavailable, historical validation sample below minimum) is genuinely honest: each traces to a real, intentional `undefined`/absent field with a code comment explaining exactly why, not a bug and not an excuse.

## 2. Current Provider Architecture

Four live `MarketDataProvider` implementations, orchestrated by `services/market-data/market-data.service.ts` (`MarketDataService`), default priority order: **Twelve Data → Alpha Vantage → Binance → Angel One**. A capability-filtered, health-aware reordering (`orderProviders()`, D2.6.4 "Smart Fallback") can reorder this at runtime when `smartFallback: true` is set (the shared production singleton, `services/market-data/shared-instance.ts`, enables it) — never changes *which* providers exist, only the attempt order.

- **Twelve Data** (`lib/market-data/providers/twelve-data.provider.ts`) — primary. Real-time quote + historical OHLCV. Forex, commodities, crypto.
- **Alpha Vantage** (`lib/market-data/providers/alpha-vantage.provider.ts`) — spot-only fallback. Real-time quote (with real bid/ask for its 3 mapped symbols) via `getMarketContext()` only — no `getSnapshot()`, no `getTimeSeries()`. EURUSD, XAUUSD, XAGUSD mapped; XAU/XAG currently rejected by the configured key/tier (documented in the file's own header — a real, previously-verified API-tier limitation, not a bug).
- **Binance** (`lib/market-data/providers/binance.provider.ts`) — crypto quote + historical klines, no API key required (public REST). BTCUSD, ETHUSD, SOLUSD, XRPUSD.
- **Angel One** (`lib/market-data/providers/angel-one.provider.ts`) — Indian equities/indices (NSE/BSE) quote + historical candles. NIFTY 50, RELIANCE, BANKNIFTY, TCS, INFY, HDFCBANK.

Supporting infrastructure (D2.6.3/D2.6.4): `lib/market-data/instrument-catalog.ts` (canonical instrument registry + per-instrument `ProviderMapping[]`), `lib/market-data/provider-capabilities.ts` (provider-level asset-class/exchange gating), `services/market-data/provider-reliability.service.ts` (health-based reordering), `services/market-data/freshness-policy.service.ts`, `services/market-data/cross-provider-validation.service.ts`, `services/market-data/market-snapshot-integrity.service.ts`, `services/market-data/discovery/*` (D2.6.12 universal instrument discovery beyond the hand-curated catalog).

## 5. Direct vs Derived vs Inferred vs Unavailable

- **A — Directly Available:** OHLC (live + historical, bounded), volume (provider-dependent), Alpha Vantage's real bid/ask (present but stranded outside the active pipeline).
- **B — Deterministically Derived:** RSI14, EMA20/EMA50, ATR14, MACD, Bollinger Bands, `volumeMetrics` (latest/average/relative) — all computed from real OHLCV via `lib/market-data/indicators.ts`, byte-for-byte the same formulas whether used as a scalar (point-in-time) or a full series (chart overlay). `recentRange`/breakout-breakdown signal (`MarketStateService`) also qualifies — real structural derivation from real candles, honestly *not* called a "liquidity zone" anywhere in the live pipeline.
- **C — Inferred Intelligence:** Trend direction (`up`/`down`/`sideways` from EMA20/EMA50 relationship), volatility band (`low`/`medium`/`high` from ATR-as-%-of-price), Regime classification, Hypothesis generation, DecisionContext state, IntelligenceScore. All downstream of A/B, never downstream of anything fabricated.
- **D — Unavailable:** Bid/ask (in the active pipeline), spread, tick data, buy/sell delta, order book, market depth, real order-book liquidity zones, slippage, execution latency, fill probability, execution risk.
- **E — Not Verified:** Binance/Angel One's exact historical-depth ceiling (not re-derived byte-for-byte this sprint, see §3); whether Alpha Vantage's XAU/XAG rejection is key-tier-specific or permanent for this product tier.

## 6. Data-Fabric Flow

```
Provider (Twelve Data / Alpha Vantage / Binance / Angel One)
        |
        v  MarketDataProvider.getSnapshot() / getTimeSeries() / getMarketContext()
Canonical instrument resolution (instrument-catalog.ts, ProviderMapping)
        |
        v
MarketDataService (priority order, optional Smart Fallback reordering,
                    per-call reliability/retry, caching, stale-fallback)
        |
        v
MarketSnapshot { symbol, price, ohlc?, volume?, bid?, ask?, ... }
   (bid/ask fields exist in the TYPE but are never set by any
    SnapshotProvider currently wired - structurally always undefined
    in this flow)
        |
        v
MarketStateService.assemble({ snapshot, candles })
        |
        v
MarketState { technical: {rsi14, ema20, ema50, atr14, macd, bollinger, volume},
              structure: {trend, recentRange, breakoutSignal, volatilityBand,
                          liquidityZones: undefined, volumeDelta: undefined,
                          bos: undefined, choch: undefined} }
        |
        v
RegimeService -> Regime
        |
        v
HypothesisService -> Hypothesis[]
        |
        v
DecisionContextService -> DecisionContext (riskContext.liquidity/execution:
                                             honest "unmeasured" default)
        |
        v
IntelligenceScoreService -> IntelligenceScore (historicalValidation gated
                                                on real DB sample >= 30,
                                                D2.7.8-D2.7.11)
        |
        v
AI Presenter (Gemini/Claude/OpenAI) -> restates only what's real, never
                                        invents bid/ask/liquidity/execution
```

`bid`/`ask`/`spread`/`tick`/`depth`/`delta` exist as TypeScript fields/types in exactly these places and nowhere else: `types/market-snapshot.ts` (bid/ask, unreachable), `types/liquidity.ts` (spread, unreachable/unused), `types/intelligence-market-state.ts` (liquidityZones/volumeDelta, explicitly never populated), `types/risk-intelligence.ts` + `types/intelligence-decision-context.ts` (liquidity/execution risk categories, explicitly "never backfilled"). No `tick`, `orderBook`, or `depth` type exists anywhere in the codebase.

## 7. MarketState Consumption

Verified from `services/intelligence/market-state/market-state.service.ts` source (not assumed):

## 8. Intelligence Consumption

Traced `MarketState → Regime → Hypothesis → DecisionContext → IntelligenceScore`:

- **Regime/Hypothesis:** consume only `MarketState.technical`/`structure` fields listed in §7 (trend, volatility band, breakout signal, RSI/EMA/ATR/MACD/Bollinger/volume-metrics). Confirmed no liquidity/bid-ask/execution reference in these services (consistent with D2.5.2/D2.5.3 architecture already documented in this repo).
- **DecisionContext:** `riskContext.liquidity`/`riskContext.execution` are explicitly documented (`types/intelligence-decision-context.ts:90`) as categories that carry RiskEngine's "honest 'unmeasured' default" — never presented as a failure, never backfilled with a guess.
- **IntelligenceScore:** `historicalValidation` component is the only score input gated on a real database sample (D2.5.4/D2.7.8-11), unrelated to liquidity/execution. No score component reads bid/ask/spread/tick/depth anywhere.
- **Conclusion:** liquidity/spread/bid-ask/order-book/delta/execution-risk are **represented in types and warnings, never actually consumed as real inputs anywhere in the live Intelligence Engine V2 pipeline** — exactly the honest, non-fabricating design the product principle demands.

## 9. Native Chart Consumption

`lib/chart-engine/` (candle-normalizer, renderer, sub-panel-renderer, indicators/compute.ts, indicators/panel-registry.ts) consumes **only OHLCV** — real candles from `MarketDataService.getTimeSeries()`, the identical source MarketState uses. Volume is rendered as its own sub-panel (confirmed: `volume`/`Volume` referenced across 6 chart-engine files) using the exact same `volumeMetrics`-class math as the scalar indicator engine (D2.7.3's own documented parity requirement, cross-checked by `validate-native-chart-production.ts`). No chart-engine file was modified in this audit.

## 11. Twelve Data Historical Limitation

Unchanged since D2.7.8/D2.7.9: `TwelveDataProvider.getTimeSeries()` issues a single `outputsize`-bounded REST call with no date-range parameters and no pagination loop — "latest N candles as of now," never an arbitrary historical window. This matters in exactly these places:

- **Historical validation** (D2.5.4/D2.7.9-11): `HypothesisOutcomeEvaluatorService` can fail to reach far enough back for an old hypothesis's evaluation boundary, honestly resolving to `inconclusive` (excluded from the sample denominator) rather than fabricating a verdict.
- **Chart history:** a user scrolling far enough back on the native chart is bounded by the same window — not separately re-verified in this sprint (chart-engine untouched).
- **Indicator computation / MarketState construction:** unaffected in the normal case — `RealTimeIntelligenceService` requests only `DEFAULT_CANDLE_OUTPUT_SIZE = 100` candles, comfortably within any single-call window for indicator warm-up (EMA50 needs 50).
- **Not fixed in this sprint**, per explicit instruction.

## 12. Missing Raw Data

None of these exist as real data anywhere in the current provider layer (Alpha Vantage's bid/ask being the sole partial exception — real, but stranded outside the active pipeline per §1/§4).

## 13. Broker/Exchange Source Requirements

| Desired Capability | Missing Raw Data | Why Current Data Is Insufficient | Potential Source Type | Priority |
|---|---|---|---|---|
| Bid/Ask (in the active pipeline) | Real-time bid/ask reaching `MarketSnapshot` | Alpha Vantage has it but isn't wired as a `SnapshotProvider`; other 3 providers never report it | Either: wire Alpha Vantage's existing bid/ask into `MarketSnapshot` (zero new provider, smallest lift), or a dedicated real-time quote-stream source for broader instrument coverage | Low-Medium (cheap partial win exists; full coverage needs a real source) |
| Spread | Real bid/ask (see above) | Cannot compute `ask - bid` without both sides genuinely present | Same as Bid/Ask | Low-Medium |
| Buy/Sell Delta | Tick-level trades with aggressor-side (buy vs. sell-initiated) classification | Candle volume has no direction; inferring direction from candle shape would be a fabrication, explicitly forbidden | Exchange/broker tick feed with aggressor-side classification (e.g. a raw trade stream, not a candle aggregate) | Medium (real product value, but genuinely requires new infrastructure, not a wiring fix) |
| Order Book / Depth | L1/L2 book snapshots or streaming depth updates | No such concept exists anywhere in this codebase's types | Exchange/broker market-depth feed (WebSocket depth stream or REST L2 snapshot endpoint) | Medium-High effort, product value depends on target user (day traders/scalpers value this most) |
| Liquidity (order-book sense) | Same as Order Book | Structural "recent range" is a real but different concept (price action, not book depth) — must never be relabeled as order-book liquidity | Same as Order Book | Same as Order Book |
| Execution Risk | Spread + slippage + latency + fill data, all real-time and execution-linked | None of the four inputs exist; this is a composite that needs every one of them genuinely measured, not estimated | Broker execution API/feed (order acknowledgment + fill reports), only meaningful once real order flow exists | Low priority until/unless AT24 actually executes orders — premature before that |

No specific broker is recommended (per explicit instruction) — the source *type* is what's missing, and multiple vendors could satisfy each row.

## 14. Recommended Priority Order

1. **Wire Alpha Vantage's already-real bid/ask into `MarketSnapshot`** (smallest possible lift — no new provider, no new credentials, the parsing code already exists and is tested; would immediately make Spread classification-B-eligible for EURUSD, and XAU/XAG the moment the key tier supports them). This alone doesn't require broker integration.
2. **Decide whether tick/order-flow data is actually a product priority** before pursuing it — it requires genuinely new infrastructure (a streaming tick feed), not a wiring fix, and D2.8.0's own mandate is to establish *whether* this is justified, not to assume it is.
3. **Order book / depth** — highest effort, evaluate against actual target-user demand (day-trading/scalping audiences value this far more than swing-trading/positional audiences) before committing.
4. **Execution risk** — explicitly sequence this *after* any real broker/execution integration decision, never before; measuring execution risk without real execution data is definitionally impossible, not a data-quality gap to work around.

## 15. Unsupported-Assumption Risks

1. **`services/ai/trading/liquidity-analysis.service.ts` fabricates liquidity zones from price alone** (§1, §4). Confirmed dead code (zero live callers) as of this audit — but its mere existence in the repository is a landmine: any future refactor that casually reconnects `market-analysis.service.ts`'s call chain (e.g., someone "fixing" the Trading Copilot by swapping in what looks like a more complete implementation) would silently reintroduce fabricated liquidity data into a user-facing surface. **Recommend a future cleanup sprint delete the entire orphaned chain** (`market-analysis.service.ts`, `liquidity-analysis.service.ts`, `technical-analysis.service.ts`, `support-resistance.service.ts`, `market-bias.service.ts`, `trade-setup.service.ts`, `risk-engine.service.ts`, `confidence-engine.service.ts` under `services/ai/trading/` — verify each has zero other callers before deleting, the same discipline as this audit).
2. **`MarketSnapshot.bid`/`ask` existing as typed fields with zero live producers** is a latent trap for any future developer who assumes "the type has it, so it must be populated" — worth either populating (Alpha Vantage wiring, §14 priority 1) or explicitly annotating as currently-unreachable in the type itself, in a future sprint.
3. **Do not let "Twelve Data reports volume" become "AT24 has order flow."** Session/24h volume is a real, legitimate, already-correctly-used signal (feeds `volumeMetrics`, RSI-adjacent context) — but it carries no directional information and must never be presented as buy/sell pressure.
