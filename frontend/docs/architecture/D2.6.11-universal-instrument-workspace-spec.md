# D2.6.11 — Universal Instrument Workspace, Dynamic Chart Resolution & Live Workspace Integration

**Status:** Implemented and tested.
**Scope:** An integration and production-readiness sprint for the pre-existing `/dashboard/workspace` page (D2.3-era). No new architecture, no new intelligence engine, no new AI pipeline. TradingView remains the chart visualization layer; it never becomes a source of market intelligence.

**Naming note:** This sprint's brief self-labeled "D2.6.10," referencing a stale "latest commit 82d9ce3." D2.6.10 ("Trader Intelligence Workspace & Verified Answer Experience" — the Assistant chat page's verified-answer UI) had already been completed and pushed earlier in the same session as commit `1e6e363`. This sprint was relabeled D2.6.11 to avoid colliding with that doc/commit history, per an explicit note to the user before work began, later confirmed by the user's own follow-up brief which independently used the same "D2.6.11" label.

---

## 1. Root cause

`components/workspace/tradingview/AdvancedChart.tsx` carried its own separate, hardcoded 7-entry `TV_SYMBOL` map (`EURUSD`/`GBPUSD`/`USDJPY`/`XAUUSD`/`XAGUSD`/`BTCUSD`/`ETHUSD`) with a silent `?? "FX:EURUSD"` fallback for anything else. Every other real catalog instrument — `NIFTY50`, `BANKNIFTY`, `RELIANCE`, `TCS`, `INFY`, `HDFCBANK`, `SOLUSD`, `XRPUSD`, `AAPL` — silently rendered the EUR/USD chart with no error state. This was a second, disconnected, incomplete symbol registry the chart used to decide what it could show — exactly the "second hardcoded chart-supported symbols list" this sprint's brief prohibits.

Everything upstream of the chart was already correct: `GlobalSymbolSelector` (D2.6.3) already resolves a real `CanonicalInstrument` and writes its `id` into `WorkspaceContext.symbol`; `market-registry.ts` has listed every Indian instrument as `enabled: true` since D2.6.6; `WorkspaceHeader`/`IntelligencePanel`'s snapshot/analyze routes already accept any enabled symbol. The chart's own local map was the sole point of failure.

A smaller instance of the same bug class was found in `components/workspace/MarketRibbon.tsx`: its own separate, hardcoded `ITEMS` array used the wrong id (`"NIFTY"` instead of the real catalog/registry id `"NIFTY50"`) and marked both NIFTY and BANKNIFTY `live: false`, predating D2.6.6's real Angel One coverage. Fixed in the same pass.

## 2. Canonical instrument flow (unchanged, confirmed correct)

```
User search (GlobalSymbolSelector)
  -> GET /api/private/instruments/search (InstrumentSearchService, D2.6.3)
  -> real CanonicalInstrument records (lib/market-data/instrument-catalog.ts)
  -> setSymbol(result.id)  [WorkspaceContext, the single symbol source of truth]
  -> every panel reads useWorkspace().symbol
```

No second symbol registry or search index was introduced. `InstrumentSearchService` and `ChartInstrumentResolver` both read `INSTRUMENT_CATALOG` directly — verified structurally (`scripts/validate-universal-workspace.ts`, test 20).

## 3. Chart resolution architecture

`lib/market-data/chart-instrument-resolver.ts` is the one new deterministic mapping layer:

```ts
resolveChartInstrument(canonicalId: string): {
  canonicalSymbol, displaySymbol, chartProvider: "tradingview",
  chartSymbol?, exchange?, supported, reason?
}
```

Every `INSTRUMENT_CATALOG` member gets an explicit, real TradingView symbol (or an honest `supported: false` with a reason) — never a silent substitution. FX/metals/crypto entries reuse the exact TradingView symbols the chart already used successfully (`FX:`, `OANDA:`, `COINBASE:`); the newly covered crypto pairs (`SOLUSD`/`XRPUSD`) follow the same `COINBASE:` convention already proven for `BTCUSD`/`ETHUSD` rather than introducing a second exchange convention. Indian instruments use TradingView's real `NSE:` listings. `AAPL` resolves a real `NASDAQ:AAPL` chart even though it has zero market-data provider coverage — the chart is a visualization concern, independent of `MarketDataService` (§4/Part 6 below).

`AdvancedChart.tsx` now calls this resolver and renders an explicit "Chart visualization is unavailable for X" state (with the resolver's real reason) when `supported` is false, instead of silently showing a different instrument. The existing `key={...}` remount mechanism (React reconciliation, not a timeout) is unchanged in mechanism — it now derives from the resolved chart symbol, so it is correct for every catalog instrument, not just the previous 7.

## 4. Provider / chart data separation (unchanged, verified)

The chart is visualization only. Market intelligence — `MarketSnapshot`/`MarketState`/`Regime`/`Hypothesis`/`Evidence`/`Risk`/`HistoricalValidation`/`IntelligenceScore` — continues to come exclusively from `MarketDataService`'s provider-capability-filtered, D2.6.4 smart-fallback path, entirely independent of `chart-instrument-resolver.ts`. `AdvancedChart.tsx` imports no market-data service; the resolver imports only the catalog.

## 5. Provider routing (unchanged, re-verified)

Catalog data confirms the documented architecture is intact: every Indian instrument carries a verified `angel-one` mapping; every crypto instrument carries a real `binance` mapping (quote + candles); every FX/metals instrument carries a real `twelve-data` mapping (`scripts/validate-universal-workspace.ts`, tests 10–12). No provider priority or routing logic was touched — `MarketDataService`'s router (D2.6.3/D2.6.4) is unmodified.

## 6. Workspace symbol-state consistency

`WorkspaceContext` (`context/WorkspaceContext.tsx`) remains the single `symbol`/`setSymbol` source of truth — one `createContext` call, one provider. Every panel (`GlobalSymbolSelector`, `WorkspaceHeader`, `AdvancedChart`, `IntelligencePanel`, `MarketRibbon`, the new `WorkspaceAssistant`, the new `WorkspaceResearch`) consumes it via `useWorkspace()`. Verified structurally (test 25–26).

## 7. AI Assistant panel

The stale `pending="Embedded assistant arrives later in D2.3."` placeholder is replaced by `components/workspace/WorkspaceAssistant.tsx`, a minimal chat surface. It is **not** a second AI pipeline: every send hits the exact same `POST /api/private/knowledge/chat` route the dashboard Assistant page uses (D2.6.5–D2.6.10, unmodified), with one additive request field — `symbol`, the Workspace's own active `WorkspaceContext.symbol`.

The chat route (`app/api/private/knowledge/chat/route.ts`) now accepts an optional `symbol` in its body and forwards it to `IntelligencePresentationService.present()` (already accepted `symbol?: MarketSymbol` on `ResolveChatIntelligenceInput` since D2.6.5 — this was a request-context bias the route simply never exposed). `services/intelligence/query/intelligence-query.service.ts`'s `resolveSymbol()` resolution priority is unchanged: a symbol mentioned explicitly in the question text still wins, then this request-context value, then persisted conversation context. This lets "What's happening?" (which names no instrument) resolve against the instrument the trader is actually looking at, and lets a symbol switch in the Workspace change what the *next* question resolves against — without ever overriding an explicit "What about RELIANCE?" typed in the box.

A resolved answer renders through the exact same `VerifiedAIAnswerCard` D2.6.10 already built — no second answer UI.

## 8. Research panel

The stale `pending="Research workspace arrives in D2.4."` placeholder is replaced by `components/workspace/WorkspaceResearch.tsx`, backed by a new thin route, `GET /api/private/intelligence/research?symbol=X`, and `services/intelligence/chat/research-snapshot.service.ts`.

`ResearchSnapshotService` reuses the exact same chat-facing boundary D2.6.5–D2.6.10 established: `IntelligenceChatContextService.resolve()` → `DecisionContextService.build()` → `buildVerifiedAnswerResponse()` (all unmodified) — no second research engine, no duplicated Intelligence Score, no new formula. It deliberately skips the AI presenter entirely: Research is a data view, not a chat turn, so `answer` is a short, deterministic, non-AI-generated summary line, and `presentedBy: "deterministic-research-snapshot"` discloses that honestly (same "Presented by X" convention D2.6.10 established). No conversation message is persisted and no audit trace is created for a Research read (`auditTraceId` stays `undefined`) — it is a stateless, read-only snapshot of the active symbol's current deterministic intelligence.

The Research panel renders through the same `VerifiedAIAnswerCard` component as the Assistant and the main chat page — it already contains everything Part H of the brief asked for (current state via the market-context header, evidence, hypotheses, invalidation, risk, historical validation, Intelligence Score, provenance), so no new UI was built for it.

## 9. Unsupported / error / loading states

- **Chart unsupported:** `AdvancedChart` — "Chart visualization is unavailable for {instrument}" plus the resolver's real reason.
- **AI Intelligence / Research unavailable:** the existing `EmptyState` pattern — "No provider could confirm live market data for {symbol} right now. Shown honestly rather than with a fabricated result."
- **Loading:** `WorkspaceResearch` resets to a real loading skeleton on every symbol change and re-fetches with an `AbortController` (the same pattern `IntelligencePanel` already established) — the previous symbol's panels are never left visible while a new symbol's data is in flight.
- **Assistant errors:** "The assistant could not respond. Please try again." — no raw provider error text is ever surfaced to the browser.

## 10. Security

- `app/api/private/intelligence/research/route.ts` requires authentication (`getUserOrNull`) before returning any data, matching every other private route's pattern.
- Neither the research route nor either new Workspace component imports a provider adapter (`angel-one.provider`, `binance.provider`, `twelve-data.provider`, `alpha-vantage.provider`) or `MarketDataService` directly — the frontend/server boundary D2.6.5 established (Frontend → chat-facing layer → intelligence services → market-data services → providers) is unchanged.
- No component references a server credential or `process.env` value.
- Verified structurally and by serialization (`scripts/validate-universal-workspace.ts`, tests 44–48).

## 11. Testing

This project has no React/component test framework — UI correctness is verified via `tsc`/`eslint`/`npm run build` plus a browser check (see the sprint's final report for exactly what was and wasn't clicked). `scripts/validate-universal-workspace.ts` (55 assert-based tests) covers every deterministic contract the fix depends on: the chart resolver (every catalog instrument explicitly classified, no silent gap, deterministic/pure, no cross-instrument collision), real provider-capability data (Indian → Angel One, crypto → Binance, FX/metals → Twelve Data), search-result correctness, structural source checks (the old `TV_SYMBOL` map is actually gone, not papered over; no duplicated TradingView symbol table; no stale placeholder text; one `WorkspaceContext`), the chat route's new symbol passthrough, the Research snapshot service (resolved/insufficient-data/no-audit-trace/no-presenter-call), fallback disclosure honesty, header/ribbon symbol-registry consistency, security, and the exact worked regression scenarios from the brief (default symbol works, search-and-select works, repeated switching doesn't retain the previous chart, India/crypto/global each hit their real provider path, a provider failure resolves honestly). Full regression across every pre-existing `validate:*` script, `tsc`, `eslint`, and `npm run build` — see the sprint's final report for pass/fail counts.

## 12. Non-goals (explicitly not built)

No ML, no new trading signals, no BUY/SELL probability, no automated trading, no broker execution, no order placement. No change to the Intelligence Score formula, Regime logic, Hypothesis logic, or `DecisionContext` architecture. No redesign of provider reliability or global provider priority. No Redis/Kafka, no vector-DB redesign. TradingView was not replaced. No second AI pipeline, no second symbol registry, no second research engine, no new market-data provider. No weakening of response integrity; no provider credential ever reaches the browser.

## 13. Known limitations

- Chart coverage is exactly the `INSTRUMENT_CATALOG` set (16 instruments). A future catalog addition needs one new entry in `chart-instrument-resolver.ts`'s `TRADINGVIEW_SYMBOL` table (or an honest `supported: false` if no real TradingView representation exists) — this is the intended, single point of extension.
- `AAPL`'s chart renders (`NASDAQ:AAPL` is a real TradingView symbol) even though no configured provider serves its market data — WorkspaceHeader/IntelligencePanel/Research all honestly show "unavailable" for it. This is a deliberate, documented split (chart visualization vs. intelligence data, per Part 6 of the brief), not an oversight.
- Live authenticated Angel One / Binance smoke validation and full interactive browser verification are reported separately in the sprint's final report, together with any environment constraints encountered.
