# D2.8.4 — Dukascopy Forex & Metals Capability Audit

**Status:** Research/documentation audit complete. No production code changed, no account created, no credentials requested. **Baseline:** D2.8.3 (`1cd5918`).
**Scope:** Determine, from official Dukascopy sources only, exactly what Dukascopy's JForex API and FIX API can provide AT24 for EURUSD, GBPUSD, XAUUSD, and XAGUSD. **No Dukascopy provider was created. No production architecture was modified.**

---

## 1. Executive finding

Dukascopy genuinely supports all four AT24 instruments (EURUSD, GBPUSD, XAUUSD, XAGUSD are confirmed, first-party, statically-defined instruments in the JForex API's own `Instrument` enum) and its **live** JForex tick feed genuinely exposes multi-level bid/ask depth with volumes (`ITick.getAsks()`/`getBids()`/`getAskVolumes()`/`getBidVolumes()`) — a real capability none of AT24's current providers (Twelve Data, Alpha Vantage, Binance, Angel One) offer for forex/metals today. **However, this capability comes with three material, evidence-based caveats that make Dukascopy a poor near-term fit:**

1. **Historical depth does not exist.** Dukascopy's own documentation states the multi-level price arrays are populated "only when working with live data" — historical ticks (`IHistory.getTicks()`) and back-testing always return a single price level. AT24 cannot backfill or research Dukascopy order-flow history the way it can with OHLC.
2. **Full API development support requires a USD 100,000 minimum deposit.** This is stated verbatim on Dukascopy's own "Minimum Conditions" page. A narrower "External Service Provider" path exists that doesn't require depositing funds, but it still requires a business-partnership screening process, not a self-serve signup.
3. **JForex API is not a simple REST/WebSocket client AT24 could call from its existing Next.js/TypeScript backend.** It is a Java library whose strategies run inside Dukascopy's own JForex client/server infrastructure (`onTick()` callbacks fired by Dukascopy's platform, not a socket AT24 opens itself). Any integration would require a separate Java service acting as a bridge — a real architectural cost, not a documentation nuance.

The FIX API is more consumable from an external system, but its own documentation states its instrument list "is limited to FX only" — **no metals** — so it cannot serve XAUUSD/XAGUSD at all, only EURUSD/GBPUSD.

## 6. JForex API analysis

- **Access model:** a Java client library whose strategies execute **inside Dukascopy's own JForex client/server runtime** — market data arrives via callbacks (`onTick()`) fired by Dukascopy's platform to a running strategy, not via a socket/HTTP endpoint an external service opens on its own initiative.
- **Language/runtime:** Java (JForex API / JForex SDK for running strategies outside the visual client, still Java).
- **Data capabilities:** richest of the two paths researched — live multi-level depth (via `ITick`), historical ticks (top-of-book only), historical bars, and the four confirmed AT24 instruments.
- **Suitability for AT24's TypeScript/Next.js stack:** **poor, without a bridge.** AT24 has zero existing Java infrastructure (confirmed in Phase 1, §7 below). Consuming JForex would require standing up and operating a **separate Java service** whose only job is running a JForex strategy and forwarding its `onTick()` data to AT24's Node.js backend over some internal channel (the sprint's non-goals explicitly forbid adding this now — noted here as a finding, not a proposal to build).
- **Licensing:** JForex API is "granted under a non-exclusive, non-transferable, worldwide license for personal, non-commercial use" by default; commercial use requires "a signed supplementary agreement" (search-summarized from Dukascopy's own terms-of-use language — class B, not independently re-verified against the full EULA text this sprint).

## 7. FIX API analysis

- **Protocol:** FIX 4.4 (Dukascopy's own stated version).
- **Access model:** a standard FIX session — genuinely consumable from an external service (including, in principle, a Node.js FIX client), unlike JForex's in-platform-strategy model.
- **Instrument coverage:** **forex only** — confirmed, first-party: "available instrument list is limited to FX only." **XAUUSD/XAGUSD are not reachable via FIX at all.**
- **Market depth:** documented to exist via `MDEntryType` entries in Market Data messages, with a separately-described "Market Depth table" showing "up to 10 price levels... on each side — BID and ASK" (search-summarized from the FIX API Programming Guide's own content — class B).
- **Minimum conditions:** **USD 100,000 minimum deposit** for full IT-supported API development access, confirmed verbatim on Dukascopy's own "Minimum Conditions" page. An "External Service Provider" category is explicitly exempted from the deposit requirement, but still requires submitting a business description for Dukascopy's own screening/partnership process — not a self-serve signup either way.
- **Suitability for AT24:** technically the more externally-consumable of the two APIs (no Java bridge needed in principle), but **instrument-incomplete** (no metals) and gated behind the same commercial-relationship requirement as JForex.

## 12. Venue/feed limitations (explicit)

- **Dukascopy data ≠ global FX market data.** Every bid/ask/depth field documented in this audit is Dukascopy Bank's own quoted price and its own SWFX venue's visible liquidity — a real, legitimate, but single-venue view.
- **Dukascopy/SWFX liquidity ≠ the entire decentralized FX market's liquidity.** SWFX aggregates "over 20 major banks" per Dukascopy's own description — a genuine multi-bank ECN pool, not the sum of all interbank/retail FX liquidity worldwide.
- **No true centralized order book exists for FX at any venue, Dukascopy included** — the `ITick` depth arrays are Dukascopy's own best-effort composite of its liquidity providers' quotes, structurally different from an exchange's single, authoritative limit order book (e.g., Binance's central-limit order book for BTCUSDT, or a COMEX futures order book).
- If AT24 ever surfaces Dukascopy-derived depth/liquidity data, it must be labeled **"Dukascopy/SWFX liquidity"**, never "FX market depth" or "global liquidity" — matching this sprint's explicit instruction and the same discipline D2.8.2/D2.8.3 already established for other venues (COMEX ≠ spot gold, Binance's own order book ≠ "the crypto market").

## 17. Recommended next step

**Do not integrate.** Dukascopy's genuine depth capability does not outweigh its cost/architecture mismatch when Binance already provides a comparable, zero-cost, zero-new-infrastructure depth+aggressor capability for AT24's crypto instruments (D2.8.3), and Angel One already provides a documented, likely-lower-friction depth path for AT24's Indian instruments once credentials are restored (also D2.8.3).
