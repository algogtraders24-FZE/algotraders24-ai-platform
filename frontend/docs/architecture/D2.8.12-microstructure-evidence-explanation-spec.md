# D2.8.12 — Microstructure Evidence Explanation & User-Facing Intelligence Integration

## 1. Implementation summary

D2.8.11 computed `MicrostructureEvidenceAssessment` (confirms/contradicts/neutral/insufficient_evidence) and attached it to `IntelligenceDecisionContext.microstructureEvidence`, but nothing downstream ever read that field — the AI presenter and the chart panel both still only saw raw bid/ask/depth numbers, never the already-computed relationship. D2.8.12 closes that gap. It adds one new pure formatter (`formatMicrostructureEvidenceExplanation`), threads the existing D2.8.11 assessment through two already-additive seams (`AIPresenterOrchestratorService.present()` and `buildPresenterQuestionWithMicrostructure()`), adds a new response-integrity check class (`microstructure-overclaim`), and optionally surfaces the same explanation on the native chart's microstructure panel. No microstructure math, threshold, or hypothesis-direction logic was reimplemented anywhere — every number and state word this sprint displays is read verbatim off D2.8.11's own `MicrostructureEvidenceAssessment`.

## 2. Exact presentation insertion point

`services/intelligence/chat/intelligence-presentation.service.ts`'s `IntelligencePresentationService.present()`. Previously, `decisionContext` (which computes `microstructureEvidence`) was built *after* the presenter was called, so the presenter never had access to it. This sprint reordered the two calls — `decisionContext = this.decisionContextService.build(envelope, context.microstructure)` now runs first — and forwards `decisionContext.microstructureEvidence` as a new 4th argument to `this.presenterOrchestrator.present(envelope, input.message, context.microstructure, decisionContext.microstructureEvidence)`. This is a two-line reorder plus one new argument; no new class was introduced at this layer.

## 4. Evidence explanation format

`formatMicrostructureEvidenceExplanation(assessment)` returns `string[]`:

```
Microstructure Evidence Relationship:
Hypothesis direction: bullish        (omitted when hypothesisDirection is "neutral"/absent)
Relationship: CONFIRMS

Evidence:
- <assessment.basis[0]>              (D2.8.11's own text, verbatim)
- <assessment.basis[1]>

Current binance microstructure confirms the bullish hypothesis.

Source: binance
Instrument: BTCUSD
Freshness: fresh
Scope: binance venue evidence - not global market liquidity.
```

The Source/Instrument/Freshness/Scope block is only emitted when `assessment.provider` is present (i.e., a real snapshot was actually evaluated) — never fabricated for a `missing-provider` case (test 7).

## 5. CONFIRMS/CONTRADICTS/NEUTRAL/INSUFFICIENT behavior

- **CONFIRMS**: `"Current {provider} microstructure confirms the {direction} hypothesis."`
- **CONTRADICTS**: `"Current {provider} order-flow pressure opposes the hypothesis - microstructure does not support the current {direction} hypothesis."` — explicitly never reuses CONFIRMS wording.
- **NEUTRAL**: `"Microstructure evidence is currently balanced - it neither confirms nor contradicts the {direction} hypothesis."`
- **INSUFFICIENT_EVIDENCE**: `"Microstructure evidence is insufficient to influence the current hypothesis. No directional confirmation is assigned."` — a dedicated sentence, never the NEUTRAL sentence, never containing "balanced." Verified never to collapse into each other by tests 3/4/14/15.

## 6. Provider attribution

Every explanation with a real assessment states Source (provider), Instrument, Freshness, and an explicit Scope disclaimer ("`{provider}` venue evidence - not global market liquidity"). When no snapshot was ever evaluated (`provider` undefined), no Source/Scope line is printed at all — never a placeholder "Source: unknown" (test 7).

## 7. Chat integration

`IntelligencePresentationService.present()` → `DecisionContextService.build(envelope, microstructure)` (computes `microstructureEvidence`) → `AIPresenterOrchestratorService.present(envelope, question, microstructure, microstructureEvidence)` → `buildPresenterQuestionWithMicrostructure()` appends the formatted explanation to the prompt every candidate presenter (Gemini/Claude/OpenAI/deterministic fallback) receives. Verified end-to-end (not just unit-tested) via `RecordingPresenter` fixtures that assert the exact D2.8.11 basis text and `Relationship: CONFIRMS`/`CONTRADICTS` lines appear in the presenter's received prompt.

## 8. Chart integration

`app/api/private/market-data/microstructure/route.ts` accepts an optional `hypothesisType` query param and, when present, computes and returns a real assessment via the unmodified `assessMicrostructureEvidence()`. `useMicrostructureSnapshot()` and `MicrostructurePanel.tsx` were extended to accept/forward it and render a "Microstructure Evidence Relationship" block (Hypothesis/Relationship/basis or contradicts/insufficient sentence/Source+Scope) when supplied. **Known limitation**: no production caller currently passes `hypothesisType` — `NativeChart.tsx` has no access to the current hypothesis without running the full intelligence pipeline, which the brief's own Phase 8 wording ("add only if it fits cleanly") argues against forcing. The plumbing is built, tested, and byte-identical-when-omitted; wiring a real caller is deferred to a future sprint that has a natural hypothesis source (e.g. the Workspace intelligence panel).

## 9. Response-integrity behavior

`MICROSTRUCTURE_OVERCLAIM_PATTERNS` (new `"microstructure-overclaim"` violation kind) rejects: guaranteed directional/execution outcomes ("guarantees BUY", "guarantees the price will rise"), "proves...direction/candle/next move" language, and "confirms/shows/indicates global liquidity" in both word orders. A genuinely honest CONFIRMS/CONTRADICTS/INSUFFICIENT_EVIDENCE explanation (as produced by `formatMicrostructureEvidenceExplanation`) passes cleanly — verified directly against `validateResponseIntegrity()`.

## 10. Real Binance runtime evidence

Live calls against the production shared instances (`binanceMicrostructureProvider`/`microstructureSnapshots`) at report time:
- **BTCUSD**: vs bullish hypothesis → `confirms` (moderate); vs bearish hypothesis → `contradicts` (moderate) — same real reading, opposite comparison, opposite relationship, proving the assessment is genuinely evidence-driven, not fixed.
- **ETHUSD**: vs bullish hypothesis → `confirms` (strong); vs bearish hypothesis → `contradicts` (strong).

Both real assessments were formatted via `formatMicrostructureEvidenceExplanation()` and confirmed to reach a candidate presenter's prompt end-to-end.
