# D2.7.5 — AT24 Native Chart: Professional Trader Workspace UX

**Status:** Implemented and tested.
**Scope:** A UX/interaction sprint, not a data/feature sprint. Transforms the D2.7.2–D2.7.4 native chart engine (already verified production-correct) into a professional trader workspace: a real chart header, a grouped indicator menu, session-level state persistence, and a fullscreen focus mode — built entirely on top of the existing architecture, with zero new provider/timeframe/instrument/indicator-math/symbol systems.

---

## 1. Architecture audit

Phase 1 re-read `app/dashboard/workspace/page.tsx`, `ChartPanel`, `NativeChart`, `ChartToolbar`, `ChartProviderToggle`, `ChartTimeframeSelector`, `useChartCandles`, `renderer.ts`, `viewport.ts`, `crosshair.ts`, `panel-layout.ts`, the indicator registry/compute layer, `WorkspaceContext`, `MarketRibbon`, `WorkspaceHeader`, `chart-instrument-resolver.ts`, the financial typography/format layer, the candles route, `candle-index.ts`, and the design tokens in `app/globals.css`, plus the D2.7.1–D2.7.4 specs. No working architecture was refactored for style. Five real, previously-missing UX gaps were found and addressed (§2):

1. No single place communicated symbol + timeframe + price + change + freshness + provenance together — that information was scattered (a small symbol chip in the toolbar, a separate provenance line below the chart, nothing showing a price/change at all).
2. The Indicators menu was a flat checkbox list with no overlay-vs-sub-panel distinction, even though the underlying data (`IndicatorSeries.panel`) already carries that distinction.
3. No fullscreen/focus mode existed.
4. Chart provider/timeframe/indicator selections (owned by `ChartPanel` since D2.7.4) were lost on a page reload — they lived only in React state, with no persistence at all, not even session-scoped.
5. An instrument whose provider genuinely reports no volume rendered a silently empty Volume sub-panel — technically honest (no fabricated bars) but not informative.

## 2. UX gaps discovered (see §1) and how each was closed

- **Chart header** (`ChartHeader.tsx`, new) — symbol, instrument name, timeframe, price, a real range change, freshness, and provenance, all read from props `NativeChart` already has (`WorkspaceContext.name`, the `timeframe` prop, the already-fetched `ChartSeries`). Zero new fetching.
- **Indicator grouping** — `INDICATOR_PANEL_ID` (new, `panel-registry.ts`) is a static id→panel lookup mirroring `compute.ts`'s real per-id panel assignment; the toolbar's Indicators menu now renders two labeled sections, "Overlays" and "Panels", both still `.filter()`-derived from `DEFAULT_INDICATOR_CONFIGS` — never a hardcoded list. A regression test computes a real series for every default indicator and asserts the static table never drifts from `compute.ts`'s actual assignment.
- **Fullscreen** — a CSS-driven focus mode (`fixed inset-0 z-50`, matching the exact z-index convention `Modal.tsx`/`MobileNav.tsx` already use), not the browser Fullscreen API (avoided deliberately — it needs a user gesture in some browsers and can be blocked in an embedded preview). Toggling it re-triggers the *existing* `ResizeObserver` (no new resize/DPR code), so devicePixelRatio-correct redraw already works. Escape exits via a `window` keydown listener scoped only to while fullscreen is active.
- **Session state persistence** — `chart-session-state.ts` (new): `sessionStorage`-backed, validated read/write for provider/timeframe/indicator keys. `ChartPanel` restores it once via a post-mount effect (never a `useState` initializer, to avoid an SSR/client hydration mismatch) and persists on every change thereafter, guarded by a `hydratedRef` so the still-default initial state never overwrites a real saved value before the restore effect runs.
- **Honest empty-volume state** — `sub-panel-renderer.ts`'s `drawVolumePanel` now draws "No volume data for this instrument" centered in the panel when candles exist but none carry a `volume` field — never a fabricated bar, never silence.

## 3. Bugs discovered

None — this sprint's own architecture audit found UX gaps (§2), not functional defects, in the D2.7.2–D2.7.4 pipeline. The chart data flow, provider fallback, viewport model, crosshair, and polling lifecycle were re-verified unchanged and correct (§9–§13).

## 4. Bugs fixed

None (see §3). One pre-existing test in `validate-native-chart-production.ts` (test #76) asserted a literal `DEFAULT_INDICATOR_CONFIGS.map` substring in `ChartToolbar.tsx`; the Phase 4 grouping refactor legitimately restructured that single `.map` into two filtered derivations (`OVERLAY_CONFIGS`/`PANEL_CONFIGS`), so the assertion was updated to check for `DEFAULT_INDICATOR_CONFIGS.filter` (still present twice) — the invariant it guards (never a hardcoded duplicate indicator list) is unchanged and still verified.

## 5. Chart header

Renders: canonical symbol + instrument name, an active-timeframe badge (reusing `ChartTimeframeSelector`'s own exported `TIMEFRAME_LABELS`, never a second label map), the latest close (`FIN_PRIMARY`), a **range change** — explicitly labeled `(range)`, computed by the new pure `computeRangeChange()` helper as `(last candle's close − first candle's open) / first candle's open` across the currently loaded candle range. This is deliberately *not* labeled "today" or "24h": the series carries no session/day boundary, so any other label would claim a figure the data doesn't support. It is also a distinct figure from `WorkspaceHeader`'s own snapshot-based session change elsewhere on the page — never a duplicate. Freshness renders as a compact Live/Stale/Unknown tag; provenance (provider, fallback, cache age) renders as tertiary text. Every field renders an honest "—" or is omitted when its source data is genuinely absent.

## 6. Timeframe UX

Unchanged data model (`SignalTimeframe`/`SIGNAL_TIMEFRAMES`) — `ChartTimeframeSelector`'s label map was exported (`TIMEFRAME_LABELS`) so `ChartHeader` can reuse it instead of hand-duplicating. Every timeframe button is a real `<button aria-pressed>`, keyboard-accessible via native Tab/Enter with no extra scripting needed. Timeframe switching continues to: refetch via the existing `[symbol, timeframe, outputSize]`-keyed effect, cancel the previous in-flight request (`AbortController` + `cancelled` flag), re-fit the viewport via `fittedKeyRef`'s `symbol|timeframe` key (D2.7.4's own fix, unmodified), and recompute indicator series (which depend on `candles`, not on `timeframe` directly — so a timeframe change's *new* candles naturally drive a recompute without any extra wiring). Indicator *selection* is untouched by a timeframe change — it's a `ChartPanel`-owned prop, structurally independent of the candles-fetch effect.

## 7. Indicator management

`INDICATOR_PANEL_ID` groups the existing seven `DEFAULT_INDICATOR_CONFIGS` into "Overlays" (EMA-20/50, SMA-20, Bollinger-20) and "Panels" (RSI-14, MACD, Volume) — a real, previously-missing distinction, verified against `compute.ts`'s actual output so the two can never silently diverge. Toggle state remains owned by `ChartPanel` (D2.7.4's fix), unaffected by a provider or timeframe switch. Unknown indicator keys are still rejected at the toggle boundary. No indicator math changed (`lib/market-data/indicators.ts` and `compute.ts` are byte-for-byte untouched this sprint).

## 8. Chart controls

The toolbar now groups controls into two logical clusters (symbol/timeframe on the left; indicators/Fit/Live/Fullscreen on the right), each independently `flex-wrap`. The Indicators dropdown now dismisses on Escape and on an outside click (previously only its own toggle button could close it). A Fullscreen toggle was added, wrapped in the existing `Tooltip` component. No separate "Reset View" control was added: in this single-viewport architecture, "reset" and "fit to data" are the same real operation — inventing a second, identical-behavior button would be UI noise, not a feature, so `Fit` alone covers it (documented here rather than silently omitted). A persistent crosshair-freeze toggle was considered and deliberately not built: the existing hover-follows-mouse crosshair already matches the professional-charting-platform convention this sprint targets, and a toggle to disable it would reduce, not add, utility.

## 9. Latest-price experience

Unchanged from D2.7.4 (`drawLatestPriceMarker` — a dashed gold line + real price label at the last candle's close). Re-verified this sprint: still throws on nothing, still skips cleanly when panned off-panel, and still renders correctly alongside the new empty-volume-panel notice in the same pipeline.

## 10. Crosshair UX

Unchanged: still binary-search snapping (`nearestIndexByTime`), still reads already-computed indicator values via `valueAtIndex` (never recomputes a series on `mousemove`), still throttled to one `setState` per animation frame. Re-verified this sprint via source inspection and a fresh binary-search-equivalence test.

## 11. Chart state persistence

`sessionStorage`-scoped (per-tab, cleared when the tab closes) — deliberately *not* `localStorage` and *not* a new database table. This distinguishes it from `WorkspacePreferences` (D2.3-P7), which already durably persists the active symbol/profile/favorites across sessions and devices — chart provider/timeframe/indicator selection is a smaller-scoped, same-tab convenience, not a durable account preference. Every read is re-validated against the real `SignalTimeframe`/`DEFAULT_INDICATOR_CONFIGS`/`ChartProviderKind` registries; a corrupted or hand-edited value is silently dropped, never applied. Fullscreen state and viewport position are deliberately **not** persisted: fullscreen auto-resuming on reload would be jarring, and a saved time range can be unsafe to reapply (especially for intraday timeframes) — the chart's existing "always re-fit on a real symbol/timeframe change" behavior is preserved as-is.

## 12. Fullscreen mode

CSS-only focus mode scoped to `NativeChart`'s own returned tree (`AdvancedChart`/TradingView is untouched and cannot be swallowed by it). `fixed inset-0 z-50` matches the exact top-most-overlay convention this codebase's `Modal.tsx`/`MobileNav.tsx` already use. Escape exits via a listener attached only while fullscreen is active, and never calls `preventDefault`/`stopPropagation` — no keyboard trap. The canvas is never remounted (no `key` churn) across the transition, so viewport/crosshair state survives it. The container's height becomes flexible (`flex-1 min-h-0`) instead of the fixed `BASE_PANEL_HEIGHT` used otherwise, and the *existing* `ResizeObserver` (not a new one) picks up the resulting layout change automatically.

## 13. Responsive behavior

`ChartHeader` and `ChartToolbar` both wrap (`flex-wrap`) on narrow viewports. The Indicators dropdown has a bounded width (`w-56`) so it cannot itself cause horizontal overflow. No new fixed-width element wider than the existing dropdown/menu convention was introduced. The crosshair readout row's existing `flex-wrap` behavior is unaffected. Desktop/tablet/mobile behavior otherwise matches D2.7.2/D2.7.3's already-verified responsive baseline — this sprint only touched the header/toolbar/fullscreen surfaces, not the core canvas responsiveness.

## 14. Loading / error / empty / stale / unsupported states

All five states from D2.7.2/D2.7.3 (`loading`, `unsupported`, `error`, `empty`, `stale`) are unchanged and re-verified present. The rejected-candle-count and provenance disclosures are unaffected. The new empty-volume-panel notice is a distinct, additional honest state (§2), not a replacement for any existing one.

## 15. Symbol switching

Unaffected by this sprint's changes; re-verified via source inspection: `useChartCandles`'s effect still depends on `[symbol, timeframe, outputSize]`, still cancels the prior in-flight request, and `NativeChart`'s `resolution`/`fittedKeyRef` are still derived fresh from the current `symbol` on every render — a repeated `NIFTY50 → BANKNIFTY → RELIANCE → BTCUSD → XAUUSD → EURUSD → NIFTY50` sequence cannot leave a stale chart, a wrong-instrument fit, or provider contamination, matching D2.7.4's own proof.

## 16. Timeframe switching

Unaffected; re-verified. `candleStepMs` is still derived from the real fetched candle spacing, never a hardcoded per-timeframe constant, so an `M1 → M5 → M15 → H1 → H4 → D1` sequence always redraws with correct spacing/axes/indicators and no stale request can overwrite a newer one (same `AbortController`/`cancelled` guard as symbol switching).

## 17. Native ↔ TradingView coexistence

Unaffected by this sprint's core switching logic; extended only in that the provider selection itself is now also session-persisted (restored the same way as timeframe/indicators). `AdvancedChart.tsx` remains completely untouched. Fullscreen and the new header are scoped to `NativeChart`'s own tree and never affect TradingView's rendering. `services/market-data/shared-instance.ts` (provider routing) is untouched.

## 18. Indian-market verification

NIFTY50/BANKNIFTY/RELIANCE/TCS/INFY/HDFCBANK re-verified: still map exclusively to `angel-one` in the catalog (never Binance/Twelve Data), and still resolve to real `NSE:`-prefixed TradingView chart symbols via the unmodified `chart-instrument-resolver.ts`.

## 19. Accessibility

The Indicators menu button has `aria-expanded`/`aria-haspopup`; the menu itself has `role="menu"` and an `aria-label`; it now closes on Escape (new) and on an outside click (new). The Fullscreen toggle exposes both a visible `Tooltip` and an `aria-label`, reusing the existing `Tooltip` component rather than inventing a second one. The timeframe/provider toggles' existing `aria-pressed` pattern is unaffected. The canvas's existing keyboard navigation (arrows/+/-/Home/End, `tabIndex=0`) is unaffected. The one new global listener (fullscreen's Escape handler) never calls `preventDefault`/`stopPropagation`, so it introduces no keyboard trap.

## 20. Performance

Full pipeline (normalize → indicators → render, including the new empty-volume-panel notice code path) re-benchmarked within budget at 500/2,000/5,000 candles. `INDICATOR_PANEL_ID` and the toolbar's `OVERLAY_CONFIGS`/`PANEL_CONFIGS` are computed once at module scope, not per render. The fullscreen Escape listener is attached/removed only on `isFullscreen` transitions. No `setState` is called directly from the pan/zoom/crosshair mouse handlers (unaffected by this sprint).

## 21. Security

No new secret-shaped values in any new file. Session storage carries only `provider`/`timeframe`/`indicatorKeys` — no PII, no credentials, no per-user identifier. The candles route's auth/validation posture (`route.ts`) is untouched.

## 22. Known limitations

- No independent vertical pan/zoom (unchanged design decision since D2.7.2).
- No live, authenticated Angel One or interactive browser verification was performed — the standing credential-refusal constraint continues to apply (see §23).
- The browser's native Fullscreen API is deliberately not used (see §12) — the CSS-driven focus mode is functionally equivalent for this sprint's purposes but does not exit the OS-level browser chrome the way a true Fullscreen API call would.
- A persistent/freezable crosshair mode was considered and deliberately not built (§8).
- Multi-symbol compare remains a types-only extension point (D2.7.3), untouched this sprint.

## 23. Browser verification limitations

Automated (`curl`) and unauthenticated-browser verification only — the candles route still returns 401 unauthenticated, `/dashboard/workspace` still 307-redirects, and the redirect target loads with zero app-level console errors. Live, authenticated interactive verification of the new header/fullscreen/indicator-grouping UI itself was not performed in this environment; the standing constraint against entering the user's password into a login field continues to apply.

## 24. Extension points

- `computeRangeChange` and `ChartHeader` are generic enough to extend with a second, session-boundary-aware change figure if a real intraday-open reference becomes available later — not attempted this sprint (would require a new data field, out of scope).
- `INDICATOR_PANEL_ID` is the natural place a future indicator registers its overlay/sub-panel classification for menu grouping, alongside its existing `panel-registry.ts`/`compute.ts` registration.
- `chart-session-state.ts`'s validated read/write pattern generalizes to any other same-tab-only chart UI preference a future sprint might add (e.g. a saved sub-panel order), without needing a new persistence mechanism.
