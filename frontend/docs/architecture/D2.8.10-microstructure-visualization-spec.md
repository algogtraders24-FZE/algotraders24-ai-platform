# D2.8.10 — Microstructure Visualization & Intelligence Evidence Layer

**Status:** Implemented and tested. **Baseline:** D2.8.9 (`5aca723`).
**Scope:** The first production visual layer for real, verified microstructure evidence (D2.8.5-D2.8.9) inside AT24's native chart engine — no new data pipeline, no new calculation, no new provider abstraction.

---

## 1. Production entry point

**Repository audit findings (Phase 1):**

- Native chart engine lives under `lib/chart-engine/**` (pure rendering/math) and `components/chart-engine/**` (React orchestration: `NativeChart.tsx`, `ChartHeader.tsx`, `ChartToolbar.tsx`, `ChartPanel.tsx`).
- `ChartPanel.tsx` (D2.7.2) toggles between `NativeChart` (AT24's own engine) and `AdvancedChart` (TradingView) — the latter was **not touched** (Rule 6).
- `ChartHeader.tsx` (D2.7.5) is the exact, established precedent for this sprint's own discipline: "a pure presentation layer over data the caller already loaded... every value is real, no field renders a fabricated value when genuinely absent — it renders an honest fallback instead."
- No existing component or route exposed a `MicrostructureSnapshot` to the browser — D2.8.6 through D2.8.9 all deliberately kept this server-side only. A thin, read-only bridge was therefore genuinely required to make browser visualization possible at all — the same kind of boundary `app/api/private/market-data/snapshot/route.ts` already provides for OHLC/quote data.

**Integration point:** `MicrostructurePanel.tsx`, rendered inside `NativeChart.tsx` directly below `ChartHeader`, visible only when the native engine is active (never touching the TradingView path).

## 2. Activation decision

Three new files bridge the existing server-side D2.8.5–D2.8.9 layer to the browser, all additive:

1. `app/api/private/market-data/microstructure/route.ts` — thin, read-only, auth-gated GET endpoint mirroring `snapshot/route.ts`'s exact pattern. Consumes D2.8.6's real `binanceMicrostructureProvider`/`microstructureSnapshots` shared instances directly — **zero calculation, validation, or provider logic reimplemented**.
2. `components/chart-engine/useMicrostructureSnapshot.ts` — client fetch hook mirroring `useChartCandles.ts`'s own AbortController/cleanup pattern, with one deliberate difference: **no background polling** (see §8).
3. `components/chart-engine/MicrostructurePanel.tsx` — pure presentation component, plus `lib/microstructure/microstructure-panel-format.ts` (the one pure formatting function it uses, split out for independent testability, matching `lib/financial-format.ts`'s own established split from `ChartHeader.tsx`).

## 3. Capability gating

The route re-derives the exact same check `RealTimeIntelligenceService.fetchMicrostructure()` (D2.8.7/D2.8.9) already uses — `getCanonicalInstrument(symbol)?.providerMappings.some(m => m.provider === "binance" && m.supportedCapabilities.includes("quote"))` — reusing the real, single canonical instrument catalog. No second registry was created.

## 4. Supported instruments

**BTCUSD, ETHUSD** — real, verified Binance provider mappings.

## 5. Unsupported instruments

**XAUUSD, XAGUSD, EURUSD, GBPUSD, NIFTY, BANKNIFTY** — the route returns `{ supported: false }` immediately, before any Binance call, confirmed by zero-provider-call assertions in the new test suite. The panel renders the brief's own specified text: *"Provider: Not available · Order Book: Not supported for this instrument · Volume Delta: Not available."*

## 6. Evidence attribution behavior

`MicrostructurePanel` always states, in order: provider label (`"Binance Order-Book Evidence"` for Binance, `"{provider} Venue Microstructure"` generically for any future provider), instrument symbol, freshness state, an "Updated {time}" stamp, and an explicit `"Source: {provider} · Data: Live REST snapshot · Venue-specific evidence, not global market liquidity"` line — never `"Global Liquidity"`, `"Global Order Flow"`, or `"Global Market Depth"`.

## 7. unavailable/stale/invalid behavior

`formatMicrostructureFieldForUI()` (`lib/microstructure/microstructure-panel-format.ts`) is the one function every field in the panel renders through:

- **available** → the real value.
- **stale** (per-field) → the real value with a `"(stale)"` suffix — though in practice D2.8.5's `buildMicrostructureSnapshot()` never assigns this to an individual field; staleness in this system is snapshot-level (`snapshot.freshnessStatus`), which the panel's header renders as an explicit `"Stale"` badge instead. The per-field branch is kept as correct, forward-compatible handling of the real `CapabilityState` type contract, not dead/speculative code.
- **unavailable** → the literal text `"Unavailable"`, never `0`.
- **not_supported_by_provider** → `"Not supported for this instrument"`.
- **invalid** → `"Invalid"` — the numeric value is never rendered, confirmed by a test asserting the raw invalid number never appears in the output string.

## 8. Failure isolation

- The route wraps the Binance fetch with D2.8.9's own `withReliability(..., { retries: 0 })` — the same 8-second-budget primitive, reused unmodified.
- A provider timeout, HTTP failure, or malformed/invalid response all degrade to the standardized `MarketDataErrorDTO` (`lib/market-data/error-dto.ts`, reused verbatim) — never an uncaught exception, never a 500 that could break the surrounding chart's own render.
- The client hook treats any non-OK response as `"error"` status and renders a small, self-contained message — it never throws, never blocks `NativeChart`'s own canvas rendering, which has no dependency on this panel at all.
- **No background polling** was added (deliberately, per Phase 8's explicit "no uncontrolled polling, no duplicate provider requests" rule): unlike `useChartCandles` (whose 20s poll is absorbed by the candles route's own server-side TtlCache), microstructure is **not cached server-side** (D2.8.5's own deliberate "read close to real-time" design) — polling it client-side would directly multiply real Binance calls with nothing absorbing them. One fetch per symbol change is the honest, non-abusive default.

## 10. Fabrication audit

Fresh repository-wide search for `liquidityZones`, `volumeDelta`, `orderBook`, `depth`, `buyVolume`, `sellVolume`, `spread`, `liquidity` found the same file set already reviewed in D2.8.7–D2.8.9 — no new fabrication. `MicrostructurePanel.tsx`'s own use of "liquidity"-adjacent terms is exclusively in the explicit venue-scope disclaimer ("not global market liquidity"), confirmed by a dedicated test. No synthetic liquidity zones, no delta computed without aggressor evidence (the panel only ever displays `snapshot.derived.volumeDelta`, D2.8.5's own unmodified calculation), no Binance substitution for another instrument, no unavailable→zero conversion, and no stale→fresh relabeling exist anywhere in the new code.

## 13. Known limitations

- **Authenticated in-browser visual rendering was not verified** — no test credentials were available in this session, and the Browser pane could not composite screenshots. What *was* verified: TypeScript compiles cleanly, the dev server compiles the new files with zero errors, the new API route is live and correctly auth-gated (real `401` confirmed via `curl`), and all underlying logic (capability gating, formatting, failure handling) is proven by 32 passing tests including 2 live Binance calls through the exact production code path. A future session with real credentials should complete a visual pass.
- The per-field `"stale"` `CapabilityState` branch in `formatMicrostructureFieldForUI()` is untriggered by the current `buildMicrostructureSnapshot()` implementation (staleness is snapshot-level only) — kept as correct, forward-compatible handling of the type contract rather than removed, since a future provider path could legitimately produce it.
- No background polling means the panel shows the microstructure snapshot as of the last symbol change/page load, not a continuously live tick — a deliberate trade-off against uncontrolled Binance load, not an oversight.
- The panel currently renders only inside the native chart engine; it is not present in the TradingView view or the Workspace Research panel (mirroring D2.8.9's own decision not to activate microstructure on that read-only, no-consumer path).

## 14. Future WebSocket boundary

No WebSocket was added anywhere in this sprint. The visualization layer is still exactly D2.8.6's REST-only path, now additionally reachable from the browser via one thin, timeout-bounded route. A future push-based visualization (live-ticking bid/ask without polling) would need its own explicitly-scoped sprint; nothing here assumes or blocks that.
