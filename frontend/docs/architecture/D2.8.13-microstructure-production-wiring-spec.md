# D2.8.13 — Microstructure Evidence Production Wiring & Decision UI

## 1. Implementation summary

D2.8.12 wired D2.8.11's `MicrostructureEvidenceAssessment` into the chat presenter's prompt via `IntelligencePresentationService`. Tracing every real production caller of `DecisionContextService` found a SECOND gap: `ResearchSnapshotService` — which powers the Workspace Research panel (`GET /api/private/intelligence/research`, `WorkspaceResearch.tsx`) — never opted into microstructure at all (`includeMicrostructure` was never passed, and `decisionContextService.build()` was called with only 1 argument). This sprint closes that gap, exposes `microstructureEvidence` on the stable `VerifiedAnswerResponse` contract both callers share, adds a deterministic UI section that renders it in both the chat "Why this answer?" card and the Research panel, and wires the native chart's `MicrostructurePanel` to a real hypothesis direction instead of leaving the D2.8.12 plumbing unconnected. No new microstructure engine, no D2.8.11 formula/threshold change, no Intelligence Score change, no BUY/SELL signal.

## 2. Exact production path

```
Real Binance microstructure
  -> D2.8.5 MicrostructureSnapshotService (calculation/validation)
  -> D2.8.7 RealTimeIntelligenceService.fetchMicrostructure() (intelligence context)
  -> D2.8.11 assessMicrostructureEvidence() inside DecisionContextService.build()
  -> D2.8.12 formatMicrostructureEvidenceExplanation() (chat prompt)
  -> D2.8.13 VerifiedAnswerResponse.microstructureEvidence (structured passthrough)
  -> CHAT ("Why this answer?" card) + WORKSPACE RESEARCH PANEL + NATIVE CHART (MicrostructurePanel)
```

Two real production callers now reach this path: `IntelligencePresentationService.present()` (chat route, wired in D2.8.12/confirmed here) and `ResearchSnapshotService.build()` (Research panel, newly wired in D2.8.13).

## 11. Known limitations

- The Research panel's `hypothesisType` sharing depends on `WorkspaceResearch` resolving before/around the same time the chart renders; until it resolves, the chart's microstructure evidence relationship is simply absent (never fabricated) — matching every other honest-loading-state convention in this codebase.
- `DeterministicSafeFallbackPresenter` (used only when every real LLM provider fails/rejects) still ignores the enriched prompt entirely and never mentions microstructure evidence in its restated-facts text; the evidence is still available structurally via `verifiedAnswer.microstructureEvidence` regardless of which presenter produced `answer`.
- ETHUSD's real evidence happened to read neutral in both directions during this report's live run — an honest reflection of real market conditions at capture time, not a code limitation.
