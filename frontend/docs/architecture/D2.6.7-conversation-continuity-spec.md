# D2.6.7 — Conversation Continuity & Verified Market Context Memory

**Status:** Implemented and tested. Closes D2.6.5's own documented limitation: `conversationContext` was accepted by the intelligence layer but never populated from persisted state.
**Scope:** Persist a small, structured, per-conversation context; load it before resolving a chat turn; save it after a resolved one. No rebuild of any existing engine.

**Non-negotiable principle** (repeat before touching any file here): conversation memory is CONTEXT, never CURRENT MARKET FACT. Every field this sprint persists is a pointer (a symbol, a timeframe, an analysis-run id, a hypothesis id) or a past classification — never a price, indicator value, or anything a fresh `MarketDataService` request could answer differently right now.

---

## 1. Existing conversation architecture (audit summary)

`Conversation`/`Message` (Prisma) already existed with no context/metadata field at all — confirmed by reading the schema directly before writing any code. `ConversationMessageService` persists append-only turns; `assertOwnedConversation`/`AnalysisHistoryService` already established the "ownership scoped in the same query, cross-user access is indistinguishable from not-found" idiom this sprint reuses verbatim.

The single most important finding: **`IntelligenceQueryService.resolveSymbol()`/`resolveTimeframe()` (D2.6.2) already implement the exact 4-tier priority order** this sprint's brief asks for — explicit-query → request-context → `conversationContext.activeSymbol`/`activeTimeframe` → unresolved — and `IntelligenceQueryContextService` already correctly consumes `conversationContext.previousAnalysisRunId` to look up a referenced prior run. None of that was rebuilt. The only real gap was that `conversationContext` was never populated from anything durable.

## 2. Context contract

`PersistedConversationContext` (`types/conversation-context.ts`) — one row per conversation (`Conversation.intelligenceContext`, additive nullable `JSONB`), always reflecting the **most recent** resolved turn, never a transcript or history array:

```ts
interface PersistedConversationContext {
  contextVersion: string;
  conversationId: string;
  userId: string;
  activeSymbol?: MarketSymbol;
  activeTimeframe?: SignalTimeframe;
  activeExchange?: string;
  activeMarket?: MarketCategory;
  lastAnalysisRunId?: string;
  lastQueryType?: IntelligenceQueryType;
  lastHypothesisIds?: string[];
  lastRegimeType?: RegimeType;
  updatedAt: string;
}
```

This is a richer, persisted **superset** of the already-existing `ConversationIntelligenceContext` (D2.6.2, `{activeSymbol?, activeTimeframe?, previousAnalysisRunId?, previousHypothesisId?}`), not a competing concept — `toConversationIntelligenceContext()` is a pure projection function that narrows the persisted shape down to exactly what `RealTimeIntelligenceService`/`IntelligenceQueryContextService` already consume. `contextVersion` lets a future schema change identify an old persisted shape; `ConversationContextService.getContext()` honestly discards (returns `null` for) a mismatched version rather than risk misreading it.

## 3. Context resolution

Unchanged — this sprint supplies the missing *input*, not new resolution logic. `RealTimeIntelligenceService.build()` already calls `IntelligenceQueryService.parse()` with whatever `conversationContext` it's given; once that's real, persisted data instead of always `undefined`, the existing priority chain does the rest. Verified directly (`scripts/validate-conversation-continuity.ts`'s "Resolution" section): explicit symbol/timeframe in the current message always overrides persisted context; persisted context is inherited only when the current message has neither; an ambiguous message (two real symbols mentioned) is never resolved by falling back to persisted context — ambiguity within the current message always wins over inheritance.

## 4. Follow-up resolution

No new pronoun-parsing logic was built, and none was needed — deterministic reference resolution for "it"/"this"/"that"/"same setup"/"previous analysis"/"this hypothesis" falls out of the existing D2.6.2 priority chain: a follow-up message mentioning none of these has no explicit symbol token, so `resolveSymbol()` already inherits `conversationContext.activeSymbol`. Verified for all eight follow-up phrasings the sprint's own examples give. `IntelligenceQueryService.parse()`'s existing keyword classifier (unmodified) already correctly tags "what could invalidate this?" as `queryType: "hypothesis"` with `invalidation` in `requestedScopes` — this sprint adds zero new classification rules.

## 5. Authorization

Every `ConversationContextService` operation is ownership-scoped in the same query — `prisma.conversation.findFirst({where: {id, userId, deletedAt: null}})` for reads, `updateMany({where: {id, userId, deletedAt: null}, ...})` for writes — identical idiom to `assertOwnedConversation`. A read by a non-owning user returns `null`, never a thrown error that could distinguish "exists but not yours" from "doesn't exist." A write attempt by a non-owning user is a scoped no-op (zero rows match the `WHERE`) — verified directly: a stranger's `saveContext()` call never overwrites the real owner's context. `IntelligenceChatContextService.resolve()` never receives another user's context: it always loads via the caller's own session-derived `userId` alongside the `conversationId`.

## 6. Analysis-run linking

`IntelligenceChatContextService.resolve()` is the one place this now happens: after a `"resolved"` turn, it derives the next context from that turn's own real `analysisRunId` and the real `Hypothesis.id`s on its envelope, and saves it — best-effort, never breaking the response the trader already has if the save fails. A later "that analysis"/"the previous analysis" question can then reach the persisted `lastAnalysisRunId`, which the already-existing `IntelligenceQueryContextService` resolves into a full `previousAnalysis` (run + outcomes) via `AnalysisHistoryService`, unmodified.

## 7. Hypothesis references

`lastHypothesisIds` persists the real hypothesis id(s) from the most recent envelope — almost always 0 or 1 entries, matching D2.5.3's hypothesis engine's own "at most one hypothesis per regime" behavior, so "this hypothesis" is rarely genuinely ambiguous in practice. Critically, **the answer to "what would invalidate it" is never a replay of the old hypothesis's stored invalidation condition** — the persisted id only identifies *which* hypothesis is being discussed; `RealTimeIntelligenceService` always recomputes a fresh `MarketState → Regime → Hypothesis` chain against a live provider request for the inherited symbol, so the actual answer reflects current market data, per the sprint's own explicit instruction not to "simply repeat the old hypothesis status."

## 8. Freshness boundary

Structurally guaranteed by construction, not by a new check: `RealTimeIntelligenceService.build()` always calls `MarketDataService.getSnapshot()`/`.getTimeSeries()` fresh on every single call, regardless of what `conversationContext` supplies — nothing in the persisted context type has a price/indicator field for a shortcut to even read from. Verified directly with a stateful fake provider that returns a different real price on each call: a context-inherited follow-up's price always matches the *second* fetch, never the first turn's cached value, and a provider failure on a follow-up honestly returns `insufficient-data` rather than silently reusing the last known snapshot.

## 9. Context replacement (never time-based expiration)

Per the sprint's own stated preference, replacement is explicit and intent-based, not time-based. `deriveNextContext()` is a pure function that always builds a **complete, fresh** context object from the current turn's own real values — it never merges the new turn onto the previous one. This makes the replacement rule hold *by construction*: when the resolved symbol changes (e.g. NIFTY50 → BANKNIFTY), the new context's `lastAnalysisRunId`/`lastHypothesisIds`/`lastRegimeType` are automatically the new symbol's own real values, never the old symbol's carried-forward pointers — there is no separate "clear stale fields" step to remember or forget. Verified end-to-end: a real NIFTY50 turn followed by a real BANKNIFTY turn on the same conversation persists only BANKNIFTY's own analysis-run id, and a third, symbol-less follow-up after that correctly inherits BANKNIFTY, never NIFTY50.

## 10. Context versioning

`CONTEXT_VERSION = "1.0.0"` is written into every persisted context and checked on every read. A future incompatible schema change bumps this constant; `getContext()` already discards a mismatch rather than attempting to interpret an old shape as if it were the new one — no migration/backfill logic needed for that case, since the honest fallback (no persisted context) is always safe.

## 11. Bounded context

The intelligence layer never receives conversation history or a transcript — only the same narrow `ConversationIntelligenceContext` shape (4 optional pointer fields) it already accepted before this sprint. `IntelligenceQueryContextService`'s own existing scope-selection logic (D2.6.2) is what decides which parts of the resulting envelope actually reach the presenter; this sprint adds no new data to that surface.

## 12. AI/LLM boundary

Unchanged and re-confirmed: symbol/timeframe/hypothesis-reference resolution is 100% deterministic application logic (D2.6.2's existing priority chain + this sprint's persistence). Gemini (or any future presenter) never determines what the conversation was about — it only ever receives an already-resolved `IntelligenceEnvelope` to paraphrase, exactly as D2.6.5 established. `GeminiIntelligencePresenter`/`DeterministicSafeFallbackPresenter`/`AIResponseIntegrityService` are all unmodified.

## 13. Security

No secret value is ever touched by this sprint. `userId` is always session-derived by the caller (`ConversationContextService` never accepts a client-supplied ownership claim). Verified directly: a different real user cannot read another user's persisted context; a forged/nonexistent conversation id returns `null`, never an error that could leak whether it exists; an empty `userId` never matches a real row.

## 14. Failure states

- No persisted context yet (first message in a conversation) → `conversationContext: undefined`, identical to D2.6.5's pre-this-sprint default behavior.
- A mismatched `contextVersion` → treated as no context, never misread.
- A save failure after a resolved turn → best-effort, logged nowhere sensitive, never breaks the response already computed for the trader.
- Ambiguous symbol in the current message → `clarification-required`, even with persisted context present (current explicit intent always governs ambiguity, per §3/§9).
- Provider failure on any turn, inherited symbol or not → `insufficient-data`, never a stale snapshot substituted from context.

## 15. Testing

`scripts/validate-conversation-continuity.ts` (`npm run validate:conversation-continuity`) — 53 assert-based checks (exceeds the ≥40 requirement): persistence (creation, round-trip, update, version mismatch, message/context conversationId coherence), resolution (override/inheritance for symbol and timeframe, exchange/market, unresolved/ambiguous symbol, unresolved timeframe), 8 follow-up phrasings, analysis-run + hypothesis linking (real DB), freshness (fresh-per-call proof via a stateful fake provider, staleness, provider-failure honesty), authorization (owner/stranger/forged-id/empty-userId/scoped-no-op-write/end-to-end chat-service isolation), replacement (symbol/timeframe/market-class changes, real end-to-end NIFTY→BANKNIFTY turn sequence), multi-turn chat integration (8 real turns through the same conversation, including a mid-conversation topic change), and a `resolveSymbol()` priority sanity check confirming the 4-tier chain this whole sprint depends on. Real Prisma-backed `User`/`Conversation`/`Message`/`IntelligenceAnalysisRun` rows are used throughout (self-cleaning), with only the market-data provider faked.

## 16. Future extensibility

Adding a new field to the persisted context (e.g. a future `lastRiskLevel` or multi-hypothesis disambiguation) is additive: bump `CONTEXT_VERSION`, extend `PersistedConversationContext` and `deriveNextContext()`'s input, no schema migration needed beyond the field already being inside the existing `JSONB` column. Nothing about this design requires touching `MarketState`/`Regime`/`Hypothesis`/`IntelligenceScore`/`DecisionContext`/any presenter — conversation memory remains a pure input to the existing, unmodified D2.6.2 resolution chain.
