# D2.7.4 — AT24 Native Chart Engine: Production Verification & Advanced Chart UX

**Status:** Implemented and tested.
**Scope:** A verification sprint, not a feature sprint. Proves the D2.7.2/D2.7.3 native chart pipeline — instrument selection → WorkspaceContext → candles API → MarketDataService → provider → normalized candles → indicators → coordinate system → Canvas renderer → trader-facing UI — is production-correct for all 13 required instruments, using deterministic fixtures (no live credentials). Fixes two real bugs the audit found. Adds UX only where verification named a real target.

---

## 1. Architecture audit

Phase 1 re-inspected every D2.7.2/D2.7.3 module (`NativeChart`, `ChartPanel`, `ChartToolbar`, `ChartProviderToggle`, `ChartTimeframeSelector`, `useChartCandles`, `renderer.ts`, `viewport.ts`, `crosshair.ts`, `candle-normalizer.ts`, the indicator modules, `panel-layout.ts`, the candles route, `MarketDataService`, `WorkspaceContext`). No architecture was refactored for style — only two genuine, demonstrable defects were found and fixed (§2).

## 2. Bugs discovered and fixed

**Bug 1 — initial-viewport race (real, high-impact).** `NativeChart.tsx`'s data effect tracked "have we seen this symbol/timeframe before" via a key stamped on every render, including the empty loading-state render. When real candles arrived moments later for the same key, the effect incorrectly believed it had already fit a viewport for that key and took the `followLatest` branch — against the 1-hour `fitToData([])` *placeholder* viewport, not real data. `followLatest` preserves the *previous* viewport's span, so every freshly loaded chart's initial view had a span of exactly 3,600,000ms regardless of the requested timeframe. For a `1d` chart (300 daily candles, ~86,400,000ms apart), this showed almost no candles. **Fix:** `fittedKeyRef` now stamps only once real (non-empty) data has actually been fit for a key; the empty-loading render never marks a key as fitted. Verified by a dedicated regression test (`validate-native-chart-verification.ts`, "BUG FIX REGRESSION").

**Bug 2 — timeframe/indicator selection lost on provider switch (real, matches Phase 11's explicit requirement).** `ChartPanel.tsx` rendered `{provider === "native" ? <NativeChart/> : <AdvancedChart/>}` — a ternary that fully unmounts `NativeChart` when switching to TradingView. `timeframe` and `activeIndicatorKeys` lived in `NativeChart`'s own `useState`, so they were destroyed on every switch and reset to defaults on switching back — violating "switching provider must preserve timeframe." **Fix:** both are now owned by `ChartPanel` (which never unmounts on a provider toggle) and passed to `NativeChart` as controlled props. The selected canonical instrument was never affected by this bug — it has always lived in `WorkspaceContext`, shared and untouched by either chart.

**Hardening (not a user-visible bug, but a real gap against Phase 8's explicit ask):** `useChartCandles`'s 20-second poll had no guard against a slow response overlapping the next tick. Added a `fetchInFlight` flag so a background poll tick is skipped (not stacked) while the previous fetch is still in flight.

## 3. Instrument verification

All 13 required instruments (NIFTY50, BANKNIFTY, RELIANCE, TCS, INFY, HDFCBANK, BTCUSD, ETHUSD, XAUUSD, XAGUSD, EURUSD, GBPUSD, USDJPY) were verified through the full pipeline — catalog resolution → chart resolution → provider capability → a fixture-provider fetch → provenance capture → candle normalization → indicator computation → renderer — using a deterministic fake `TimeSeriesProvider` (never real network data, never presented as live). Every instrument resolves, every chart symbol is exchange-prefixed and real, every pipeline run completes without throwing and without fabricating data.

## 4. Indian-market verification

NIFTY50/BANKNIFTY/RELIANCE/TCS/INFY/HDFCBANK were verified to map exclusively to the `angel-one` provider in the canonical catalog — never Binance or Twelve Data. Their chart symbols resolve to real `NSE:`-prefixed tickers derived from the Angel One-confirmed catalog mappings (unchanged since D2.6.6). No live Angel One session was available or attempted this sprint; all verification here is fixture-based, per the sprint's own explicit instruction not to invent live results.

## 5. Timeframe verification

Every `SignalTimeframe` (1m/5m/15m/30m/1h/4h/1d/1w) was verified end to end: `PROVIDER_INTERVAL` has a real mapping, candle spacing/indicator computation/viewport fitting all work with the real per-timeframe step size, and time-axis granularity correctly splits intraday (clock-time) from day+ (date) timeframes. No second timeframe registry was created.

## 6. Indicator verification

All 7 default indicators (EMA-20, EMA-50, SMA-20, Bollinger-20, RSI-14, MACD-12-26-9, Volume) were verified for: correct candle alignment (one point per candle, matching timestamps), no NaN/Infinity leakage, determinism, **no future-data leakage** (the value at any index is proven identical whether computed from the full series or a series truncated right after that index — a genuine lookahead-bias test, not just a correctness check), and correct panel/overlay classification. The existing scalar implementations in `lib/market-data/indicators.ts` were not modified — no real defect was found that required changing them.

## 7. Crosshair verification

Verified: exact snap at the first candle, exact snap at the last candle, honest snapping (never a fabricated index) for x positions before the first candle and after the last, binary-search equivalence with the underlying `nearestIndexByTime` function, and `-1` on an empty series.

## 8. Viewport verification

Verified: initial fit bounds include every real candle, pan preserves span, zoom in/out change span correctly in the right direction, zoom respects the 5–2000 visible-candle floor/ceiling, price auto-fits only the visible window, every produced bound is finite, and 500 pan round-trips introduce no floating-point drift. Includes the dedicated Bug 1 regression test (§2).

## 9. Polling / live-fetch verification

Verified via source inspection (this project's established, no-DOM-test-framework convention for React hooks): initial fetch fires on mount, the 20-second interval is real, each response replaces the series wholesale (no append/merge that could double-count a candle), a `cancelled` flag prevents a stale pre-navigation response from applying, a background poll failure is silently absorbed while a foreground fetch failure surfaces an honest error, polling continues automatically after any single failure, cleanup aborts the in-flight request and clears the interval on both symbol/timeframe change and unmount, and the new `fetchInFlight` guard prevents overlapping requests (Bug/hardening, §2). No WebSocket was introduced.

## 10. TradingView / native coexistence

Verified: the provider toggle is explicit (`native | tradingview`), neither chart is ever silently substituted for the other (no try/catch fallback path exists), both charts read the active symbol from the same `WorkspaceContext` (never a component-local copy), `AdvancedChart.tsx` is completely untouched, no second symbol registry was introduced, and `services/market-data/shared-instance.ts` (provider routing) is untouched. The state-loss bug (§2, Bug 2) is fixed and verified.

## 11. Security verification

Verified: the candles API requires authentication, symbol is validated server-side against the real catalog, timeframe is validated server-side via `isSignalTimeframe`, `outputSize` is server-side bounded, no provider credential pattern appears in any route or client chart-engine file, provider errors are sanitized through the shared error-DTO, no secret-shaped values are logged, and the route-local cache key carries no per-user identifier.

## 12. Performance

Full pipeline (normalize → indicators → render, 3 sub-panels active) measured within budget at 500/2,000/5,000 candles; crosshair lookup (binary search) stays fast across 300 probes at 5,000 candles. Confirmed via source inspection: no `setState` is called directly from the pan/zoom/crosshair mouse handlers (only through the rAF-throttled hover path or the rarer viewport-change path), `ResizeObserver` is disconnected in its effect cleanup, and the hover animation-frame handle is cancelled on unmount.

## 13. UX changes (Phase 9, added only after correctness verification)

- **Latest-price marker**: a horizontal dashed gold line at the last real candle's close, with its real price value in the axis gutter — drawn directly from `candles[]`, never a second/fabricated price source.
- **Provenance/freshness disclosure**: a small text line reading real `provider`/`fallbackUsed`/`cached`+`cacheAgeMs`/`freshness` values already present on `ChartSeries` — never invented text, never shown when the underlying field is absent.

No other UX changes were made — the toolbar, timeframe selector, indicator selector, provider toggle, crosshair readout, and all chart states (loading/empty/error/unsupported/stale/partial) from D2.7.2/D2.7.3 were verified correct as-is and left unchanged. AT24's black/gold design system and D2.7.1's financial typography tokens are the only colors/fonts used.

## 14. Known limitations

- No independent vertical pan/zoom (unchanged design decision since D2.7.2).
- Live, authenticated Angel One/broker session testing was not available or attempted — all Indian-market verification is fixture-based, per the sprint's own instruction.
- Live, authenticated interactive browser verification of the chart UI itself (indicator toggles, panel rendering, crosshair readout, keyboard nav) could not be completed in this environment — see the sprint's final report for exactly what was and wasn't verified.
- Multi-symbol compare remains a types-only extension point (D2.7.3) — untouched this sprint.

## 15. Browser verification limitations

Automated (`curl`) and unauthenticated-browser verification only — see the final report. The standing credential-refusal constraint (never enter the user's password into a login field) continues to apply.

## 16. Explicit non-goals

No trading signals, no BUY/SELL recommendations, no automated trading, no broker execution, no ML/LLM chart interpretation, no WebSockets, no Redis/Kafka, no website redesign, no removal of TradingView, no silent fallback between chart providers, no fabricated market data, no changes to Intelligence Score/Regime/Hypothesis/DecisionContext.
