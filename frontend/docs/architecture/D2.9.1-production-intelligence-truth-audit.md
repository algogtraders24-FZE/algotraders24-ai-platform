**Type:** Audit + minimal provable fix. No architecture redesign, no new intelligence features, no trading-logic changes, no Intelligence Score/HypothesisEngine/DecisionContext methodology changes, no provider-priority changes, no TradingView/NativeChart core changes, no D2.7.9–D2.7.11 cron changes.

**Previous sprint:** D2.9.0 (commit `3b3225b`) — fixed the hypothesis-outcome evaluator's `nowMs` clock-propagation bug and the Angel One candle-window sizing bug.

## 1. Complete data → intelligence chain

```
Provider (Twelve Data / Alpha Vantage / Binance / Angel One)
  → MarketDataService (provider selection, fresh-only cache, fallback)
  → validateCandles() (reject duplicate / out-of-order / future-timestamp / invalid-OHLC / negative-volume)
  → lib/market-data/indicators.ts (RSI14, EMA20/50, ATR14, MACD, Bollinger, volume metrics)
  → MarketStateService.assemble() (MarketState: structure.trend/volatilityBand/recentRange, candleValidation)
  → RegimeService.classify() (Regime: regimeType, confidence, basis)
  → HypothesisService.generate() (Hypothesis[]: type, invalidationCondition, predictionWindow)
  → HypothesisOutcomeEvaluatorService (validated/invalidated/pending/inconclusive, D2.9.0-fixed)
  → HistoricalValidationService (aggregated validatedRate, MIN_HISTORICAL_VALIDATION_SAMPLE-gated)
  → IntelligenceScoreService.compute() (8-component 0–100 score, deterministic)
  → DecisionContextService.build() (well-supported / partially-supported / conflicted / insufficient-intelligence)
  → RealTimeIntelligenceService.build() (VerifiedRealTimeIntelligenceContext, optional microstructure fetch)
  → buildVerifiedAnswerResponse() (the ONE canonical presentation contract, VerifiedAnswerResponse)
  → Chat (IntelligencePresentationService) | Workspace Research (ResearchSnapshotService) | Workspace AI Intelligence panel (intelligence-panel-projection.service.ts, D2.8.16)
  → Native Chart (independent read-only candle path, never touches DecisionContext)
```

**Key structural finding:** as of D2.8.16 (this session, prior to D2.9.0), three of the four presentation surfaces (Chat, Workspace Research, Workspace AI Intelligence panel) all terminate in the exact same `VerifiedAnswerResponse` object, built by the exact same `ResearchSnapshotService.build()` → `DecisionContextService.build()` → `buildVerifiedAnswerResponse()` chain. They cannot structurally disagree about score/regime/decisionState for the same symbol at the same moment — a disagreement would require a bug in that one shared chain, not two independent implementations. This is the single biggest fact this audit rests on.

**Silver-lining scope decision (unchanged from D2.8.16):** Trading Copilot and Market Intelligence remain deliberately separate, differently-scoped tools (raw per-indicator technical confidence vs. the full Intelligence Engine) and are not required to numerically match the Intelligence Engine's score — see §12 for the classification.

No place was found where one of the four unified-chain layers can silently disagree with another without a corresponding bug in a single shared function (which would then affect every consumer identically, not just one).

**Symbol aliasing:** `getCanonicalInstrument()` is the single resolution point every layer uses (`MarketDataService`, `fetchMicrostructure()`, `RealTimeIntelligenceService`, `HypothesisOutcomeEvaluatorService` via `hypothesis.symbol`, the candles route, the Research/panel routes) — no second symbol-normalization table exists anywhere in the traced chain.

**Previous-symbol leakage (Defect #2, already fixed in this session before D2.9.0):** `WorkspaceHeader.tsx`'s symbol-change effect reset its loading `state` but never cleared its `snapshot` object, so a symbol switch (e.g. EURUSD → BTCUSD) briefly rendered the new symbol's title with the PREVIOUS symbol's price/provider/timestamp underneath it. - `IntelligencePanel.tsx` — gates all `data` reads behind an early `state === "loading"` return; never reaches stale `data` during a symbol switch.
- `WorkspaceResearch.tsx` — explicitly calls `setData(null)` alongside `setState("loading")`.
- `useChartCandles.ts` (Native Chart) — uses one combined `result` state object (`setResult({status:"loading"})` replaces the whole object, including any previous `series`), structurally immune to this bug class.
- `MarketRibbon.tsx` — architecturally different (shows N symbols simultaneously via a `Record<symbol, Snap>`, not a single active-symbol switch), not subject to this bug class.

**Unsupported-provider substitution:** never observed or possible by construction — `isTimeSeriesProvider`/`isSnapshotProvider` type guards in `MarketDataService` skip a provider that doesn't implement the required capability rather than calling it, and `orderProviders()`/`providerSupportsInstrument()` filter by the catalog's real `providerMappings` before ranking (D2.6.3/D2.6.4, unmodified).

## 3. Timestamp / point-in-time audit

Re-verified after D2.9.0's `nowMs` clock-propagation fix:

- **Monotonic candles / duplicate rejection / future-candle rejection:** enforced by `validateCandles()` (D2.8.15), unmodified this sprint. Re-confirmed passing (40/40 `validate-intelligence-data-sufficiency.ts`).
- **Indicator calculations use only eligible candles:** `MarketStateService.assemble()` computes every indicator exclusively from `validation.validCandles`, never the raw input — unmodified, re-confirmed.
- **Historical evaluation uses its supplied reference clock:** this is the exact D2.9.0 fix. New D2.9.1 regression test asserts the fix line (`nowMs: clock.now()`) is still present, guarding against a future revert.
- **T0/T1 determinism (new tests, `validate-production-intelligence-truth.ts`):**
  - T0 (1s before the window closes): status is `pending` — no data past the boundary is used.
  - T1 (1s after, same input data): status resolves (no longer `pending`) — the additional data becomes usable exactly at the boundary, not before.
  - Same clock + same input data, evaluated twice: byte-identical `status`, `actualPriceMovePct`, and `evaluationBasis`.
- **No future-data leakage in outcome evaluation:** unchanged, `validate-hypothesis-outcome.ts`'s own "no future leakage" test re-confirmed passing.
- **Presentation does not combine snapshots from different evaluation times:** by construction — `VerifiedAnswerResponse.generatedAt` is a single timestamp for the whole object; there is no per-field timestamp that could drift within one response.

No new timestamp defect found. D2.9.0's fix is intact and now has a permanent regression guard.

## 6. Hypothesis consistency

Every hypothesis's `invalidationCondition` is evaluated against a `MarketState` reconstructed strictly at or before its own stored evaluation boundary — this is precisely what D2.9.0 fixed and what §3's T0/T1 tests now prove deterministically. `createdAt`/`predictionWindow` are read from the stored `HypothesisSnapshot`, never recomputed from "today". No hypothesis can be evaluated against a MarketState newer than its own evaluation timestamp — the evaluator only ever fetches candles up to `dueAt` (`evalIdx`), never beyond.

## 8. Microstructure consistency

`fetchMicrostructure()` (`RealTimeIntelligenceService`) gates on the target instrument's own real `providerMappings` containing a `binance` entry with `quote` capability — never a hardcoded symbol list. Catalog audit (new D2.9.1 test, `validate-production-intelligence-truth.ts`) confirms **only BTCUSD/ETHUSD/SOLUSD/XRPUSD have any `binance` mapping in the entire catalog** — EURUSD, GBPUSD, XAUUSD, XAGUSD, NIFTY50, and BANKNIFTY structurally cannot trigger a Binance call; there is no code path that would attempt one.

`MICROSTRUCTURE_OVERCLAIM_PATTERNS` (`ai-response-integrity.service.ts`, D2.8.2/D2.8.7-12, unmodified) unconditionally rejects any AI-generated text claiming "global market liquidity" or similar generalized-from-Binance framing, regardless of whether microstructure evidence was actually present for that request. Confirmed present and wired via a new D2.9.1 structural test.

Bid/ask, depth, imbalance, volume-delta, and aggressor-side evidence all carry real provider/instrument attribution in `MicrostructureEvidenceAssessment` (D2.8.5–D2.8.11, unmodified, re-confirmed passing across all 8 microstructure suites re-run this sprint — 0 failures).

## 12. Cache / request consistency

Audited `MarketDataService`'s shared caching (added this session, before D2.9.0):

- **New D2.9.1 tests (`validate-production-intelligence-truth.ts`):** a symbol switch always reaches the real provider for the new symbol (cache keys are per-symbol, never shared/global) — proven with a counting fake provider. The identical symbol/interval/outputSize within the cache TTL is served from cache (no duplicate provider hit). A different interval for the same symbol is never conflated with a different timeframe's cached candles (`${symbol}:${interval}:${outputSize}` is the full key).
- Chart polling (`useChartCandles`, 20s interval) and the shared `MarketDataService` cache (fresh-only TTL) are two independent layers that do not fight each other: the route-level cache absorbs the chart's own repeat polls, and the service-level cache (this session's fix) absorbs cross-consumer duplication (chart + indicators + Research panel + AI Intelligence panel all requesting the same symbol/interval within seconds of each other, previously each hitting the provider independently and exhausting the Twelve Data rate limit — the original bug this cache was built to fix).
- Stale cache is never silently presented as fresh: `getStale()`'s `ageMs` is always available to the caller, and `MarketSnapshot.cached`/`cacheAgeMs` are honestly surfaced (D2.3.S3, unmodified).

No new cache defect found.

## 13. Failure-mode matrix

| Scenario | What the user sees | Engine state | Fabricated value? |
|---|---|---|---|
| Provider success | Real price/candles, live badge | `resolved` | No |
| Provider timeout | Falls back to next provider, or honest `provider_error`/`insufficient-data` | typed `MarketDataProviderError` | No |
| Provider HTTP error | Same as above | typed error, `kind` classified by status code | No |
| Rate limit | Falls back to next provider or honest unavailable; live-reproduced for XAGUSD this sprint | `rate_limit` kind, retried with backoff (3 attempts) then falls back | No |
| Malformed candle | Silently dropped, never re-enters computation | `candleValidation.issues` records it; valid remainder still used | No |
| Future candle | Rejected relative to the evaluator's own `nowMs`/`clock` (D2.9.0 fix) | `future-timestamp` issue | No |
| Duplicate candle | Rejected, first-seen wins | `duplicate-timestamp` issue | No |
| Insufficient candles | Indicator honestly `undefined`, never a placeholder | per-indicator `dataAvailable: false` | No |
| Unsupported microstructure (e.g. EURUSD) | No microstructure section shown, disclaimer conditional on real capability (D2.8.15) | `microstructureEvidence: undefined` | No |
| Stale microstructure | Freshness surfaced honestly, never presented as live | `freshness` field on the snapshot | No |
| Invalid microstructure | Rejected before use (same `validateCandles`-style discipline) | discarded, not substituted | No |
| Missing hypothesis | `primaryHypotheses: []`, decisionState reflects it, never fabricated | real empty array | No |
| Missing historical outcome | `historicalContext.status: "unavailable"` or `"insufficient-sample"`, `validatedRate` stays `undefined` below `MIN_HISTORICAL_VALIDATION_SAMPLE` (never `0`) | honest | No |
| Missing indicator | `undefined`, excluded from the score with a documented completeness penalty, never treated as 0/100 | honest | No |

Every row was independently already covered by an existing, currently-passing suite (cited in the cross-reference table below) except the future-candle/insufficient-candle interaction with the evaluator's own clock, which is the D2.9.0 fix now covered by §3's new tests.
