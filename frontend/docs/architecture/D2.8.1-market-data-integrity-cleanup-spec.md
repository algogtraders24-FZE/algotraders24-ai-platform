# D2.8.1 — Market Data Integrity & Fabrication-Risk Cleanup

**Status:** Implemented and tested. **Baseline:** D2.8.0 (`docs/architecture/D2.8.0-market-data-capability-audit.md`, PASS).
**Scope:** Wire Alpha Vantage's already-real EURUSD bid/ask into the existing `MarketSnapshot` pipeline; derive spread only from a valid bid/ask pair; remove the confirmed-dead liquidity-fabrication service; verify every honest-unavailable field this platform declares is still honest.

---

## 1. Existing market-data evidence model (unchanged)

The provider hierarchy from D2.6.3/D2.6.4 is unchanged: `MarketDataProvider` (base — `getMarketContext`) with two additive, duck-typed capabilities detected at runtime via `isSnapshotProvider()`/`isTimeSeriesProvider()` (`types/market-data-provider.ts`):

- `SnapshotProvider.getSnapshot()` → the canonical `MarketSnapshot` (`types/market-snapshot.ts`).
- `TimeSeriesProvider.getTimeSeries()` → historical `Candle[]`.

`MarketDataService` (`services/market-data/market-data.service.ts`) is the single orchestrator: priority-ordered provider list, per-call reliability (timeout/retry/backoff), TTL caching with stale-fallback resilience, and (opt-in) health-based `smartFallback` reordering. This sprint added no new abstraction to this stack — it only made an existing, structurally-declared capability (`MarketSnapshot.bid`/`ask`) actually reachable by one more real provider, and added one small, centrally-computed derived field (`spread`).

## 2. Alpha Vantage bid/ask integration path

`AlphaVantageProvider` (`lib/market-data/providers/alpha-vantage.provider.ts`) previously implemented only the base `MarketDataProvider` interface — its real, parsed bid/ask (`"8. Bid Price"` / `"9. Ask Price"` from `CURRENCY_EXCHANGE_RATE`) was stranded inside `getMarketContext()`'s text-only `evidence[]` array and never reached any structured consumer.

This sprint added `AlphaVantageProvider.getSnapshot()`, making the class also implement `SnapshotProvider`. It:

- Reuses the exact same cached `fetchQuote()` / `TtlCache` path `getMarketContext()` already used — no second fetch, no second cache.
- Reports `price`, `bid`, `ask`, `quoteCurrency: "USD"`, `timestamp` (provider's own UTC "Last Refreshed" when parseable, else `retrievedAt`), `timezone: "UTC"`, `provider`, `retrievedAt`, `providerSymbol` (e.g. `"EUR"` for canonical `EURUSD`).
- Never reports `ohlc`, `volume`, or `changePercent` — the exchange-rate endpoint has no session OHLC or volume, and `MarketSnapshot.ohlc`'s own doc comment already anticipates this ("spot-only providers omit it").
- Reports `marketStatus: "unknown"` — Alpha Vantage's realtime-exchange-rate endpoint has no open/closed signal, so `"unknown"` is the honest value, never a guess.
- Works for any symbol already in `SYMBOL_MAP` (`EURUSD`, `XAUUSD`, `XAGUSD`), not hardcoded to EURUSD — XAU/XAG will surface bid/ask through this same path the moment the configured key/tier supports them (unchanged pre-existing limitation, see file header).

**Provider selection order was NOT changed.** `MarketDataService`'s default array (`TwelveDataProvider, AlphaVantageProvider, BinanceProvider, AngelOneProvider`) is byte-identical to before this sprint. Alpha Vantage participates in the existing `getSnapshot()` selection/fallback loop at its existing priority position (2nd). Practically:

- **Normal path (Twelve Data healthy):** EURUSD snapshots are unchanged — Twelve Data still wins, still supplies real OHLC, still has no bid/ask (exactly as before this sprint).
- **Fallback path (Twelve Data fails/unconfigured for EURUSD, or `smartFallback` demotes it on real recorded unreliability):** Alpha Vantage now correctly serves a valid snapshot — with real bid/ask but honestly no OHLC — where previously it could not serve `getSnapshot()` at all (a real resilience gap this sprint closed as a side effect, not a deliberate goal).

No merge-two-providers-into-one-snapshot mechanism was introduced; that would have been a new abstraction the sprint brief explicitly disallowed. One provider's `getSnapshot()` wins, exactly as before.

## 3. Spread derivation rules

`types/market-snapshot.ts` gained one new optional field: `spread?: number`, mirroring the existing `bid?`/`ask?` fields' own convention (undefined means "not known", never a guessed/zero value).

`MarketDataService.getSnapshot()` gained one small, centrally-located, pure helper — `withDerivedSpread()` — applied to whichever provider's snapshot won the existing selection loop, **before** caching and before the existing `fallbackUsed` provenance stamp:

```
spread = ask - bid   ONLY WHEN bid !== undefined AND ask !== undefined AND ask >= bid
spread = undefined   in every other case
```

This is deliberately centralized (not computed inside each provider) so any current or future `SnapshotProvider` that ever supplies a valid bid/ask gets `spread` for free, with the derivation logic living in exactly one place. It is a pure function over the winning snapshot's own already-provider-validated `bid`/`ask` — never derived from `price`, never from candles, never a fixed/percentage estimate, never a zero-fallback.

## 4. Unavailable-data policy (unchanged, reverified)

Every "no genuine source → undefined, never guessed" rule this platform already enforced remains exactly as it was:

- Alpha Vantage's `getSnapshot()` rejects an invalid or partial bid/ask pair — finite, `bid > 0`, `ask > 0`, `ask >= bid` are all required; failing any one leaves **both** `bid` and `ask` undefined (never a partial/one-sided value, never a normalized-into-range fake value).
- `MarketSnapshot.ohlc`, `.volume`, `.changePercent` remain undefined from Alpha Vantage, exactly as `getMarketContext()` already documented.
- `types/intelligence-market-state.ts`'s `liquidityZones`/`volumeDelta` fields, and `MarketStateService`'s own "intentionally omitted — never populated" comment, are untouched — this sprint made no code change anywhere in that file or service.
- `DecisionContextService.buildMissingInformation()`'s four hardcoded "permanent, structural non-implementation" items (liquidity zones, buy/sell volume delta, execution risk, liquidity risk / order-book depth) are untouched and reverified still present (see §10).

## 5. Fabrication-risk finding (reverified fresh, not assumed from D2.8.0)

A fresh reference search (not a reuse of D2.8.0's prior conclusion) confirmed `services/ai/trading/liquidity-analysis.service.ts`'s `getLiquidity(price)` still fabricated liquidity zones as fixed `±0.5%/1%/1.5%` price offsets with zero underlying order-book evidence, and that its **only** caller anywhere in the repository was `services/ai/trading/market-analysis.service.ts`'s `analyzeMarket()` — itself confirmed to have **zero** live callers (no route, no service, no component imports `analyzeMarket`, `marketAnalysisMeta`, or `liquidityMeta`; the string `"market-analysis"` that appears elsewhere in the codebase is an unrelated, real intent/schema id used by `services/ai/prompts/*` and `services/ai/assistant.service.ts` — a coincidentally-shared label, not a caller of this dead chain). Three existing validation scripts (`validate-alpha-vantage-provider.ts`, `validate-market-analysis-orchestration.ts`, `validate-evidence-intelligence.ts`) already asserted specific market-data files must never reference `services/ai/trading/` — a pre-existing defensive check, not a caller.

## 6. Dead liquidity service disposition

**Removed** (deletion, not deprecation — references/callers/tests/docs all confirmed genuinely unused, satisfying the sprint's "prefer deletion only if genuinely unused" bar):

- `services/ai/trading/liquidity-analysis.service.ts` (the fabrication itself).
- `services/ai/trading/market-analysis.service.ts` (its sole caller, itself dead — leaving it in place after deleting its only import would have left a broken build, and it independently satisfied the same "zero live callers" bar).

**Deliberately left untouched** (scope discipline — not part of this sprint's mandate, and removing them was not required for correctness):

- The other 6 sibling files in `services/ai/trading/` (`technical-analysis`, `support-resistance`, `market-bias`, `trade-setup`, `risk-engine`, `confidence-engine`) — none of these fabricate anything D2.8.0 flagged; they are pure computations over a caller-supplied price. They are now fully orphaned (their only caller, `market-analysis.service.ts`, is gone), but deleting already-inert files beyond the specific fabrication this sprint targeted would have been scope creep against "do not redesign architecture."
- `types/technical-analysis.ts` (`LiquidityZones`, `TechnicalIndicators`, `SupportResistance`) and `types/market-analysis.ts` (`MarketQuote`, `MarketAnalysis`) — genuinely still imported by real files (`components/trading/*.tsx`, `data/mock-market.ts`) outside the deleted service chain. Deleting them would have broken those files for no reason connected to this sprint's mandate.

## 7. Active Trading Copilot liquidity path

Reverified fresh: `services/ai/trading-copilot.service.ts` (the real, live route at `app/api/private/trading-copilot/analyze/route.ts`) contains **zero** references to "liquidity" in any form. There is no "separate honest liquidity implementation" in the live Trading Copilot to protect — the conditional constraint in the sprint brief ("do not modify it if it exists") simply does not apply, because it does not exist. This sprint made no change to `trading-copilot.service.ts` or its route, and a regression assertion (`validate-market-data-integrity.ts` test 15) now guards that this remains true.

## 8. What remains unavailable (unchanged)

- Bid/ask/spread for every instrument other than Alpha Vantage's `EURUSD` (and, once the key/tier supports it, `XAUUSD`/`XAGUSD`) — Twelve Data, Binance, and Angel One still supply none of these fields.
- Tick data, buy/sell volume delta, order-book depth/market depth, real liquidity zones (order-book sense), slippage, latency, fill probability, execution risk — no source exists anywhere in this platform for any of these; none were touched, added, or stubbed.
- `MarketDataCapability` (`types/canonical-instrument.ts`) remains exactly `"quote" | "candles"` — no `"orderbook"`/`"trades"` capability was introduced.

## 9. Explicit non-goals (honored)

No new market-data vendor, WebSocket, or broker integration. No order-book depth, buy/sell delta, or execution-risk scoring implemented. No change to Intelligence Score weights/formula, `RegimeService`, `HypothesisService`, `DecisionContextService`'s semantics, Twelve Data's behavior, historical validation, or the D2.7.x chart engine. `NativeChart.tsx` and TradingView's `AdvancedChart.tsx` were not touched. No trading signal, BUY/SELL recommendation, automated trading, or order-placement capability was added. `vercel.json`/D2.7.11 cron configuration and `MIN_HISTORICAL_VALIDATION_SAMPLE` are untouched. Provider selection order is byte-identical to before this sprint (see §2).
