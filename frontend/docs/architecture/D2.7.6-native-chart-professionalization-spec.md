# D2.7.6 — AT24 Native Chart Professionalization & Real-Market UX

**Status:** Implemented and tested.
**Scope:** A rendering-quality sprint, not a feature sprint. Moves the D2.7.2–D2.7.5 native chart engine (already verified production-correct and workspace-ready) from "beta Canvas chart" toward "professional financial-terminal-quality chart" by closing genuine, audit-verified rendering gaps — never by redesigning working architecture, duplicating a registry, or inventing infrastructure.

---

## 1. Architecture audit

Re-read `components/chart-engine/`, `lib/chart-engine/` (including `coordinate-system.ts`, `price-axis.ts`, `time-axis.ts`, `canvas-colors.ts`, `canvas-typography.ts`, `candle-classifier.ts`, `types.ts` — not previously re-inspected line-by-line in this sprint series until now), `lib/chart-engine/indicators/`, `WorkspaceContext`, and the D2.7.1–D2.7.5 specs. Distinguished four things per the brief's own framework:

- **Genuine functional defects**: none found. The D2.7.2–D2.7.5 pipeline is correct as-is.
- **Genuine UX/rendering gaps** (see §2): no vertical time-grid, no candle-body-width cap at extreme zoom, fixed (non-responsive) axis tick density, no crosshair price-axis label, RSI/MACD/Volume sub-panels missing value-axis reference labels.
- **Cosmetic opportunities considered and deliberately NOT taken**: see §14 (non-goals/rejected ideas).
- **Architecture already correct, deliberately NOT touched**: `fitToData()`'s exact left-edge behavior (§3), the coordinate system, the viewport model, the indicator calculation layer, the candle normalizer, `chart-instrument-resolver.ts`, the instrument catalog, the timeframe registry, TradingView's `AdvancedChart.tsx`, and D2.7.5's session-persistence/fullscreen/header work.

## 2. Genuine defects/UX issues discovered

No functional defects. Five real, previously-missing rendering-quality gaps were found and closed:

1. Only horizontal (price) gridlines existed — no vertical (time) gridlines, weakening the chart's visual grid/hierarchy.
2. Candle body width had no maximum cap — zooming to the engine's own `MIN_VISIBLE_CANDLES` floor (5) could stretch a body past 100px, an unprofessionally oversized block.
3. Price/time axis tick density was a fixed constant (5/6) regardless of the panel's actual pixel size — could crowd on a short/narrow viewport or under-label a large desktop one.
4. The crosshair drew a timestamp label but no price-axis label — a standard professional-charting feature this engine lacked entirely.
5. The RSI panel's 70/30 reference lines had no numeric labels; the MACD panel had no explicit zero line when the histogram itself had no visible bars; the Volume panel had no numeric value-axis label at all.

## 3. A finding that was investigated and explicitly NOT changed

The first visible candle sitting flush against the plot's left edge (`fitToData()`'s `minTime = candles[0].time`, no left padding) initially looked like a candidate defect (the leftmost candle's body can render partially off-canvas). It is not: `scripts/validate-native-chart-engine.ts`'s own test 22 ("`fitToData` spans the real candle range") asserts `vp.minTime === candles[0].time` exactly — a deliberate D2.7.2 design contract, not an oversight, and standard behavior for virtually every candlestick charting library when scrolled to the data boundary. Changing it would have been a real regression against an explicit prior-sprint test, not a genuine improvement. Left untouched.

## 4. Bugs fixed

None — no functional defects were found (see §1–§2).

## 5. Rendering improvements

- **Vertical time-grid** (`drawTimeGrid`, new in `renderer.ts`): drawn once, behind every panel (not per sub-panel, since every panel shares one time axis), using the same crisp-1px-line convention (`Math.round(...) + 0.5`) the existing horizontal price grid already uses.
- **Candle body width cap** (`MAX_BODY_WIDTH_PX = 24`, new constant in `renderer.ts`): candle bodies are now clamped to a professional maximum width even at the engine's most extreme zoom-in level, matching mainstream charting-terminal conventions. Verified behaviorally (not just by source inspection) via a recording fake `CanvasRenderingContext2D` that captures real `fillRect` width arguments.

## 6. Axis improvements

- `targetPriceTickCountForHeight(heightPx)` (new, `price-axis.ts`) and `targetTimeTickCountForWidth(widthPx)` (new, `time-axis.ts`): pure, additive helpers that derive a sensible tick count from the panel's *real* pixel dimensions instead of a fixed constant, clamped to `[2, 8]`. Both fall back to the original fixed default (5/6) for a non-finite/zero dimension — **fully backward compatible**; neither `computePriceTicks` nor `computeTimeTicks` had their signatures changed (both already had an optional trailing `targetCount` parameter from D2.7.2 — `renderer.ts` now simply computes a real value for it instead of omitting it). No hardcoded per-instrument/per-symbol precision table was introduced; decimal precision is still derived purely from the tick step, unchanged since D2.7.2.

## 7. Crosshair improvements

A real price-axis label (`drawCrosshair`, extended): when the crosshair's y-position falls within the price panel's own row, a price value badge renders in the price-axis gutter, computed via the existing `yToPrice` inverse conversion — never a fabricated or interpolated value. Styled in `textTertiary` (steel), deliberately never gold, so it is never confused with the D2.7.4 latest-price marker. **Deliberately scoped to the price row only**: a y-position inside a sub-panel (Volume/RSI/MACD) has its own, different value scale (e.g. 0–100 for RSI) — showing a number derived from the main price `Viewport` there would be wrong, so the label is simply omitted rather than guessed. Binary-search snapping, `requestAnimationFrame` throttling, and the "never interpolate a synthetic OHLC value" rule are all unchanged.

## 8. Latest-price improvements

## 9. Sub-panel improvements

- **RSI**: the existing 70/30 dashed reference lines now carry real numeric labels (`"70"`/`"30"`) — a real, standard, published RSI convention, never an invented threshold.
- **MACD**: a dashed zero reference line is now drawn unconditionally (previously the zero line was only implicitly visible via the histogram bars' own baseline, invisible whenever the histogram itself had no bars in view).
- **Volume**: a real max-volume value-axis label now renders (top-right of the panel, via the existing `formatCompactVolume` — never a second/ad hoc volume formatter), shown only when real volume data exists; the D2.7.5 "No volume data for this instrument" honest-state notice is unchanged and the two are mutually exclusive by construction (verified by test).

Re-verified via the real, unmodified catalog/resolver (no live network calls; deterministic fixtures only, never presented as live data): NIFTY50/BANKNIFTY/RELIANCE/TCS/INFY/HDFCBANK still resolve exclusively to Angel One with real `NSE:`-prefixed chart symbols; BTCUSD/ETHUSD resolve to real `COINBASE:`-prefixed symbols; XAUUSD/XAGUSD and EURUSD/GBPUSD all resolve to real, chartable symbols. ## 13. Symbol/timeframe/provider switching verification

Re-verified via source inspection (this project's established convention for React-hook/effect behavior, no DOM test framework available): the `[symbol, timeframe, outputSize]`-keyed fetch effect, `AbortController`/`cancelled`-flag stale-request cancellation, the D2.7.4 `fittedKeyRef` re-fit fix, and indicator recomputation on the `[candles, activeConfigs]` dependency are all unchanged and unaffected by this sprint's renderer-only changes. Provider switching remains explicit (`native | tradingview`), with no silent fallback either direction, and D2.7.5's session-persisted provider/timeframe/indicator state is untouched.

## 14. Responsive verification

The new `targetPriceTickCountForHeight`/`targetTimeTickCountForWidth` helpers were tested across mobile (~311px plot width), tablet (~700px), and desktop (~1400px) widths, and short (~90px) vs tall (~900px) panel heights, confirming monotonically sensible tick counts within `[2, 8]` at every size. `renderChart` was exercised at both a narrow mobile canvas (360×320) and a large desktop canvas (1920×900) without throwing. `ResizeObserver`-driven canvas sizing, the D2.7.5 fullscreen container's flexible height, and `ChartToolbar`/`ChartHeader`'s `flex-wrap` behavior are all unaffected — this sprint touched no layout/CSS code.

## 15. Performance results

Full pipeline (normalize → fit → indicators → render, including the new grid lines and axis labels) re-benchmarked within budget at 500/2,000/5,000 candles. The two new tick-count helpers are O(1) — 10,000 combined calls complete in well under 200ms. Crosshair binary-search lookup remains fast across 300 probes at 5,000 candles, unaffected by this sprint.

## 25. Known limitations

- Volume/MACD-histogram sub-panel bar widths were deliberately NOT given the same `MAX_BODY_WIDTH_PX` cap as the main candlestick body — out of this sprint's audited scope (Phase 4's own scope language is about candle body/wick proportions specifically); a future sprint could extend the same pattern there if a real need is demonstrated.
- No independent vertical pan/zoom (unchanged design decision since D2.7.2).
- The crosshair's price-axis label is intentionally silent (not drawn) when hovering a sub-panel row — a deliberate correctness choice (§7), not an oversight; a future sprint could add a correctly-scoped RSI/MACD-specific value label if a real need is demonstrated.
- Live, authenticated interactive browser verification was not performed (§24).
