# D2.8.3 — Angel One + Binance Real Market Microstructure Capability POC

**Status:** Read-only capability-confirmation complete. No production code changed. **Baseline:** D2.8.2 (`47243cd`).
**Scope:** Determine, with direct runtime evidence wherever possible, exactly what Angel One SmartAPI and Binance can supply AT24 for NIFTY/BANKNIFTY and BTCUSDT/ETHUSDT respectively. **No provider integrated. No production architecture modified.**

---

## 1. Executive summary

**Angel One: runtime verification was NOT possible this sprint.** AT24's own Angel One credentials (`API_KEY`, `CLIENT_CODE`, `PIN`, `TOTP_SECRET`) are **absent from both `.env` and `.env.local`** in this checkout (confirmed by presence-only checks — no value was ever read or printed). Per this sprint's explicit final rule, no result is fabricated: every Angel One capability below is classified **B** (documented by the provider, not observed with AT24's credentials this sprint) or **E** (not verified), never **A**. D2.6.6's prior live smoke test (2026-08-11, cited as historical record only, not this sprint's evidence) previously confirmed real NIFTY/BANKNIFTY LTP quotes and candles — that access no longer exists in this environment.

**Binance: full runtime verification succeeded.** Using only Binance's public, unauthenticated REST and WebSocket market-data endpoints (no account, no credentials, exactly as instructed), this sprint captured real, live payloads for BTCUSDT/ETHUSDT depth snapshots, best-bid/ask, individual trades, aggregated trades, the partial-book-depth WebSocket stream, and the incremental diff-depth WebSocket stream. **Binance genuinely supplies a legitimate aggressor-side indicator** (`isBuyerMaker`/`m`) on every trade and aggTrade record — the single most important finding of this sprint, since it means buy/sell volume delta is a real, class-C deterministic derivation for Binance (not fabrication), while it remains flatly unavailable for every other AT24 provider.

## 4. Phase 3 — Binance capability test (runtime-verified, class A throughout)

All calls were made to Binance's public market-data endpoints (`api.binance.com` REST, `stream.binance.com:9443` WebSocket) — no API key, no account, nothing beyond what any anonymous browser could reach. Every payload below is a real, live capture from this sprint, timestamps and prices genuine as of the capture time (August 2026), included only as structural evidence, not as a live price feed.

**REST `/api/v3/depth?symbol=BTCUSDT&limit=10`** (order-book snapshot):
```json
{"lastUpdateId":98559154237,"bids":[["62981.37000000","1.90254000"], ...10 levels], "asks":[["62981.38000000","8.45828000"], ...10 levels]}
```
Confirms: real 10-level bid/ask snapshot, `[price, quantity]` pairs, a `lastUpdateId` sequence marker.

**REST `/api/v3/trades?symbol=BTCUSDT&limit=5`** (individual trade tape):
```json
{"id":6575486433,"price":"62983.37000000","qty":"0.00009000","quoteQty":"5.66850330","time":1786786224596,"isBuyerMaker":false,"isBestMatch":true}
```
Confirms: `id` (trade ID/sequence), `price`, `qty`, `quoteQty`, `time` (unix ms), and — critically — **`isBuyerMaker`, a real, documented, per-trade aggressor-side flag**. `isBuyerMaker: false` means the buyer was the taker (aggressor was the buy side); `true` means the seller was the taker.

**REST `/api/v3/aggTrades?symbol=BTCUSDT&limit=5`** (aggregated trades):
```json
{"a":4033705317,"p":"62983.37000000","q":"0.07941000","f":6575486455,"l":6575486455,"T":1786786226571,"m":false,"M":true}
```
Confirms: `a` (agg trade ID), `f`/`l` (first/last raw trade ID folded into this aggregate — a real sequence range), `m` (the same aggressor flag as `isBuyerMaker`, renamed for this endpoint).

**REST `/api/v3/ticker/bookTicker?symbol=ETHUSDT`** (best bid/ask):
```json
{"symbol":"ETHUSDT","bidPrice":"1878.48000000","bidQty":"50.27200000","askPrice":"1878.49000000","askQty":"25.34700000"}
```
Confirms: real top-of-book bid/ask with quantities, for a second instrument (ETHUSDT), not just BTCUSDT.

**WebSocket combined stream** (`btcusdt@depth10@100ms` / `btcusdt@aggTrade` / `btcusdt@trade` / `btcusdt@bookTicker`), one real message per stream captured via a disposable 8-second connection:
- `depth10@100ms`: identical shape to the REST depth snapshot (`lastUpdateId`, 10 bid/ask levels), confirmed pushed every ~100ms.
- `bookTicker`: `{"u":98559169270,"s":"BTCUSDT","b":"62985.99...","B":"6.02296...","a":"62986.00...","A":"3.16169..."}` — a real streaming update ID (`u`) accompanying best bid/ask.
- `trade`: `{"e":"trade","E":1786786267780,"s":"BTCUSDT","t":6575486708,"p":"...","q":"...","T":1786786267780,"m":false,"M":true}` — same aggressor flag (`m`) confirmed present in the real-time stream, not just the REST snapshot.
- `aggTrade`: `{"e":"aggTrade","E":...,"s":"BTCUSDT","a":4033705423,"p":"...","q":"...","f":...,"l":...,"T":...,"m":false,"M":true}` — same fields as the REST endpoint, confirmed live.

**WebSocket incremental diff-depth stream** (`btcusdt@depth@100ms`, distinct from the partial-book `depth10` stream above), two consecutive real messages captured:
```json
{"e":"depthUpdate","E":1786786305514,"s":"BTCUSDT","U":98559175353,"u":98559175358,"b":[["62840.49000000","0.00000000"], ...],"a":[["62988.95000000","0.60674000"]]}
{"e":"depthUpdate","E":1786786305614,"s":"BTCUSDT","U":98559175359,"u":98559175362,"b":[...],"a":[]}
```
Confirms: `U`/`u` (first/last update ID **in this event**), and directly observed the documented reconciliation contract working — the second message's `U` (98559175359) is exactly the first message's `u` (98559175358) **+ 1**, the real sequence-continuity guarantee a local order-book reconstruction would rely on. A quantity of `"0.00000000"` at a price level is the documented "remove this level" signal, also directly observed (`"62840.49000000","0.00000000"` and `"50391.16000000","0.00000000"` in the two captures).

**Historical data:** not re-tested this sprint (documented-only, class B) — `/api/v3/historicalTrades` and `/api/v3/klines` are Binance's documented historical trade/candle endpoints; AT24's `BinanceProvider` already uses `/klines` for candles (class A, pre-existing). No historical tick/depth archive product was found in Binance's public API documentation for either sprint.

**Ephemeral probe scripts:** two disposable Node scripts (native `WebSocket`, zero dependencies) were written to the session scratchpad (outside the repository), run with a bounded timeout, and **deleted immediately after capturing the payloads above** — confirmed via a post-deletion directory listing. Neither script, nor any credential, was ever committed. See §9 for the git-safety confirmation this claim rests on.

## 5. Phase 4 — legitimate derivations (documented only, NOT implemented)

| Derivation | Basis | Raw inputs | Provider(s) | Class |
|---|---|---|---|---|
| Spread | `ask - bid` | `bookTicker.askPrice`, `bookTicker.bidPrice` (Binance); Angel One would need `Full`/`Depth 20` top-of-book, not observed this sprint | Binance (real inputs observed); Angel One (inputs undocumented at field level) | **C** (Binance) / not derivable this sprint (Angel One) |
| Mid price | `(ask + bid) / 2` | same as spread | Binance | **C** |
| Bid/ask imbalance | `(bidQty - askQty) / (bidQty + askQty)` at top of book | `bookTicker.bidQty`, `bookTicker.askQty` | Binance | **C** |
| Depth imbalance | same formula summed across N depth levels | `depth10`/`depth` stream's `bids[]`/`asks[]` quantity arrays | Binance | **C** |
| Depth-weighted pressure | Σ(quantity × 1/distance-from-mid) per side | same depth arrays | Binance | **C** |
| Liquidity concentration | share of total depth-array quantity within the top K levels | same depth arrays | Binance | **C** |
| Trade volume | Σ `qty` over a time window | `/trades` or `trade` stream `q` field | Binance | **C** |
| **Buy volume** | Σ `qty` where `isBuyerMaker === false` (buyer was the aggressor/taker) | `/trades`/`/aggTrades` `isBuyerMaker`/`m` field | **Binance only** | **C** — this is the sprint's core positive finding: a *legitimate*, provider-supplied aggressor flag, not an inferred proxy |
| **Sell volume** | Σ `qty` where `isBuyerMaker === true` | same field | **Binance only** | **C** |
| **Volume delta** | buy volume − sell volume, both as derived immediately above | same field | **Binance only** | **C**, and *only* because the raw aggressor-side data genuinely exists — per this sprint's explicit rule, this would be forbidden as a derivation for any other AT24 provider, none of which supplies a real aggressor flag |

**None of the above was implemented in production this sprint.** This table exists purely to distinguish "mathematically legitimate, given real raw inputs" from "would be fabrication" — the same discipline D2.8.1 already established for spread.

## 6. Phase 5 — instrument/venue correctness

## 12. Known limitations

- Angel One's exact `Full`/`Depth 20` WebSocket payload shape remains genuinely unknown to AT24 — no first-party example exists in either D2.8.2 or this sprint's research, and no live test was possible. This is the single biggest open question blocking any real Angel One depth-integration decision.
- Binance's `/api/v3/historicalTrades` (historical tick archive) was not tested this sprint — documented to exist, but its exact response shape and pagination behavior are unverified against a live call.
- "Number of orders per price level" was confirmed **absent** from every Binance payload observed (a real negative finding, not an oversight) — Binance's public API exposes aggregated quantity per level, never a per-level order count.
- This sprint did not attempt to measure real Angel One or Binance WebSocket update frequency/latency under load — Binance's `100ms` stream interval is a documented parameter, observed to hold for the two-message capture window in §4, but not stress-tested.

## 13. Recommended D2.8.4

**Do not integrate yet.** The evidence gap is asymmetric: Binance is fully characterized and technically ready for a future, explicitly-scoped depth/aggressor-derivation POC; Angel One is not even reachable in this environment. The most useful next step is narrow and low-risk: **restore/confirm AT24's Angel One credentials (with the user's explicit go-ahead, matching the D2.6.6 precedent) and repeat exactly this sprint's Phase 2 methodology** — one disposable, read-only `Full`/`Depth 20` WebSocket capture for `NIFTY50`/`BANKNIFTY`, deleted after use, documented the same way §4 documents Binance. Only once both providers have real class-A evidence should a genuine "wire microstructure data into MarketSnapshot" production sprint be scoped — and even then, per this sprint's Phase 4 findings, only Binance's `isBuyerMaker`-derived buy/sell volume delta has a currently-confirmed legitimate raw-data basis; Angel One's would remain undetermined until its own live payload is seen.
