## 1. The locked rule

> **`/blog` visibility is decided by the PUBLICATION JOB, never by
> `Article.status`.** An Article is visible iff it has a **SUCCEEDED
> `PublishingJob` for destination `INTERNAL_BLOG`** (and its current content
> still hashes to that job's `contentHash`).

Querying `Article.status = "published"` would recreate the exact drift P2.3
removed — an Article can reach `published` by other means (the legacy route,
a direct DB edit) with no real publication behind it. The reader trusts the
job, not the flag.

Enforced in two places:
- `PublishingRepository.listPublishedInternalBlogRecords()` /
  `findPublishedInternalBlogRecordBySlug()` — the Prisma query filters
  `destination:"INTERNAL_BLOG"`, `status:"SUCCEEDED"`, `deletedAt:null`,
  `article:{deletedAt:null}`. It never reads `article.status`.
- `BlogReaderService` — additionally recomputes the content hash and refuses
  to serve a post whose content has **drifted** from the published version.

## 2. Read model

`types/publishing/blog-contract.ts` (additive, still `PUB-v1`):
`BlogPostSummary` (index), `BlogPost` (article page, sanitized sections +
`BlogPostSeo`), `PublishedInternalBlogRecord` (what the repo hands the
service).

`services/publishing/blog-reader.service.ts` — `BlogReaderService`:

| method | used by | notes |
| --- | --- | --- |
| `listPosts()` | `/blog` index, `/blog` sitemap section | newest-first; drift-checked |
| `getPostBySlug(slug)` | `/blog/[slug]` page + `generateMetadata` | `null` if not published / wrong destination / drifted / unknown slug |
| `listSlugs()` | `generateStaticParams`, `sitemap.ts` | = `listPosts().map(slug)` |

Source is injectable (`BlogReaderSource`) — the Prisma repo in production, an
in-memory fake in tests. Ownership-independent (public read).

### SEO field resolution (`buildSeo`)

Persisted `Article.seo` JSON is used **where valid**, with fallbacks:
`title → seo.title || article.title`; `description → seo.metaDescription ||
truncate(article.summary, 155)`; OG/Twitter title+description fall back to the
resolved title/description. **`canonicalUrl` is honoured only if it is exactly
`<SITE_URL>/blog/<slug>`** — otherwise the real route is used, so the canonical
is always a genuine, non-404 destination.

## 3. Sanitization

`lib/publishing/sanitize-text.ts` — `toSafePlainText` / `toSafeInline`. **No
new dependency** (P2 rule): strips HTML tags + all `<`/`>` + C0/DEL control
characters (keeps `\n`, `\t`). Applied to every `heading` / `body` / title /
excerpt before it reaches a page.

Defence in depth, three layers:
1. write path — `InternalBlogAdapter.validate()` rejects a raw `<script>`;
2. read path — `toSafePlainText` strips markup;
3. render — every value is a React **text child** (`{value}`), auto-escaped.
   **No `dangerouslySetInnerHTML` anywhere** (asserted by a test).

`contentHash` is computed from the **raw** (pre-sanitize) content, so
sanitizing for display never trips the drift check.

## 4. Pages

| route | file | notes |
| --- | --- | --- |
| `/blog` | `app/blog/page.tsx` | Server Component, `revalidate = 300`, static `<title>`/`description`, `canonical: /blog`. Lists `blogReaderService.listPosts()`; empty-state when none. |
| `/blog/[slug]` | `app/blog/[slug]/page.tsx` | `revalidate = 300`; `generateStaticParams` from `listSlugs()`; `dynamicParams` default true so a freshly-published post renders on first request; `notFound()` when the reader returns null. |

`generateMetadata({ params })` (params is a `Promise` in this Next version) →
`title`, `description`, `keywords`, `alternates.canonical`, `openGraph`
(`type: "article"`, `publishedTime`), `twitter` (`summary_large_image`). A
missing post → `{ title: "Article not found", robots: { index: false } }`.

Layout matches the rest of the marketing site (`Navbar` / `Footer` /
`PageHero` / `Disclaimer`).

## 5. Sitemap + robots

`app/sitemap.ts` — adds `${SITE_URL}/blog` and one entry per
`blogReaderService.listSlugs()` post (derived the same way
`generateStaticParams` derives them — no invented URLs; `.catch(() => [])` so a
DB blip never breaks the whole sitemap).

`app/robots.ts` — **unchanged**: it already `allow`s `/` and only disallows
`/dashboard`, `/api`, `/auth`, so `/blog` is indexable.

Canonical URLs (`https://algotraders24.ai/blog/<slug>`) that the whole
pipeline has been computing since P2.1 **stop being 404s**.

## 6. Legacy `Publish now` route — DECIDED: rewired through the engine

`POST /api/private/publishing/articles/[id]/publish` (the dashboard's
"Publish now" button) previously flipped `Article.status = "published"` with
**no `PublishingJob`** → after P2.5 that Article would be **invisible on
`/blog`** (a dead end).

**It now delegates to `publishingService.publishArticleNow(userId, articleId)`:**

```
validateArticle() pre-gate   (unchanged: >=3 sections / disclaimer / >=3 keywords / SEO score >= 70)
      ↓  (422 + issues[] on failure - same shape the dashboard already reads)
createJob({ destination: INTERNAL_BLOG })   (immediate)
      ↓
runAttempt()   →  SUCCEEDED  ⇒  Article -> published inside commitSuccess (drift-safe), post live on /blog
              →  FAILED      ⇒  409 with the adapter's error message
```

- The dashboard button keeps working; its response body changes from
  `{ article }` to `{ job }` (the dashboard only checks `status === "ok"` and
  reloads, so this is invisible to it).
- `articleService.publish()` is now **`@deprecated`** and has no callers.
- **`POST /articles/[id]/schedule`** (legacy direct `status = "scheduled"`
  flip) is **left as-is** — migrating it needs the dashboard to send slot
  values, which is a UI-sprint change. Documented, not touched (no regression
  risk).

## 9. P2.6 recommendation (do NOT start automatically)

**Next: P2.6 — end-to-end + beta verification.** Publishing is now
functionally complete; P2.6 proves the whole path on a running app and closes
the loop.

1. **Full E2E on a running build** (not just services): draft → `POST
   /publish-jobs` (immediate + scheduled) → `POST /dispatch` (cron-secret +
   admin) → `GET /blog` + `GET /blog/[slug]` render the post → `robots.txt` /
   `sitemap.xml` include it → the dashboard "Publish now" button drives the
   rewired route.
2. **Negative E2E:** a scheduled post is absent from `/blog` until its slot;
   a failed job never appears; a cross-user `GET /publish-jobs/:id` → 404.
3. **SEO check:** view-source a live `/blog/<slug>` — `<title>`, meta
   description, canonical `<link>`, OG/Twitter tags present and correct.
4. **The `/schedule` legacy route + dashboard**: decide with the UI sprint
   whether the dashboard "Schedule" control sends a `PublishingSlot` to
   `POST /publish-jobs` (retiring the legacy `status = "scheduled"` flip).
5. **Beta gate:** confirm the daily `0 7 * * *` dispatch cron is live on the
   deployment and `CRON_SECRET` is set.
