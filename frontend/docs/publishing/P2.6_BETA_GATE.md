## 4. Observations (not defects — recorded for awareness)

1. **ISR staleness during testing.** `/blog` (`revalidate = 300`) and
   `/sitemap.xml` are cached. Publishing then deleting a *test* post leaves a
   ≤5-minute window where the list / sitemap reference a slug that now 404s.
   This is a property of ISR + test churn, **not** the engine — genuine
   published content does not get deleted out from under the cache. Takeaway:
   **do not run `validate:publishing-e2e` against the production DB casually**;
   point it at a dev database, or accept the short cache lag.

2. **`next dev` (Turbopack) served `/blog` as 404 in this worktree** — not
   reproduced in the deployed `next build` (which renders `/blog` and
   `/blog/<slug>` perfectly, proven above). The worktree had many mid-session
   branch switches + a symlinked `node_modules`; most likely a stale Turbopack
   route cache. **Recommend:** verify `npm run dev` serves `/blog` from a
   clean checkout before beta. It is not a code defect — same commit, deployed
   = works.

3. **Nav still shows "Blog — SOON".** The `Navbar`/`Footer` link config marks
   Blog as coming-soon; the route is live and directly reachable but not yet
   linked from the site chrome. UI-sprint item (P2.5 §6 already flagged the
   dashboard/schedule coupling as UI-sprint scope).

## 5. Owner confirmations required before flipping the beta switch

Two things can only be checked from the Vercel dashboard, not from here:

1. **`CRON_SECRET` is set in the Vercel project env.** The dispatcher's
   `isValidCronSecret()` needs it; without it, a cron-triggered
   `POST /api/private/publishing/dispatch` returns 401 and **PENDING /
   scheduled jobs never publish** (an admin can still trigger dispatch
   manually). This is the single highest-value config to confirm.

2. **The `0 7 * * *` publishing cron shows as registered** in the Vercel
   project's Cron Jobs list. Hobby allows one run/path/day; `vercel.json` now
   has three daily crons — confirm Vercel accepted all three and the next
   scheduled run for `/api/private/publishing/dispatch` is shown.

Non-blocking follow-ups (UI sprint / product):
- Link `/blog` from the nav (drop the "SOON").
- Migrate the dashboard "Schedule" control to send a `PublishingSlot` to
  `POST /publish-jobs` (retire the legacy `status = "scheduled"` flip).
- Publish the first genuine blog post (the pipeline is proven).
