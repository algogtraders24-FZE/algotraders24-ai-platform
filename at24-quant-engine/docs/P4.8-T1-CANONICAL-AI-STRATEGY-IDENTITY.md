# P4.8-T1 — Canonical AI Strategy Identity

**Status:** Implemented, full 12-item acceptance matrix passing (10 automated tests + 2 structural facts), full regression green. Bounded to the locked T1 scope: deterministic per-user identity for AI-compiled strategies only. No engine changes, no Prisma changes, no historical backfill, no `computeSemanticStrategyHash()` changes.

## 0. Why this phase

P4.8's own investigation-only audit established that a genuine Strategy Library requires stable, logic-based identity — not one tied to `runId`, and not one that changes every time the identical trading logic is recompiled. The audit found that AI-compiled strategies minted a fresh `identity.strategyId = ai-${userId}-${Date.now()}` on every single compile call, meaning two runs of "the same AI strategy" could never be recognized as the same strategy. Registry and MQL-imported strategies never had this problem — their `strategyId` is a fixed, human-assigned literal (`"golden"`, `"ref-ema-crossover"`).

## 1. Decision 1, as originally locked, and why it changed mid-implementation

The lock specified `computeCanonicalIRHash(ir)` as the canonical fingerprint (excludes `strategyId`/`metadata`, already public, already tested). Implementation proceeded exactly per that lock, then failed its own required adversarial test: two compiler inputs describing byte-identical trading logic (same entries/exits/indicators/risk/instruments/timeframes), differing only in the LLM's restated `intent` text and the generated display `name`, produced **different** `strategyId`s.

**Root cause:** `computeCanonicalIRHash` keeps `provenance`, and `StrategyIRProvenance.sourceHash = computeCanonicalHash(input)` where `input` includes the LLM-restated `intent` — so phrasing variance leaked back in through `provenance`, undetected by the original audit (which checked `strategyId`/`metadata` exclusion but not `provenance`).

**Resolution, after a Decision-1 re-audit:** `ir-hash.ts` already contains a second, sibling function — `computeCrossPlatformSemanticHash(ir)` — built for the engine's own MQL4/MQL5 parity requirement (Q0.8.49): "does this describe the exact same trading behavior, regardless of where it came from." It excludes `strategyId`, `strategyVersion`, `sourcePlatform`, `sourceLanguage`, `sourceVersion`, `sourceHash`, `irVersion`, `metadata`, **and `provenance`**. Verified directly against the exact failing adversarial pair before relocking — the hashes matched. This function is already public (same `export *` chain), already tested (`mql-parity.test.ts`, `q11-mql-platform-fixtures.test.ts`), and untouched by this phase. **Net engine changes: 0** — smaller than the originally locked plan, not larger.

## 2. What changed

**`frontend/services/algo-test/nl-strategy-compiler.service.ts`** — `compileNaturalLanguageStrategy()`'s `identity` parameter now takes `userId: string` instead of a caller-supplied `strategyId: string`. Internally: compiles the IR once with a placeholder `strategyId` (irrelevant — `computeCrossPlatformSemanticHash` excludes it entirely), computes the canonical hash on that IR, then builds the real `ir.strategyId = ai-${userId}-${canonicalHash}` before validation/reduction proceeds. Everything downstream (`validateStrategyIRStructure`, `checkReductionEligibility`, `reduceStrategyIRToSpec`) now operates on the final, correctly-identified IR.

**`frontend/services/algo-test/algo-test.service.ts`** and **`frontend/app/api/private/algo-test/compile/route.ts`** — both call sites updated to pass `userId` instead of minting `ai-${userId}-${Date.now()}` themselves. Neither computes identity independently anymore — there is exactly one place `strategyId` construction happens.

**`frontend/scripts/validate-nl-strategy-compiler.ts`** — its fixed `IDENTITY` constant updated to the new shape (`userId` instead of `strategyId`); no assertion in that file depended on the specific `strategyId` value, so this is a pure signature-compatibility update.

**Nothing else changed.** No Prisma migration. `computeSemanticStrategyHash()` is untouched. Golden/MQL-imported strategies never call `compileNaturalLanguageStrategy` at all — a structurally separate code path, unaffected.

## 3. The disclosed, NOT-fixed asymmetry — `strategyId` vs `strategyHash`

Per the locked stop condition, this phase deliberately does **not** make the existing, persisted `AlgoTestRun.strategyHash` (`computeSemanticStrategyHash(spec)`) deterministic across phrasing variance. `StrategySpec` has no `provenance` field to lean on, and `computeSemanticStrategyHash` keeps `identity` (which includes `name`) in its hash input — so the exact adversarial pair that now shares a `strategyId` still produces two **different** `strategyHash` values. Measured directly, not assumed — see test 10 below. `strategyId` (the new logical-library identity) and `strategyHash` (the existing, unmodified persisted fingerprint) are deliberately two different concepts answering two different questions, exactly as scoped.

## 6. Known limitations / explicitly deferred

- `strategyHash` (`computeSemanticStrategyHash`) still varies with `identity.name`/phrasing for AI-compiled strategies — disclosed in §3, not fixed here. A future phase could revisit whether `StrategySpec.identity.name` belongs in that hash at all, but that is a change to an existing, widely-relied-on function shared by every strategy source, explicitly out of this phase's bounded scope.
- `/compile` (the preview-only route) remains unwired to any UI — a pre-existing, orphaned P4-Phase-1 surface, unrelated to this phase, not touched.
- No Strategy persistence model, no Strategy Library UI, no run aggregation — all explicitly P4.8-T2+.
