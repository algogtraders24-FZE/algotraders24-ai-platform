# Q0.8 MQL AST

## Deliberately minimal (Q0.8.5)

`domain/mql-importer/ast.ts` defines exactly the declaration/statement/expression node kinds Q0.8.5 enumerates as a MINIMUM — not a complete C/C++ grammar. Declarations: `IncludeDirective`/`DefineDirective`/`PropertyDirective` (preprocessor, Q0.8.4), `InputDeclaration`, `GlobalVariableDeclaration`, `StructDeclaration` (shallow — field list only, no methods), `FunctionDeclaration`. Statements: `BlockStatement`, `IfStatement`, `ReturnStatement`, `ExpressionStatement`, `VariableDeclarationStatement`, `ForStatement`. Expressions: `Literal`, `Identifier`, `UnaryExpression`, `BinaryExpression`, `AssignmentExpression`, `CallExpression`, `MemberExpression`, `IndexExpression`, `ConditionalExpression` (ternary). Every node carries its own `position: SourcePosition` (Q0.8.3/43's source-to-IR trace requirement).

## `switch`/`while`/`do-while`: skip-recovery, not first-class nodes

Q0.8.5's own minimal statement list omits these three — rather than crash on them or force an incomplete implementation, `parser.ts`'s `skipRecoveryStatement()` consumes the construct's balanced-brace body (or single trailing statement, for a brace-less form) structurally and emits an `UnparsedStatementNode` plus a WARNING diagnostic (`UNPARSED_STATEMENT`) naming exactly what was skipped. This is proven safe against the real G01 fixture: its one `switch` statement (mapping a deal-close reason enum to a CSV label string) sits entirely inside `OnTradeTransaction`'s pure-telemetry code path — never signal-relevant — so skipping it costs nothing semantically, and the position is preserved for a future sprint to promote `switch` to a first-class node if a later fixture needs it.

## Comma-separated multi-declarators (`VariableDeclarator`)

A real pattern found in G01 (`SBar prevDay,prevWeek;`, `SBar candle1,candle3;`) that a naive single-name declaration node cannot represent. Both `VariableDeclarationStatementNode` and `GlobalVariableDeclarationNode` carry `declarators: readonly VariableDeclarator[]` (`{name, isArray, initializer?}`) rather than a single `name`/`initializer` pair — discovered and fixed BEFORE any downstream code (semantic analyzer, IR generator) depended on the old shape, so this was a clean AST redesign, not a migration.

## C-style casts: conservative detection, documented false-negative

`(long)PositionGetInteger(...)` and `(ENUM_DEAL_REASON)HistoryDealGetInteger(...)` (both real G01 patterns) must be distinguished from a plain parenthesized expression like `(INIT_FAILED)` in a `return` statement — MQL's grammar is genuinely ambiguous here without a real type-symbol table, which this sprint's AST does not build. The chosen heuristic (`parser.ts`'s `parsePrimary()`) recognizes a cast target only when it is a `TYPE_KEYWORDS` member (int/long/double/string/etc.) OR matches MQL's own `/^ENUM_[A-Z0-9_]+$/` naming convention, AND the following token cannot be a binary-operator continuation. This correctly handles every cast in the real G01 file; a cast to an arbitrary custom struct/class name (rare in practice, absent from G01) is NOT auto-detected and instead parses as a plain parenthesized expression — a documented, low-risk false negative rather than a false positive that would misparse a legitimate parenthesized expression as a bogus cast.

## What Q0.8 does NOT do

No full expression-statement-level type inference (the AST has no symbol table beyond the flat `MQLSourceDocument.symbolTable` name→kind map). No loop-body deep semantic analysis (`for` loops parse fully — a real requirement, since G01's position-scanning loops use them — but their bodies are walked the same as any other statement, with no special "this is a loop" semantic treatment). No preprocessor macro EXPANSION (`#define` is recorded as a name/value pair, never substituted into subsequent tokens — Q0.8.4's explicit "do NOT implement a full C/C++ preprocessor" boundary).
