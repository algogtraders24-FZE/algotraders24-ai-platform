# Q0.2 Contract Freeze

Audit of the Q0-established contracts before Q0.2 added functionality, per Q0.2.1. Contracts frozen by Q0: `StrategySpec`, `Expression`, `MarketData`, `MarketState`, `Signal`, `Decision`, `OrderIntent`, `Position`, `RiskSpecification`, `ExecutionSpecification`, `BacktestConfig`, `BacktestResult`, `ReproducibilityMetadata`, `StrategyVersionRecord`.

## Unchanged (no modification)

`StrategySpec`'s own shape, `MarketData` (`Instrument`/`OHLCVBar`/`MarketDataSeries`/`Timeframe`), `Signal`, `Decision`, `OrderIntent`, `Position`, `BacktestConfig`, `BacktestResult`, `ReproducibilityMetadata`, `StrategyVersionRecord`'s public API (`freezeStrategyVersion`/`verifyStrategyVersionIntegrity` behave identically to Q0).

## Changed

### 1. `Expression.ComparisonOperator` — additive

**OLD**: `">" | ">=" | "<" | "<=" | "==" | "!="`
**NEW**: `">" | ">=" | "<" | "<=" | "==" | "!=" | "cross_above" | "cross_below"`
**WHY**: Q0.1 identified `cross_above`/`cross_below` as OLD's one genuine structural expressiveness edge over NEW; Q0.2.2 requires closing it.
**COMPATIBILITY IMPACT**: None — purely additive to a union type. Every existing `ComparisonExpression` value remains valid; no existing code path changes behavior.
**TEST IMPACT**: None to existing tests (all 40 Q0 tests still pass unmodified). New coverage in `test/cross-operators.test.ts`.

### 2. `MarketState` — additive field

**OLD**: `{ instrument, timeframe, asOf, bars, indicatorValues }`
**NEW**: adds `previousIndicatorValues?: ReadonlyMap<string, number | boolean>`
**WHY**: `cross_above`/`cross_below` require an explicit prior observation to evaluate deterministically (Q0.2.2's mandate: "must use explicit previous/current observations", never "currently above" ambiguity). Rather than have the evaluator carry hidden history state (which would break `evaluateExpression`'s current pure-function-of-`(expr, state)` signature and complicate every future caller), the prior observation is carried on `MarketState` itself, optionally.
**COMPATIBILITY IMPACT**: None — optional field, absent by default. Every existing `MarketState` value (all of Q0's tests construct these without the new field) remains valid and behaves identically. `cross_above`/`cross_below` against a `MarketState` lacking this field deterministically evaluate to `false` (see Q0.2.2 semantics below) rather than throwing, so old test fixtures are unaffected even if a spec happened to use a cross operator against them.
**TEST IMPACT**: None to existing tests. New coverage in `test/cross-operators.test.ts` and `test/failure-modes.test.ts`.

### 3. `RiskSpecification` — additive fields

**OLD**: `sizing`, `maxPositionSize?`, `maxExposure?`, `stopLoss?`, `takeProfit?`
**NEW**: adds `breakeven?`, `trailingStop?`, `partialClose?`, `sessionHours?`, `maxHoldingPeriod?`, `maxSimultaneousPositions?`, `dailyLossLimit?` (all optional; new supporting types `DistanceSpec`, `BreakevenRule`, `TrailingStopRule`, `PartialCloseRule`, `SessionWindow`, `SessionHoursRule`, `MaxHoldingPeriodRule`, `DailyLossLimit`)
**WHY**: Q0.1 identified these as OLD's genuine risk-management sophistication that NEW lacked (breakeven/ATR-trailing/partial-close/daily-loss-halt/session-hours from `quant_engine/engine.py`'s `RiskConfig`). Q0.2.8 requires designing (not building an evaluator for) these fields.
**COMPATIBILITY IMPACT**: None — all new fields optional. `validateRiskSpecification()` extended with new validation branches, but every branch is gated on the corresponding field being present, so a Q0-era `RiskSpecification` validates identically to before.
**TEST IMPACT**: None to existing tests (explicit backward-compatibility test added: "all Q0-original risk fields still validate exactly as before"). New coverage in `test/risk-specification-extended.test.ts`.

### 4. `ExecutionSpecification` — additive fields, and a rename to avoid a naming collision

**OLD**: `fillModel: FillModel`, `slippage?: SlippageModel`, `spread?: SpreadModel`, `commissionPerUnit?: number`
**NEW**: adds `fee?: FeeAssumption`, `latency?: LatencyAssumption`, `priceBasis?: PriceBasis`, `marginAssumption?: MarginAssumption`, `costsExplicitlyZero?: true`; and **renames** the exported type aliases `FillModel` → `FillModelKind`, `SlippageModel` → `SlippageAssumption`, `SpreadModel` → `SpreadAssumption` (the field names `fillModel`/`slippage`/`spread` on `ExecutionSpecification` itself are UNCHANGED — only the exported TYPE ALIAS names changed).
**WHY (additive fields)**: Q0.2.15 requires an explicit contract for fee/latency/price-basis/margin, and an explicit guard against silently assuming zero execution costs.
**WHY (rename)**: Q0.2.16 mandates a new behavioral-interface family named exactly `FeeModel`/`SpreadModel`/`SlippageModel`/`FillModel`/`MarginModel`/`LatencyModel` (see `reality-models.ts`). Those names collided with the pre-existing static config-shape type aliases in `execution-specification.ts`. Rather than compromise the Q0.2.16-mandated interface names, the OLDER, less-constrained static config aliases were renamed to an `*Assumption`/`*Kind` suffix, consistent with the already-existing `LatencyAssumption`/`MarginAssumption` naming.
**COMPATIBILITY IMPACT**: The new fields are additive and optional (no impact). The rename changes exported TYPE NAMES only — no field on any value changes, no runtime behavior changes, and nothing outside this package imported those type names (confirmed: `at24-quant-engine` has no external consumers yet, per Q0.1's usage audit). Also added a new function, `validateExecutionSpecification()`, which did not exist in Q0 at all (pure addition, nothing to break).
**TEST IMPACT**: None to existing tests. New coverage in `test/execution-specification.test.ts`.

## Deliberately NOT changed, despite temptation

- **`StrategyVersionRecord.contentHash`** still hashes the *entire* spec, including `metadata.createdAt`. Q0.2.10 requires a hash that excludes non-semantic metadata for *research identity* purposes — but changing `freezeStrategyVersion()`'s existing behavior would be a breaking change to a frozen contract for no compatibility gain (its job — detecting ANY mutation of a frozen record, including a metadata edit — is different from and equally valid to "semantic equivalence"). Instead, Q0.2 adds a **separate, new function**, `computeSemanticStrategyHash()` (`runtime/identity.ts`), for the research-identity use case. Both hashes coexist; callers pick whichever matches their actual question ("did this record change at all" vs. "is this the same strategy semantically").
- **`IndicatorReference`** was not given a `version` field, even though Q0.2.10 asks for "indicator versions" as part of composite identity. Threading a version pin through `Operand`/`Expression` (a frozen contract) would have been a much larger, riskier change for a benefit fully achievable by passing an explicit `indicatorVersions` map alongside the spec at hash-computation time (see `computeStrategyIdentityHash()`). `IndicatorReference` itself is not in Q0's frozen-contract list, so this was a free choice, not a forced one — made in favor of the smaller blast radius.
