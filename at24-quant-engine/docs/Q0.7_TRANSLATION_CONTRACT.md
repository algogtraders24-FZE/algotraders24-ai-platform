# Q0.7 Translation Contract

## The pipeline (Q0.7.37) and where Q0.7 stops

```
parse/import           <- NOT built (SourceParser interfaces are stubs)
    v
semantic validation     <- validateStrategyIR() (this sprint)
    v
canonicalization        <- canonicalizeStrategyIR() (this sprint)
    v
IR validation            <- validateStrategyIR() again, on the canonical form (idempotent — see below)
    v
execution compatibility   <- computeExecutionCompatibility() (this sprint)
    v
simulation                 <- Q0.5/Q0.6, UNMODIFIED — reached only via a future IR-to-StrategySpec reducer, NOT built in Q0.7
```

**A parser must never directly create executable orders (Q0.7.37's explicit rule).** Concretely: nothing in `src/runtime/strategy-ir/` calls `runSimulation()`/`runMultiFidelitySimulation()` (Q0.5/Q0.6) or constructs a `SimulationOrder`. The boundary between "this IR is valid and execution-compatible" and "an actual simulation runs it" is the still-unbuilt IR→StrategySpec reducer `docs/Q0.4_STRATEGY_IR.md` always anticipated as a separate, future semantic-reduction step.

## computeCanonicalIRHash (Q0.7.34)

Excludes `strategyId` and `metadata` (which carries `createdAt`/`description`/`author`/`tags`) — the identical exclusion discipline as Q0.2's `computeSemanticStrategyHash`, applied one layer up. Everything else — including `sourcePlatform`/`sourceHash`/`sourceVersion`/`irVersion`/`provenance` — participates in the hash: these are facts ABOUT the IR (Q0.7.1's required identity fields), not decorative metadata, so two IRs from genuinely different platforms are EXPECTED to hash differently even when their trading logic is equivalent. `compareParity()` (`docs/Q0.7_PARITY_MODEL.md`), not hash equality, is the tool for detecting cross-platform semantic equivalence.

## canonicalizeStrategyIR / canonicalizeExpression (Q0.7.36)

STRUCTURAL reordering only, never algebraic simplification: `A AND B` and `B AND A` canonicalize to the identical operand order (commutative, order-independent) and therefore hash identically; a comparison's `left`/`right` are NEVER reordered (not commutative — `A > B` stays structurally distinct from the logically-equivalent `B < A`); `A AND A` is never reduced to `A`. `test/strategy-ir-hash-canonicalization.test.ts` and `test/strategy-ir-failure-catalog.test.ts` item 18 prove both the reordering AND the refusal to simplify. Canonicalization is IDEMPOTENT (`canonicalize(canonicalize(x)) === canonicalize(x)`, `test/strategy-ir-roundtrip.test.ts`) and lossless across a JSON serialization boundary.

## ExecutionCompatibilityReport (Q0.7.39)

`computeExecutionCompatibility(ir, targetFidelity)` (`runtime/strategy-ir/execution-compatibility-engine.ts`) checks a StrategyIR's declared features against what `runtime/simulation/simulation-engine.ts` (Q0.5, frozen) and `runtime/fidelity/multi-fidelity-engine.ts` (Q0.6, frozen) actually implement TODAY — every row traces to a specific fact already documented in `docs/Q0.5_EXECUTION_MODEL.md`/`docs/Q0.5_POSITION_ACCOUNT.md`/`docs/Q0.6_D2_D3_EXECUTION.md`, not a guess. Concretely SUPPORTED: all four `OrderTypeIR` values, `STOP_LOSS`/`TAKE_PROFIT`/`TIME_EXIT`/`RISK_EXIT`, `NETTING` accounting. Concretely UNSUPPORTED today: `atr-based` position sizing (Q0.5's `resolvePositionSize()` throws explicitly), `SIGNAL_EXIT`/`SESSION_EXIT` (Q0.5 never evaluates `StrategySpec.exitRules`, and no forced-exit-at-session-end evaluator exists), `HEDGING` accounting mode, a genuine `HIGHER`-role dual-timeframe strategy at any fidelity, and `LOWER`-role execution detail specifically when `targetFidelity` is `D1_OHLC` (it IS supported at `D2_LOWER_TIMEFRAME`/`D3_M1`).

## What Q0.7 does NOT do

No IR→StrategySpec reducer (the actual translation-contract fulfillment — explicitly the next architectural boundary, not this sprint's job). No parser calls any of this pipeline with real source text. No caching/memoization of validation or compatibility results (every call recomputes from scratch — correctness first, matching every prior sprint's stated priority).
