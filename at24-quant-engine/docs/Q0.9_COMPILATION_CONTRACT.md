# Q0.9 Compilation Contract

`compileStrategy(ir, targetFidelity = "D1_OHLC")` (`src/runtime/reduction/compilation.ts`) is the single entry point that turns a `StrategyIR` into a `StrategyCompilationResult`:

```ts
interface StrategyCompilationResult {
  readonly ir: StrategyIR;
  readonly strategySpec?: StrategySpec;       // absent iff BLOCKED
  readonly reductionReport: ReductionResult;    // status, diagnostics, semanticLoss, approximations, sourceTrace
  readonly validationReport: ValidationResult;  // Q0.7's validateStrategyIR(ir)
  readonly compatibilityReport: ExecutionCompatibilityReport; // Q0.7's computeExecutionCompatibility(ir)
  readonly resultHash: string;                  // computeCompilationHash(ir, reductionReport)
}
```

## The compilation hash

`computeCompilationHash(ir, reduction)` combines four inputs via `computeCanonicalHash` (Q0's own canonicalizing hasher, unmodified):

1. `computeCanonicalIRHash(ir)` — Q0.7's full-identity IR hash (unaffected by `strategyId`/non-semantic metadata, per Q0.7.34).
2. `computeSemanticStrategyHash(reduction.strategySpec)` if present, else `null` — Q0's own StrategySpec hash, which strips `metadata` but keeps `identity` (including `strategyId` and `identity.name`, both genuinely semantic — see `test/q09-compilation.test.ts`).
3. `REDUCER_VERSION` (currently `"0.1.0"`) — so a future change to the reduction algorithm itself changes every previously-compiled strategy's hash, rather than silently reusing a stale one.
4. `reduction.status` — `"REDUCED"`, `"REDUCED_WITH_WARNINGS"`, or `"BLOCKED"` are distinct compiled identities even for the same IR.

Deliberately excluded: timestamps, `createdAt`, and any other non-semantic metadata — two compilations of the identical strategy at different times produce the identical hash (`test/q09-compilation.test.ts`, `test/q09-mql-e2e-golden.test.ts` reproducibility tests).

## Two hashes, two questions (extending Q0.8's pattern one layer further)

| Hash | Answers |
|---|---|
| `computeCanonicalIRHash(ir)` (Q0.7) | "Is this the same imported strategy, semantically?" |
| `computeSemanticStrategyHash(spec)` (Q0) | "Is this the same executable StrategySpec?" |
| `computeCompilationHash(ir, reduction)` (Q0.9) | "Is this the same *compiled* artifact — same IR, same reducer version, same reduction outcome?" |
| `simulationResultHash` (Q0.5/Q0.6, surfaced in `CompilationSimulationResult`) | "Is this the same simulated *outcome*?" |

A `CompilationSimulationResult` carries all of: `compilationHash`, `strategySpecHash`, `simulationResultHash`, `fidelity`, and `provenance` — enough to answer "which exact strategy, compiled how, run how, with what result" from the result object alone, with no external state.

## BLOCKED compilations are still first-class results

`compileStrategy()` never throws for a BLOCKED IR — it returns a `StrategyCompilationResult` with `strategySpec: undefined`, a full `reductionReport` explaining why, and a `resultHash` that still uniquely identifies "this IR, blocked, for these reasons" (so re-compiling a permanently-blocked strategy like G01 is itself deterministic — `test/q09-g01-reduction.test.ts`). Only `compileToSimulation()` throws, and only because there is no `StrategySpec` to simulate at all — see `docs/Q0.9_SIMULATION_BRIDGE.md`.
