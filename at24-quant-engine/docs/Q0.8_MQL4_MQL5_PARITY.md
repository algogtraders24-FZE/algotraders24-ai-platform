# Q0.8 MQL4/MQL5 Parity

## Dialect detection (Q0.8.7) — from constructs, never filename

`detectDialect()` (`runtime/mql-importer/dialect-detector.ts`) checks for MQL5-only event functions (`OnInit`/`OnDeinit`/`OnTick`/`OnTimer`/`OnTrade`/`OnTradeTransaction`/`OnBookEvent`/`OnChartEvent`) versus MQL4-style bare `init`/`start`/`deinit`. An explicit `forcedDialect` parameter always wins (for callers who already know, e.g. a `.mq4`/`.mq5` file-extension convention upstream of this package) — but the DEFAULT path never consults the filename at all, satisfying Q0.8.7's explicit rule. Ambiguous/neither-present sources default to MQL5 with confidence honestly reported as `"DEFAULTED"`, never silently upgraded to `"CONSTRUCT_BASED"`.

## Two hash functions, two different questions (Q0.8.49)

Q0.7's `computeCanonicalIRHash()` (`docs/Q0.7_TRANSLATION_CONTRACT.md`) deliberately INCLUDES `sourcePlatform`/`sourceHash`/`sourceVersion` — two IRs from different platforms are expected to hash differently even with identical trading logic, since that hash certifies "is this the exact same IR record." Q0.8.49 asks a genuinely different question — "does this describe the exact same trading behavior, regardless of where it came from" — which needs a NARROWER hash. `computeCrossPlatformSemanticHash()` (additively extending `runtime/strategy-ir/ir-hash.ts`, Q0.7's own module, not a parallel one) excludes every identity/origin field (`strategyId`, `strategyVersion`, `sourcePlatform`, `sourceLanguage`, `sourceVersion`, `sourceHash`, `irVersion`, `metadata`, `provenance`) and hashes only what remains — the genuinely semantic fields (entries, exits, risk, position management, timeframes, etc.).

`test/mql-parity.test.ts` proves this concretely: an MQL4 `OrderSend(_Symbol,OP_BUY,...)` and an MQL5 `CTrade.Buy(...)` source, both describing the same 0.1-lot BUY with SL/TP and a 1%-risk input, produce DIFFERENT `computeCanonicalIRHash()` values (platform identity differs, as expected) but the IDENTICAL `computeCrossPlatformSemanticHash()` value. A genuine semantic difference (BUY vs. SELL) is NOT masked by the narrower hash — changing one side's direction changes the semantic hash too.

## `compareParity()` reused, not reimplemented, for MQL4/MQL5

Q0.7's `compareParity()` (`docs/Q0.7_PARITY_MODEL.md`) works unmodified for MQL-imported IRs — `test/mql-parity.test.ts` calls it directly on the equivalent MQL4/MQL5 pair, confirming zero differences on `entries`/`risk` (the two platforms agree completely on trading logic) while the overall `identical` flag is `false` (full-IR hash differs on platform identity, exactly as `docs/Q0.7_PARITY_MODEL.md` documents `identical` should behave).

## G01 hand-built vs. imported parity (Q0.8.46)

A hand-built `StrategyIR` for G01 (`test/mql-parity.test.ts`'s `buildHandBuiltG01IR()`, representing what a careful human analyst reading the same source would record) agrees with the AUTOMATED import on every core structural dimension: instruments, timeframes, entry/exit counts, risk sizing method, and — critically — BOTH independently arrive at `executionEligible: false`, because the state-machine representational gap is real (a limitation of Q0.7's IR itself, not a parser shortfall). The one deliberate, documented difference (the hand-built version claims `semanticStatus: "APPROXIMATED"` with an explicit accounting-mode `ApproximationRecord`, reflecting a human's slightly higher confidence that a fresh MT5 account defaults to netting; the automated importer stays at `"UNSUPPORTED"` with only a WARNING-level note) is explicitly surfaced by `compareParity()`, never silently absorbed.

## Real platform facts this sprint's fixtures encode

- MQL4's `OrderSend` is a single flat call carrying `(symbol, cmd, volume, price, slippage, stoploss, takeprofit, comment, magic, expiration, color)` — `cmd` (`OP_BUY`/`OP_SELL`/`OP_BUYLIMIT`/etc.) is the ONLY place order side/type is expressed; `semantic-analyzer.ts` extracts `side` from it when the constant is a recognizable literal, leaving it `undefined` (never guessed) when it is a runtime-computed expression (`test/mql-failure-catalog.test.ts` item 10).
- MQL5's `CTrade::Buy`/`CTrade::Sell` carry `(volume, symbol, price, sl, tp, comment)` — positionally distinct from `OrderSend`'s layout; the analyzer's argument-index mapping for each is independently correct (verified against both the real G01 file and the synthetic MQL4/MQL5 fixture pair).
- A literal `0`/`0.0` SL or TP argument means "not set for this leg" by MQL's own convention, not "a stop-loss of exactly zero" — `ir-generator.ts`'s `isMeaningfulPriceExpr()` treats it as absent, a real bug this sprint's own failure-catalog testing caught and fixed (previously, ANY non-empty string — including the literal `"0.0"` — was treated as "SL/TP present").

## What Q0.8 does NOT do

No MQL4-vs-MQL5 STANDARD LIBRARY diffing beyond what the fixtures above exercise (e.g. no exhaustive catalog of every function that exists in one dialect but not the other). No automatic dialect CONVERSION (MQL4 source is never rewritten as MQL5 or vice versa — only independently imported and compared as IR).
