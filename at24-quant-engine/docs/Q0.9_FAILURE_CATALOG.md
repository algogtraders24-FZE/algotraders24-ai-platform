# Q0.9 Failure Catalog

The 24 required failure modes for the reduction/compilation/simulation-bridge layer, each proven with a concrete test in `test/q09-failure-catalog.test.ts`. Distinct from Q0.8's `docs/Q0.8_FAILURE_CATALOG.md` (MQL parsing/semantic-analysis level) — this catalog is entirely about what happens AFTER a `StrategyIR` already exists: can it be reduced, compiled, and simulated honestly. Numbering matches the test file exactly.

## Structural and eligibility failures (1-6, 15)

1. **Invalid IR** — an IR failing `validateStrategyIR()` is never even reduced; `reduceStrategyIRToSpec` returns `BLOCKED` immediately.
2. **Missing expression** — an entry with no provable condition (the honest placeholder) is blocking via the `"entry/exit signal logic"` unsupported semantic, never defaulted to always-true.
3. **Unsupported indicator** — a generic (non-named) indicator, or MACD/BOLLINGER_BANDS (multi-output), blocks at the simulation-adapter boundary with an explicit reason.
4. **Unsupported order** — non-MARKET `executionType`s pass through structurally (Q0.5/Q0.6's own concern to execute correctly); the reducer never re-validates order-type-specific behavior it doesn't own.
5. **Unsupported timing** — any entry timing other than `NEXT_BAR_OPEN` is blocking.
6. **Unsupported MTF** — a `HIGHER`-role timeframeSeries is blocking (genuine dual-timeframe calculation is deferred).
15. **Invalid position mode** — `HEDGING` accountingMode is blocking; Q0.5/Q0.6 implement `NETTING` only.

## Data and timing failures (7, 9, 14)

7. **Future data** — an insufficient-bars-for-warmup condition throws an explicit `"insufficient bars for indicator warmup"` error rather than silently reading past (or before) the available series — see `docs/Q0.9_SIMULATION_BRIDGE.md`'s warmup fix.
9. **Unknown/ambiguous timezone** — a disclosed WARNING-level assumption (broker/local time) is NOT itself blocking, distinguishing a disclosed assumption from an actual eligibility failure.
14. **Unresolved dependency** — a declared dependency timeframe is a Q0.7-level structural concern, not re-invented at the reduction layer.

## Repainting and semantic-loss failures (8, 12, 13)

8. **Repainting** — a `REPAINTING` `repaintingModel` is blocking regardless of any other property.
12. **Semantic loss** — a `SEMANTIC_EQUIVALENT` strategy (a real, disclosed platform-mapping choice) can still independently block for an unrelated eligibility reason — semantic-loss disclosure and execution eligibility are independent axes.
13. **Unresolved state** — an `UNSUPPORTED` semanticStatus with a BLOCKING unsupported-semantic entry blocks reduction (the G01-style case, generalized).

## Risk and execution integrity (10, 11)

10. **Invalid risk** — a StrategySpec that would fail Q0's own `validateStrategySpec()` (e.g. negative sizing quantity) causes the reducer to return `BLOCKED` before that invalid spec can ever reach the simulation engine.
11. **Invalid execution** — `execution.declared` is passed through by direct reference; a structurally invalid one is caught by `validateStrategySpec`, never silently accepted.

## Identity, determinism, and purity (16, 17, 19, 24)

16. **Compilation hash mismatch** — two structurally-different eligible IRs never share a `resultHash`.
17. **Mutation attempt** — `reduceStrategyIRToSpec`/`compileStrategy`/`compileToSimulation` never mutate any input object (IR, bars) passed to them.
19. **Result nondeterminism** — compiling and simulating the same real MQL5 source twice produces byte-identical `compilationHash` and `simulationResultHash`.
24. **Compilation hash purity** — `computeCompilationHash(ir, reduction)` called twice on the same pair always returns the same string.

## Adapter and cross-dialect integrity (18, 22)

18. **Simulation adapter mismatch** — the `indicatorKey()` the adapter uses to populate `SimulationConfig.indicatorSeries` always matches the key an `Expression`'s `indicatorOperand()` would reference — never a silent lookup miss that would leave a `MarketState` field undefined.
22. **MQL4/MQL5 parity mismatch** — the same strategy shape written in both dialects reduces to StrategySpecs with matching risk/entry-direction semantics (full coverage in `test/q09-parity.test.ts`, including a deliberately-introduced mismatch that IS correctly detected).

## Real-world negative case (20)

20. **G01 state-machine blocking** — the real G01 EA compiles to `BLOCKED` (full coverage in `docs/Q0.9_G01_REDUCTION.md` / `test/q09-g01-reduction.test.ts`); this catalog entry is the cross-reference proving the same guarantee holds at the failure-catalog level, not just in a dedicated test file.

## Real-world positive and provenance cases (21, 23)

21. **Invalid MQL4/MQL5 strategy** — a syntactically-recoverable but semantically-empty source (no entries at all) yields a structurally-valid but execution-ineligible IR — never a crash, never a fabricated entry.
23. **Missing source provenance** — an IR with a placeholder (all-zero) `sourceHash` still compiles without throwing; provenance completeness itself is Q0.7's own validator's concern, not re-invented at this layer.

## What Q0.9's catalog does NOT do

No performance/load failure modes (this sprint's `scripts/benchmark-reduction.ts` is measurement-only, per Q0.2.22's own "correctness-first, no thresholds" convention). No fuzzing harness — all 24 items are hand-selected from this sprint's own specification and the real G01/MQL5/MQL4 fixtures' actual content.
