# Q0.8 Failure Catalog

The 28 required failure modes (Q0.8.52), each proven with a concrete test in `test/mql-failure-catalog.test.ts`. Grouped here by theme; numbering matches the test file exactly.

## Parsing (1-3)

1. **Malformed syntax** — an unbalanced `if(` recovers via diagnostics, never an unhandled exception.
2. **Unknown token** — a genuinely unrecognized character (`@`) is tokenized, never silently dropped.
3. **Unsupported directive** — `#pragma once` (not `#include`/`#define`/`#property`) produces a WARNING, never a silent skip.

## Identifiers, indicators, shifts (4-9)

4. **Unresolved identifier** — a call to neither a built-in nor a locally-defined function is recorded as `UNRESOLVED_CROSS_FILE_CALL`, never silently trusted.
5/13. **Invalid indicator** (`iCustom`, two catalog entries per Q0.8.52's own numbering) — flagged `ICUSTOM`, never guessed at as a named family.
6. **Invalid shift** — a variable (non-literal) index is `NON_LITERAL_SHIFT`, never assumed safe.
7. **Future shift** — `Close[-1]` is `FUTURE_SHIFT_REJECTED`, BLOCKING, never clamped.
8. **Invalid timeframe** — an unrecognized `PERIOD_*` constant is simply not added to `timeframes`, never force-mapped.
9. **Invalid symbol** — a non-standard symbol string is still recorded verbatim, never rejected or crashed on.

## Orders and execution dependencies (10-15, 20-23)

10. **Ambiguous order** — an `OrderSend` command that can't resolve to BUY/SELL leaves `side` unset.
11. **Unsupported order** — a lookalike function name is never fabricated into an `OrderCallSite`.
12/14. **Unsupported external dependency / DLL** — `#import "x.dll"` flagged as `UNSUPPORTED_PREPROCESSOR`.
15. **WebRequest** — flagged `WEBREQUEST`, never executed or simulated.
20. **Dynamic execution** — an order whose volume comes from an unresolved cross-file call is recorded as such, never trusted as a literal.
21/22. **Invalid SL / invalid TP** — a literal `0`/`0.0` leg is recorded exactly as written (and, per `docs/Q0.8_MQL_EXECUTION_MAPPING.md`, treated as "not set," never as a real value).
23. **Invalid position sizing** — no risk-percent-named input → `fixed-quantity` default, never an invented percentage.

## Repainting, timezone, account mode, trade events (16-19)

16. **Repainting** — a strategy signaled by an unresolved `iCustom` is never independently certified `NON_REPAINTING`.
17. **Ambiguous timezone** — `TimeLocal()` is BLOCKING, never silently UTC.
18. **Ambiguous account mode** — always WARNING-flagged as assumed, never asserted as fact.
19. **Unsupported trade event** — `OnTradeTransaction` (pure telemetry in the real G01 case) is recognized without being treated as BLOCKING when it doesn't feed signal logic.

## State, MTF, identity, comparison (24-28)

24. **Hidden state** — a write-only global is still tracked (never dropped for lack of a corresponding read) — this item's own test caught and fixed a real double-counting bug (an assignment target was briefly also recorded as a read).
25. **MTF future leak** — a `HIGHER`-timeframe reference with no provable OR plausible new-bar gate is BLOCKING — this item's own test caught a real gap (the MTF check originally missed `iClose`-style series-reference timeframes entirely).
26. **Source hash mismatch** — Q0.7's own `validateStrategyIR()` (reused unmodified) rejects a tampered `provenance.sourceHash`, proving the same protection extends to MQL-imported IRs.
27. **IR parity mismatch** — `compareParity()` surfaces a deliberately introduced SL/TP-presence difference between two otherwise-similar imports — this item's own test caught the literal-zero-SL/TP bug described above (both imports initially looked identical because "0.0" was wrongly treated as "present").
28. **Parser nondeterminism** — the real 660-line G01 source (not just small synthetic snippets) parses to a byte-identical AST and diagnostic list across repeated calls.

## Bugs this catalog itself caught (a genuine testing success, not a footnote)

Three of the 28 items (10/21/22's underlying extraction logic, 24, and 25/27) directly caught real defects during this sprint's own development — fixed before the catalog was finalized, not before it existed. This is the pattern the catalog exists to produce: writing the failure-mode test FIRST surfaces the bug, not the other way around.

## What Q0.8 does NOT do

No performance/load failure modes (parsing a single EA file is not a scale concern this sprint addresses). No fuzzing harness (the 28 items are hand-selected from Q0.8.52's own list and the real G01 fixture's actual content, not randomly generated inputs).
