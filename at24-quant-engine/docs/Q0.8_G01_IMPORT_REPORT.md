## The central, honest finding

G01's actual entry/exit logic — Liquidity Sweep → Displacement → Market Structure Shift → Fair Value Gap → Retest → Entry — is a **multi-bar state machine** (`ENUM_G01_STATE`) spanning several `#include` modules. Q0.7's `StrategyIR` has no representation for cross-bar state machines (a documented, deliberate scope boundary — `docs/Q0.7_STRATEGY_IR.md`). Per Q0.8's own critical success criterion ("if AT24 cannot faithfully represent something: DO NOT GUESS. Report it. If the difference can materially change backtest results: BLOCK execution."), the importer emits entries with an honest placeholder condition (`1 == 0`, always false) paired with a BLOCKING `UnsupportedSemantic` naming exactly what could not be represented and why.

**Result: `validateStrategyIR(g01Ir).executionEligible === false`.** This is the CORRECT outcome, not a failure of the importer — it is proof the whole Q0.7→Q0.8 pipeline works as designed: real, complex source is parsed and analyzed faithfully, and the one thing that cannot yet be honestly represented is blocked, never silently fabricated.

## Source-level surprises this fixture caught (fixed before shipping)

1. `input group "Section Title"` has no trailing semicolon in real MQL5 (undocumented-by-example syntax quirk) — see `docs/Q0.8_MQL_AST.md`.
2. Comma-separated multi-declarators (`SBar prevDay,prevWeek;`) required an AST shape change (`declarators` array) before this sprint's downstream code existed to depend on the old shape.
3. The MTF-availability check originally only scanned `symbolTimeframeSites`, missing `iClose`-style series-reference-based timeframe mentions entirely (G01's real M15 usage) — fixed (`docs/Q0.8_MQL_LOOKAHEAD.md`).
4. A literal `0.0` SL/TP argument was initially treated as "present" (any non-empty string), incorrectly attaching phantom exits to orders that deliberately omit one leg — fixed (`docs/Q0.8_MQL_EXECUTION_MAPPING.md`).
