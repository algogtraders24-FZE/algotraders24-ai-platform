# Q1.4 — Eligibility Gate Audit

Code-level audit + tests proving every imported strategy passes through the canonical eligibility boundary (`runtime/reduction/eligibility-gate.ts`'s `checkReductionEligibility`), and that no alternate compiler/simulation path bypasses it.

## The chain, verified directly against current code

```
importMQLSource()  →  StrategyIR
compileStrategy(ir)  →  validateStrategyIR + computeExecutionCompatibility + reduceStrategyIRToSpec(ir)
                                                                                 ↑
                                                          reduceStrategyIRToSpec() ALWAYS calls
                                                          checkReductionEligibility(ir) FIRST;
                                                          returns { status: "BLOCKED", strategySpec: undefined }
                                                          with no exception if ineligible.
```

`git grep -n ": StrategySpec = {" src` (and `as StrategySpec`) returns exactly **one** match: `runtime/reduction/ir-to-spec-reducer.ts`. No other file in `src/` constructs a `StrategySpec` object from an IR. `compileStrategy()` (`compilation.ts`) is the single orchestrator and calls `reduceStrategyIRToSpec` unconditionally, every time, with no flag or code path that skips it.

## Alternate-path bypass check

`runSimulation()` (Q0.5's raw entry point) accepts a `StrategySpec` directly — this is **not** a bypass of MQL-import eligibility, because such a spec never claimed to be an import in the first place (Q0's own architecture: hand-authored/AI-proposed specs are validated by `validateStrategySpec()`, a different and complete gate for a different claim). No function anywhere converts an IR into a `StrategySpec` other than `reduceStrategyIRToSpec`. **Verdict: no bypass exists.**

## Positive confirmation: eligibility failures never silently degrade

Every `BLOCKED` result in the corpus carries `diagnostics.length > 0` with real, human-readable reasons (proven in `test/q14-end-to-end-pipeline.test.ts`'s per-fixture assertions) and `strategySpec: undefined` — never a partial or best-effort spec.
