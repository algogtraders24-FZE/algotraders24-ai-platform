# Q0.7 Platform Semantic Matrix

## A semantic reference, not a parser (Q0.7.40)

`PLATFORM_SEMANTIC_MATRIX` (`domain/strategy-ir/platform-matrix.ts`) has one `PlatformSemanticProfile` row per `SourcePlatform` (`MT4_MQL4`/`MT5_MQL5`/`TRADINGVIEW_PINE`/`NINJATRADER_NINJASCRIPT`/`CTRADER_CBOT`/`AT24_NATIVE`; `AI_GENERATED`/`UNKNOWN` deliberately excluded — they have no platform-native semantics to catalog), across 16 dimensions: account mode, order model, position model, bar timing, MTF, repainting, SL/TP, trailing, partial close, sessions, timezone, fees, spread, slippage, intrabar, historical/realtime. Every cell is a REAL, CITED fact reused from `docs/Q0.4_PLATFORM_R&D.md`/`docs/Q0.4_PLATFORM_DECISIONS.md`/`docs/Q0.4_PINE_SEMANTICS.md` — this file structures already-researched findings into a queryable shape, it does not invent platform behavior. `test/strategy-ir-platform-matrix.test.ts` spot-checks several of the most consequential facts directly (MT4 hedging-only vs. MT5's explicit dual-mode vs. cTrader's native dual-mode vs. AT24's netting-only implementation).

## How the matrix is used

Two consumers, both in `runtime/strategy-ir/`:

1. **`execution-compatibility-engine.ts`** doesn't read the matrix directly — it checks a StrategyIR's DECLARED features (which may have come FROM any platform) against what Q0.5/Q0.6's engine ACTUALLY implements, independent of source platform. The matrix instead informs what a FUTURE translator needs to know to correctly POPULATE an IR's fields (e.g., "MT4 has no netting mode" tells a translator to always set `accountingMode: "HEDGING"` for MT4-sourced strategies, never to guess).
2. **A future reducer/translator** (not built in Q0.7) would consult the matrix to decide, PER SOURCE PLATFORM, which IR fields need an explicit platform-default annotation (`ExecutionAssumptionsIR.platformDefaultsUsed`) versus which can be read directly off the source.

## Selected findings worth restating here (full detail in the Q0.4 docs cited above)

- **Account mode**: MT4 is hedging-only (no netting exists at all); MT5 and cTrader both support EITHER mode explicitly, selectable; AT24 itself implements NETTING only (Q0.5), with HEDGING reserved but unbuilt. A translator sourcing from MT4 must never emit `accountingMode: "NETTING"` — there is no such MT4 behavior to represent.
- **Bar timing**: NinjaScript's `Calculate` modes (`OnBarClose`/`OnEachTick`/`OnPriceChange`) are the most explicit, best-documented calculation-timing control of any researched platform — directly informed `BarCloseSemantics`' five-value shape (Q0.7.24).
- **MTF/lookahead**: Pine's `request.security()` with `barmerge.lookahead_on`/`lookahead_off` is the researched precedent for `RequestSecurityCapability` (Q0.7.21) — AT24's validator always treats `lookahead: "ON"` as BLOCKING, never a silently-accepted alternative (`docs/Q0.7_LOOKAHEAD_REPAINTING.md`).
- **Intrabar/spread**: cTrader's bid/ask-native data model is the top-fidelity-tier precedent (matches AT24's own future D5 reservation); MT5's PUBLISHED 3-5-3-point tick-generation algorithm is explicitly contrasted with MT4's UNDOCUMENTED "wave templates" — disclosure, not sophistication, is what separates an acceptable heuristic from an unacceptable black box (`docs/Q0.4_PLATFORM_DECISIONS.md`'s own framing, reused verbatim here).

## What Q0.7 does NOT do

No parser reads this matrix to auto-populate an IR (that translation logic doesn't exist yet). No numeric "compatibility score" is derived from it — it is descriptive reference data, consulted by a human or a future translator, not a scoring input.
