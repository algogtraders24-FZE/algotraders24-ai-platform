# Q0.7 Lookahead / Repainting (IR Layer)

## Repainting model (Q0.7.22) — the mandatory execution-eligibility gate

`RepaintingModel` (`domain/strategy-ir/repainting-ir.ts`): `NON_REPAINTING|CONFIRMED_ONLY|REALTIME_DEPENDENT|REPAINTING|UNKNOWN` — vocabulary drawn directly from `docs/Q0.4_LOOKAHEAD_REPAINTING.md`'s researched causes (retroactive indicator recalculation, unconfirmed current-bar reads, revised historical data, synthetic-chart leakage, unavailable-quote access). `UNKNOWN` is a legitimate, honest value — a translator that genuinely cannot prove which category applies must say so rather than guess `NON_REPAINTING`. Per Q0.7.22's explicit rule, BOTH `REPAINTING` and `UNKNOWN` make a StrategyIR permanently execution-INELIGIBLE (`runtime/strategy-ir/ir-validator.ts`'s `checkRepainting()`) — structurally valid, never execution-clean, until the translator resolves it to one of the other three values. `test/strategy-ir-golden-fixtures.test.ts` proves fixture 23 (a Pine strategy with an unconfirmed `request.security()` read) is exactly this case.

## Realtime/historical asymmetry (Q0.7.23) — never normalized away

`RealtimeHistoricalAsymmetry` (`historicalVsRealtimeDiffers`/`barCloseVsIntrabarDiffers`, both required booleans, no default) records whether the SOURCE actually behaves differently across these four evaluation contexts. `false` for both is the ONLY way to claim "no asymmetry exists" — the IR never assumes it by omission, matching TradingView's own documentation (the platform Q0.4 found MOST transparent about this asymmetry existing at all — `docs/Q0.7_PLATFORM_MATRIX.md`).

## Structural prevention, still the strongest layer

Per `docs/Q0.4_LOOKAHEAD_REPAINTING.md`'s three-tier detection strategy (structural prevention > differential replay > provenance audit), Q0.7 adds ONE new structural guarantee: `SeriesOffsetRef`'s rejection of negative (future) offsets (`domain/strategy-ir/series.ts`'s `validateSeriesOffset`) makes "read a future bar via a raw series offset" impossible to even CONSTRUCT, the same class of guarantee Q0.2's incremental-indicator-step-function pattern and `TimeFrontier` already provide for indicators and bar-visibility respectively. Combined with `docs/Q0.7_MTF_SEMANTICS.md`'s HTF-close-only rule, the STRUCTURAL layer now covers: future bars (Q0.2), future MTF/HTF reads (Q0.7.20), and future series offsets (Q0.7.9) — three of `docs/Q0.4_LOOKAHEAD_REPAINTING.md`'s catalogued "future bars"/"HTF leakage"/"MTF leakage" sources are now impossible to represent in a valid IR at all, not merely checked-for.

## What still requires the DIFFERENTIAL-REPLAY and PROVENANCE-AUDIT tiers (unbuilt in Q0.7)

Retroactive indicator recalculation and revised historical data remain outside what a static IR structure alone can detect — those require actually RUNNING a strategy twice (once truncated, once full) and comparing, or auditing `DatasetVersion`/`DatasetId` after the fact, exactly as `docs/Q0.4_LOOKAHEAD_REPAINTING.md` always specified. Q0.7 does not build either of those detectors for the IR layer; `RepaintingModel`/`RealtimeHistoricalAsymmetry` are DECLARATIVE fields a translator must set correctly, not something Q0.7 independently verifies against actual source behavior.

## What Q0.7 does NOT do

No differential-replay lookahead detector for IR-level constructs (Q0.2's own no-lookahead test remains the only implemented instance of that pattern, for indicators specifically). No automated repainting DETECTION from source code (there is no parser to feed one). No synthetic-chart-leakage classification (still reserved, per `docs/Q0.4_INTRABAR_ENGINE.md`).
