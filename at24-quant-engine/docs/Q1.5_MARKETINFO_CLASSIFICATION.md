# Q1.5.5 — MQL4 `MarketInfo()` Classification

## The gap (Q1.4-documented, closed here)

`MarketInfo(symbol, MODE_*)` had zero dedicated handling in `semantic-analyzer.ts` — every call, regardless of mode, fell through to the generic `UNRESOLVED_CROSS_FILE_CALL` bucket.

## Classification matrix

| MQL4 property | Semantic meaning | AT24 category | Executable? | Rationale |
|---|---|---|---|---|
| `MODE_STOPLEVEL` | Broker's minimum stop distance | `BROKER_CONSTRAINT_DEPENDENCY` | No (broker-fed, never fabricated) | Exact MQL4 analog of MQL5's `SYMBOL_TRADE_STOPS_LEVEL` |
| `MODE_FREEZELEVEL` | Broker's freeze distance | `BROKER_CONSTRAINT_DEPENDENCY` | No | Analog of `SYMBOL_TRADE_FREEZE_LEVEL` |
| `MODE_MINLOT` | Minimum lot size | `BROKER_CONSTRAINT_DEPENDENCY` | No | Analog of `SYMBOL_VOLUME_MIN` |
| `MODE_MAXLOT` | Maximum lot size | `BROKER_CONSTRAINT_DEPENDENCY` | No | Analog of `SYMBOL_VOLUME_MAX` |
| `MODE_LOTSTEP` | Lot step increment | `BROKER_CONSTRAINT_DEPENDENCY` | No | Analog of `SYMBOL_VOLUME_STEP` |
| `MODE_SPREAD` | Live/dynamic spread | `UNRESOLVED_CROSS_FILE_CALL` | No | **Deliberately NOT a broker constraint** — a live, dynamic value, not a static trading constraint. Mirrors the exact precedent this session's own Q0.8.39 baseline repair established for MQL5's `SYMBOL_SPREAD` |
| `MODE_BID` / `MODE_ASK` | Live bid/ask | `UNRESOLVED_CROSS_FILE_CALL` | No | Real MQL4 EAs use the bare `Bid`/`Ask` predefined variables; this legacy `MarketInfo` idiom is rare enough that the honest generic default is correct — no dedicated realtime-dependency heuristic was built for it |
| any other mode (e.g. `MODE_DIGITS`) | — | `UNRESOLVED_CROSS_FILE_CALL` | No | Unchanged, honest default |

## Implementation

`MARKETINFO_BROKER_CONSTRAINT_TOKENS` (`semantic-analyzer.ts`) — the five MQL4 modes above — feeds the **same** `BROKER_CONSTRAINT_DEPENDENCY` category the existing MQL5 `SymbolInfoInteger`/`SymbolInfoDouble` + `BROKER_CONSTRAINT_TOKENS` check already uses (never a second, drifting category). `MarketInfo(symbol, MODE)` checked via `expr.args.some(...)`, matching the existing MQL5 call's own arg-position-agnostic style.

## Explicitly out of scope

`MODE_SPREAD` as a broker constraint, `MODE_BID`/`MODE_ASK` classification (any category), and every other `MarketInfo` mode remain **EXPLICITLY UNSUPPORTED** — no new semantic category was invented for them.

## Evidence

`test/q15-marketinfo-classification.test.ts` (11 tests): all 5 broker constraints classify correctly, `MODE_SPREAD`/`MODE_BID`/`MODE_ASK` stay unresolved, an unrelated mode (`MODE_DIGITS`) is unaffected, determinism (3× identical), zero false positives.

| `MODE_SPREAD` as broker constraint | **EXPLICITLY UNSUPPORTED** |
