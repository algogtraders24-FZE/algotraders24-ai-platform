# Q0.12 — Pending Order Fill Contract

## The eight dimensions (Q0.12.1)

`PendingOrderFillSemantics` (`domain/strategy-ir/platform-matrix.ts`), attached to every `PlatformSemanticProfile` as `pendingOrderFill`:

| Field | Meaning |
|---|---|
| `limitTouchBehavior` | `TOUCH_SUFFICIENT` \| `PENETRATION_REQUIRED` \| `UNKNOWN` — does merely touching the limit level fill it, or must price trade strictly through? |
| `limitPenetrationBehavior` | Free text: what "penetration" means when required |
| `stopTriggerBehavior` | `TOUCH_TRIGGER` \| `PENETRATION_TRIGGER` \| `TICK_DEPENDENT` \| `BAR_APPROXIMATION` \| `UNKNOWN` |
| `gapThroughBehavior` | `FILL_AT_TRIGGER` \| `FILL_AT_OPEN` \| `FILL_AT_AVAILABLE_PRICE` \| `UNRESOLVED` |
| `triggerFillRelationship` | Free text: is fill price ever claimed equal to trigger/limit, or does the platform document a possible divergence? |
| `historicalExecutionModel` | `BAR` \| `INTRABAR` \| `TICK` \| `LOWER_TIMEFRAME_RECONSTRUCTION` \| `BROKER_SIDE_SIMULATION` \| `PLATFORM_SPECIFIC_SYNTHETIC` \| `UNKNOWN` |
| `bidAskRequirement` | `NOT_REQUIRED` \| `REQUIRED` \| `OPTIONAL` \| `UNKNOWN` |
| `intrabarRequirement` | Free text: what intrabar detail the platform's own backtester can use, and any documented caps |

`UNKNOWN` is a first-class, honest value — used for MQL4, MQL5, NinjaTrader, and cTrader's touch-vs-penetration specifics, since Q0.4's own prior research did not pin these down with citable precision. Only Pine (extensively researched, `docs/Q0.4_PINE_SEMANTICS.md`) and AT24-native (verifiable directly from source) get firm classifications for every field.

## AT24-native's own classification, derived from real code (never guessed)

- `limitTouchBehavior: PENETRATION_REQUIRED` — `resolveLimitFill()`'s `low < limit`/`high > limit` strict inequality (Q0.5, unmodified).
- `stopTriggerBehavior: TOUCH_TRIGGER` — `resolveStopFill()`'s `high >= stop`/`low <= stop` inclusive comparison.
- `gapThroughBehavior: FILL_AT_OPEN` — both a LIMIT's favorable gap and a STOP's unfavorable gap resolve to the bar's own open, never the requested level.
- `historicalExecutionModel: LOWER_TIMEFRAME_RECONSTRUCTION` — D2/D3 (Q0.6) reconstruct real child bars; D1 alone is `BAR`.
- `bidAskRequirement: NOT_REQUIRED` — OHLCV-only; `BID`/`ASK` price references are named-but-`UNSUPPORTED` (Q0.11.3), never approximated.

## Pine's documented divergence (why AT24 does NOT replicate its default)

Pine's own default `limitTouchBehavior` is `TOUCH_SUFFICIENT` — ANY price within a bar's OHLC range counts as reaching a limit, not genuine trade-through. AT24 deliberately implements the stricter `PENETRATION_REQUIRED` behavior UNCONDITIONALLY (matching Pine's own non-default, opt-in strict mode), per Q0.4's "never silently favorable" mandate. This is the single clearest, most concrete cross-platform divergence this contract captures.

## Versioning and hashing (Q0.12.13/38)

`PLATFORM_SEMANTIC_PROFILE_VERSION` (currently `"1.0.0"`) is bumped whenever any execution-semantic rule in `PLATFORM_SEMANTIC_MATRIX` changes. `computeSemanticProfileHash()` hashes the version plus the entire matrix — any change to any platform's `pendingOrderFill` (or any other field) changes this hash deterministically, proven in `test/q12-failure-catalog.test.ts` item 20.
