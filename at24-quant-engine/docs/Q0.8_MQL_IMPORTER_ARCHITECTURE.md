# Q0.8 MQL Importer Architecture

## The pipeline (Q0.8's critical rule: parsing and semantic interpretation stay separate)

```
sourceText (string)
   |
   v
tokenize()                    runtime/mql-importer/lexer.ts — native, hand-rolled (Q0.8.2/55, no third-party lexer)
   |
   v
parseMQL()                    runtime/mql-importer/parser.ts — recursive-descent + precedence climbing (Q0.8.5)
   |                           produces a ProgramNode AST carrying ZERO trading-strategy meaning
   v
detectDialect()                runtime/mql-importer/dialect-detector.ts — from ACTUAL constructs (Q0.8.7), never filename
   |
   v
analyzeMQLSemantics()           runtime/mql-importer/semantic-analyzer.ts — THE ONLY place meaning is assigned
   |                             produces an MQLSemanticModel (events, indicators, orders, state, unsupported constructs...)
   v
generateStrategyIR()             runtime/mql-importer/ir-generator.ts — reduces the semantic model into Q0.7's StrategyIR
   |                              never a second interpretation pass — every field traces to something already recorded
   v
StrategyIR + MQLImportReport       importMQLSource() (runtime/mql-importer/mql-importer.ts) — the single public entry point
```

No stage is skipped, merged, or reordered. A "text-to-IR regex parser" (the pattern Q0.8's own spec explicitly forbids) would collapse all five stages into one pass with no inspectable intermediate structure — this pipeline keeps each stage's OUTPUT independently testable (`test/mql-lexer.test.ts`, `test/mql-parser.test.ts`, `test/mql-semantic-analyzer.test.ts`, and the IR-generation assertions in `test/mql-golden-fixtures.test.ts`/`test/mql-g01-import.test.ts`).

## Why the real G01 EA is the primary validation target

`docs/Q0.4_STRATEGY_IR.md` and Q0.7's own IR were designed on paper; Q0.8 is the first sprint that runs a genuinely complex, 660-line, real-world MQL5 Expert Advisor through the full pipeline. `test/mql-g01-import.test.ts` reads `ea-research/G01_LiquiditySweep_MSS_FVG/AT24_GOLD_G01_LiquiditySweep_MSS_FVG.mq5` directly via `fs.readFileSync` (never an ES `import` — the package's isolation guarantee, `test/isolation.test.ts`, forbids `src/` taking a runtime code dependency on `ea-research/`, not a test reading a real-world fixture file; the file is never written to). The result: **zero BLOCKING parse diagnostics** — the parser handles the entire real file, including two real syntax quirks discovered only by testing against it (see below) — and a semantic model that correctly identifies every event handler, both CTrade order calls, all 27 inputs, the real M5/M15 multi-timeframe usage, and (critically) that G01's actual entry logic is a cross-file, multi-bar state machine the current IR cannot represent — see `docs/Q0.8_G01_IMPORT_REPORT.md`.

## Two real bugs the G01 fixture caught that no synthetic test had

1. **MQL5's `input group "Section Title"` directive has no trailing semicolon** — a genuine, undocumented-by-example syntax quirk. The parser has a dedicated case for it (`parser.ts`'s `parseInputDeclaration`), tolerant of an optional trailing `;` too.
2. **Comma-separated multi-declarator statements** (`SBar prevDay,prevWeek;`) — required promoting `VariableDeclarationStatementNode`/`GlobalVariableDeclarationNode` from a single `name`/`initializer` pair to a `declarators: readonly VariableDeclarator[]` array (an AST shape change made before any downstream code depended on the old shape, so no migration was needed).

Both are documented here rather than silently "just working" — they are exactly the kind of gap only a REAL fixture surfaces, which is why Q0.8.44 mandates one.

## Scope boundaries (deliberate, not oversights)

- **No `#include` expansion.** Each `#include` is recorded (`MQLSourceDocument.includes`) but never resolved/merged into one AST. G01's actual liquidity/sweep/displacement/MSS/FVG/risk logic lives across 12 `Include\*.mqh` files this importer does not parse — every call into one of them is honestly recorded as `UNRESOLVED_CROSS_FILE_CALL` (95 such calls for the real G01 file), never guessed at.
- **`switch`/`while`/`do-while` are skip-recovered**, not modeled as first-class AST nodes (Q0.8.5's own minimal statement list omits them) — `docs/Q0.8_MQL_AST.md` explains the recovery mechanism and why it is safe for this sprint's scope.
- **Cast-target detection is conservative** — only `TYPE_KEYWORDS` (int/long/double/string/etc.) and identifiers matching MQL's own `ENUM_*` naming convention are recognized as C-style cast targets, avoiding false positives like `INIT_FAILED` being misread as a cast.
- **No code generation** — only parsing/analysis/IR-generation exist; `SourceGenerator` (Q0.7) remains an unimplemented interface.

## What Q0.8 does NOT do

No Pine/NinjaScript/cBot parser (explicitly deferred to a future sprint, per Q0.7's own "one platform at a time" plan). No code generation. No D4 tick engine, no WFO/Monte Carlo/optimizer, no AI model, no cloud API, no broker integration, no external indicator execution (`iCustom` is flagged, never run).
