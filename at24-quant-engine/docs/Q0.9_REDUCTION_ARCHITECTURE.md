# Q0.9 Reduction Architecture

Q0.9 builds the missing bridge from an imported `StrategyIR` (Q0.7/Q0.8's semantic source of truth) to Q0.5/Q0.6's simulation engine:

```
StrategyIR --[eligibility gate]--> REDUCED/BLOCKED --[reducer]--> StrategySpec --[adapter]--> D1/D2/D3 simulation
```

## The three layers

1. **Eligibility gate** (`src/runtime/reduction/eligibility-gate.ts`, `checkReductionEligibility(ir)`) — the "honest block" mechanism. Runs a fixed battery of checks against `ir` and returns `{ eligible, blockingReasons }` BEFORE any spec-building begins. Reuses Q0.7's own `validateStrategyIR()` as its first check, then adds Q0.9-specific execution-capability checks (see below). If even one blocking reason exists, no `StrategySpec` is ever built for that IR.

2. **Reducer** (`src/runtime/reduction/ir-to-spec-reducer.ts`, `reduceStrategyIRToSpec(ir)`) — a pure function: never mutates `ir` or any nested object, and returns a discriminated `ReductionResult` (`status: "REDUCED" | "REDUCED_WITH_WARNINGS" | "BLOCKED"`). Calls the eligibility gate first; on failure returns `BLOCKED` with no `strategySpec` field present at all (never a partial or fabricated one). On success, builds a `StrategySpec` by direct reference/spread from `ir.risk` and `ir.execution.declared` (never rebuilt), and validates the result with Q0's own `validateStrategySpec()` as a final gate.

3. **Compilation** (`src/runtime/reduction/compilation.ts`, `compileStrategy(ir)`) — orchestrates `validateStrategyIR` + `computeExecutionCompatibility` (Q0.7) + `reduceStrategyIRToSpec` (above), then computes a `compilationHash` identifying this exact (IR, reducer version, reduction status, StrategySpec) tuple.

4. **Simulation adapter** (`src/runtime/reduction/simulation-adapter.ts`, `compileToSimulation(compilation, bars, options)`) — the ONLY function in the package connecting a compiled strategy to Q0.5/Q0.6. See `docs/Q0.9_SIMULATION_BRIDGE.md`.

## What the eligibility gate currently requires (Q0.5/Q0.6's real execution capability, not an arbitrary restriction)

- `positionManagement.pyramiding.sameDirectionBehavior === "ACCUMULATE"` and `reversal.{buyToSell,sellToBuy} === "REVERSE"` — Q0.5's simulation engine has exactly one same-direction/opposite-direction behavior baked in; anything else in the IR would silently misdescribe what actually executes.
- `positionManagement.accountingMode === "NETTING"` — Q0.5/Q0.6 implement netting only.
- `repaintingModel` is `NON_REPAINTING` or `CONFIRMED_ONLY` — never `REPAINTING`/`REALTIME_DEPENDENT`.
- No `timeframeSeries` with `role === "HIGHER"` — genuine dual-timeframe strategy calculation is deferred (`docs/Q0.6_MTF_SAFETY.md`).
- No `SIGNAL_EXIT`/`SESSION_EXIT` exit kinds — Q0.5's `StrategySpec.exitRules` are accepted structurally but never evaluated (`docs/Q0.5_EXECUTION_MODEL.md`); a strategy relying on one would silently never exit that way.
- Each exit of kind `STOP_LOSS`/`TAKE_PROFIT` requires the corresponding `ir.risk` field to already be resolved.
- Each entry must have `direction !== "FLAT"`, `sizingModel.method !== "atr-based"` (Q0.5's own documented limitation), and `timing === "NEXT_BAR_OPEN"`.

None of these are new restrictions invented by Q0.9 — each traces to a real, already-documented capability boundary of Q0.5/Q0.6's frozen engine. The gate's job is to make that boundary visible and enforced at import time, instead of letting an incompatible IR silently misbehave once simulated.

## Determinism and purity

Every function in this layer is pure and referentially transparent: identical inputs always produce identical outputs (`test/q09-compilation.test.ts`, `test/q09-mql-e2e-golden.test.ts` reproducibility tests), and none of them mutate their inputs (`test/q09-failure-catalog.test.ts` item 17). This mirrors the same discipline Q0.7's IR canonicalization and Q0.6's simulation engine already hold themselves to.
