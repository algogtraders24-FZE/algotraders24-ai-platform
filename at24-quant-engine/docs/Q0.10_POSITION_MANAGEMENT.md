# Q0.10 — Position Management Architecture

## The four layers, kept strictly separate

```
Policy                Evaluation              Action                 Execution
-----------------     ------------------      -----------------      -------------------
RiskSpecification  →  evaluateRisk()       →  RiskAction          →  simulation-engine.ts
(breakeven/           (runtime/risk/           (MOVE_STOP /           mapRiskAction() +
 trailingStop/         pipeline.ts,             PARTIAL_CLOSE /        position-engine.ts
 partialClose/         Q0.3, unmodified)        FORCE_EXIT_REQUIRED)   (Q0.5, frozen except
 maxHoldingPeriod)                                                     the additive
                                                                        initialStopLoss fix)
```

Q0.10's own contribution sits ABOVE this, never inside it:

```
PositionManagementPolicy  ←  extractPositionManagementPolicy(spec.risk)   (domain/position-management.ts)
PositionManagementInstruction  ←  derivePositionManagementInstruction(riskResult)
```

These are a **read-only, audit-facing vocabulary layer**. `extractPositionManagementPolicy` is a pure projection of `RiskSpecification`'s four management fields — never a duplicate contract. `derivePositionManagementInstruction` is a pure mapping from an already-computed `RiskEvaluationResult` into a richer, explicitly-named record (`StopAdjustment` / `PartialCloseInstruction` / `ForcedExitInstruction`), distinguishing breakeven-sourced from trailing-sourced stop moves via the new `RiskAction.MOVE_STOP.sourceRule` tag. Neither function calls `evaluateRisk()`, mutates a `Position`, or executes anything — see `docs/Q0.10_POSITION_MANAGEMENT_AUDIT.md` for why this shape was chosen over duplicating execution logic.

## What Q0.10 actually built

Per the audit, the Policy→Evaluation→Action→Execution chain for breakeven/trailing/partial-close/max-holding was **already fully implemented and correct** in Q0.3/Q0.5. Q0.10's real, net-new work:

1. **The R-multiple fix** — `Position.initialStopLoss` (additive field), populated by `openPosition()`, consumed by `buildTrade()`'s R-multiple computation instead of the current (management-mutable) `stopLoss`. Without this, ANY position management that moves a stop past entry (breakeven's and trailing's entire purpose) crashed the simulation. See the audit doc for the full justification of touching these two nominally-frozen files.
2. **`sourceRule` on `RiskAction.MOVE_STOP`** (`domain/risk-evaluation.ts`, `runtime/risk/pipeline.ts`) — distinguishes a breakeven-triggered stop move from a trailing-triggered one, previously indistinguishable to any caller.
3. **The eligibility gate now positively evaluates management fields** (`runtime/reduction/eligibility-gate.ts`) rather than silently letting them through unchecked: an `atr-multiple` `DistanceSpec` used by breakeven/trailing/partialClose is only SUPPORTED when a matching-period ATR indicator is actually declared in `ir.indicators`, and at most one distinct ATR period may be referenced across all risk rules combined (Q0.5's `SimulationConfig.atrByIndex` is a single series, not one per period).
4. **A validator bug fix**: `BreakevenRule.lockOffset`'s own field documentation always said `value: 0` means "move to exactly entry" — a legitimate, common case — but `validateDistanceSpec` rejected it unconditionally. Fixed via a `lockOffset`-only validator (`validateBreakevenLockOffset`); every other `DistanceSpec` use site is unchanged.
5. **MQL4/MQL5 detection and reduction** of breakeven/trailing/partial-close/max-holding source patterns (`docs/Q0.10_MQL_MANAGEMENT.md`) — genuinely new semantic-analyzer/ir-generator logic, since Q0.8 only detected the raw calls (`ModifyCallSite`/`PartialCloseCallSite`), never interpreted them.
6. **A pyramiding/reversal heuristic refinement**: Q0.9's "no custom position-management code" signal counted `OrderOpenPrice`/`OrderLots`/`OrderStopLoss`/`OrderTakeProfit` — accessors a breakeven/trailing pattern MUST call to compute its trigger — alongside genuine gating/counting functions (`PositionsTotal`/`PositionSelect`/etc.). Under the old check, detecting breakeven at all automatically flipped pyramiding to the conservative REJECT branch, permanently blocking the very strategies this sprint targets. Split into `MANAGEMENT_ACCESSOR_FUNCTIONS` (excluded from the gating signal) vs. everything else; G01's real case (which uses genuine gating functions) is unaffected.
7. **An ATR-indicator-registration fix**: an ATR indicator referenced ONLY by a risk leg or management rule (never by the entry condition) never made it into `ir.indicators`, silently making its own risk rule permanently un-computable. Fixed via `registerAtrIndicatorIfNeeded`, called for all five binding sites (SL, TP, breakeven, trailing, partial-close).

## Non-duplication guarantees

- No second R-multiple formula: `derivePositionManagementInstruction` and every management evaluator (`breakeven.ts`/`trailing.ts`/`partial-close.ts`) use `DistanceSpec`/`resolveDistanceSpec`, never `computeRMultiple` directly for triggers — see `docs/Q0.10_CONFLICT_SEMANTICS.md`'s R-multiple-consistency note.
- No second event queue, order engine, or position mutation path: `MODIFY_STOP`/`REDUCE_POSITION`/`FORCE_EXIT` are mapped and applied entirely inside Q0.5's existing per-bar loop (`simulation-engine.ts`'s Step 5) — Q0.10 added zero new simulation-engine control flow.
- No second indicator math: ATR values for management triggers come from the SAME `buildIndicatorSeriesFromIR`/`calculateSeries()` path Q0.9 built for SL/TP.
