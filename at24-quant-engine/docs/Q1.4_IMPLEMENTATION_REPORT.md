## Files intentionally untouched

Every file under `src/` (zero changes — `git status --porcelain -- at24-quant-engine/src` confirms this). Rules 1–7, 9–19 of Q1.4's own safety rules are all trivially satisfied since nothing outside `at24-quant-engine/test`, `at24-quant-engine/scripts`, and `at24-quant-engine/docs` was touched.

## Real findings this sprint surfaced (all pre-existing, all honestly documented, none patched)

1. `OrderSelect()` correctly trips the conservative pyramiding/reversal heuristic (verified, not a defect).
2. Unresolved SL/TP formulas correctly BLOCK the whole strategy at eligibility (verified, not a defect).
3. `MarketInfo()` (MQL4's real broker-constraint idiom) is not specifically classified — falls through to `UNRESOLVED_CROSS_FILE_CALL`, still honest, just less precise. Documented as a real coverage gap, not fixed (out of this sprint's scope — no new detection logic).
4. `PyramidingPolicy.maxEntries`/`maxPositions` exist as a TYPE field but are never enforced anywhere in `src/` — a real, precise, newly-surfaced architectural gap, documented, not fixed (no engine changes this sprint).

## Performance

`npm run benchmark:q14-full-pipeline` — full source-to-execution path: avg 7.26ms/op, p50 6.51ms, p95 12.62ms, p99 26.97ms (~138 ops/sec) on a 200-bar strategy. No regression possible or claimed — zero hot-path code changed.

## Known limitations (carried forward, not introduced)

- MQL5's `OrderGetInteger(ORDER_TYPE)` idiom is not recognized (Q0.13/Q1.3-documented).
- Expiration is detected but never compiled into an executable operation from source (Q0.13/Q1.3-documented).
- `MarketInfo()` broker-constraint reads fall through to generic unresolved-call reporting (newly precise, this sprint).
- `PyramidingPolicy.maxEntries`/`maxPositions` are unenforced (newly precise, this sprint).
- No cross-statement `OrderSelect`/`PositionSelect` target tracing exists (Q0.13/Q1.3-documented).
- G01 remains `BLOCKED` (its cross-file state machine is genuinely unresolved).

## Deferred work (recommended Q1.5)

1. `OrderGetInteger(ORDER_TYPE)` recognition (closes the MQL5 coverage gap).
2. Generic `ExitRule`-based condition-authored close/exit evaluation (would benefit MQL, Pine, NinjaScript, and cBot simultaneously — the future-platform check's own strongest finding).
3. `PyramidingPolicy.maxEntries`/`maxPositions` enforcement in the simulation engine (a real, platform-agnostic gap).
4. `MarketInfo()`-based broker-constraint classification for MQL4.
