# Q0.6 Determinism

## The success criterion (unchanged from Q0.5, now proven across three fidelities)

Same input bars + same strategy + same configuration + same detail-provider data must produce the EXACT SAME events, orders, fills, positions, account, trades, metrics, and provenance — on repeated execution AND on replay — for D1_OHLC, D2_LOWER_TIMEFRAME, and D3_M1 independently.

## Sources, verified

1. **No wall-clock, no randomness, no environment access anywhere in `src/runtime/fidelity/`** — statically enforced by `test/fidelity-determinism.test.ts`, scanning every file for `Date.now()`, `Math.random()`, `process.env`, bare `new Date()`, `crypto.randomUUID` — the identical pattern Q0.3's `risk-determinism.test.ts` and Q0.5's `simulation-determinism.test.ts` established, now extended to the fidelity layer.
2. **Every child-derived ID is a deterministic string function of its own inputs** — `IntrabarObservation.childBarId = "${symbol}:${childTimeframe}:${timestamp}"`; every `SimulationEvent`/`SimulationOrder`/`SimulationTrade` produced from a child-bar resolution reuses Q0.5's OWN deterministic ID schemes UNCHANGED (`docs/Q0.5_EVENT_QUEUE.md`, `docs/Q0.5_ORDER_ENGINE.md`) — a child-originated event's `eventId` differs from a parent-originated one only because its TIMESTAMP differs (the child bar's own timestamp), never because a new ID scheme was invented.
3. **`BarDetailProvider.getDetail()` is a pure function of its query and the provider's own fixed dataset** — `createStaticBarDetailProvider` never mutates its input array (defensively sorts into a NEW array at construction time) and never consults anything outside its closure.
4. **Every state transition in the D2/D3 orchestrator is a pure function** — identical to Q0.5's guarantee (`docs/Q0.5_DETERMINISM.md`, items 2-3), since `runFidelityAwareSimulation()` calls the SAME Q0.5 position/account/order-transition functions, none of which mutate their inputs.
5. **`resultHash`** — `computeCanonicalHash()` (Q0.2, reused, not reimplemented) over every field of a `MultiFidelitySimulationResult` except the hash itself. `test/fidelity-determinism.test.ts` proves three independent runs of the SAME config produce an identical hash, separately for D1_OHLC and D2_LOWER_TIMEFRAME.

## D2/D3 event ordering (Q0.6.27/28)

Within one parent bar, child-derived events (`ORDER_FILLED`, `POSITION_OPENED`, `POSITION_CLOSED`, etc.) are recorded at their OWN child bar's timestamp, interleaved chronologically as the per-child loop processes them — using the SAME `SimulationEventType` union and the SAME `eventId = "${eventType}:${timestamp}:${sequence}"` scheme Q0.5 already established (`domain/simulation/event.ts`, unmodified). No new event type was invented for "this event came from a child bar" — since the ID scheme already includes the timestamp, and a child's timestamp is always distinct from its parent's, child-originated events are automatically identity-distinct from parent-originated ones without any new machinery.

## Replay (Q0.6, same guarantee as Q0.5.37)

`test/fidelity-determinism.test.ts`: replaying a JSON-round-tripped copy of the SAME parent bars through a second, independent `runMultiFidelitySimulation()` call reproduces an identical `resultHash`, proving serialization boundaries introduce no drift — for D2 specifically (the newly-added code path).

## Immutability (Q0.6, same guarantee as Q0.5.38)

The input `bars` array is frozen before being passed to `runMultiFidelitySimulation()` and the run completes without throwing (no attempted mutation). Every `SimulationTrade` produced by a D2 run is independently frozen by Q0.5's OWN `TradeLedger.record()` (reused, not reimplemented) — a mutation attempt on a returned D2 trade throws exactly as it does for a D1 trade.

## Isolation

`src/runtime/fidelity/` imports only from `src/domain/`, `src/runtime/determinism.ts`, `src/runtime/identity.ts`, `src/runtime/signal-generator.ts`, `src/runtime/risk/`, and `src/runtime/simulation/` — all within `at24-quant-engine`. Zero imports from `quant-engine/`, `quant_engine/`, `quant-engine-handoff/`, any broker API, or any new runtime dependency (confirmed by `git status` and the existing `test/isolation.test.ts`, which scans the whole package and required no changes for Q0.6).
