# Q0.7 Strategy IR

## What Q0.7 builds (and what it deliberately doesn't)

The canonical `StrategyIR` (`domain/strategy-ir/strategy-ir.ts`) — the semantic layer between a source platform (MT4/MT5/Pine/NinjaScript/cBot/AI) and Q0's canonical `StrategySpec`, exactly as `docs/Q0.4_STRATEGY_IR.md` architected and explicitly deferred to a future sprint. **No parser is implemented for any platform** — `SourceParser`/`SourceGenerator` (`domain/strategy-ir/parser-interfaces.ts`) are type-only stubs, unimplemented anywhere in `src/`. What IS implemented is everything a translator would need to TARGET: the IR's own shape, a structural+semantic validator, deterministic canonicalization/hashing, an execution-compatibility checker against Q0.5/Q0.6's actual engine, a cross-platform parity comparator, and the one legitimate compiler that exists today — `compileAIStrategyToIR()`, turning a structured AI intent into IR directly (never through a "source language").

```
MQL4 / MQL5 / Pine / NinjaScript / cBot / AT24-native / AI
                    |
                    v (mechanical program-structure translation — NOT built in Q0.7)
              Strategy IR              <- Q0.7 (this sprint)
                    |
                    v (semantic reduction — NOT built in Q0.7)
             StrategySpec               <- Q0's canonical, deterministic, minimal contract
```

## Deliberately narrower than Q0.4's full research scope

`docs/Q0.4_STRATEGY_IR.md` researched variables (with scope/persistence), arbitrary state, loops, and full arithmetic expressions as things a REAL translator would eventually need. None of those are in Q0.7's `StrategyIR` — they remain flagged as needing further design, exactly as Q0.4 left them. Q0.7's `StrategyIR` covers exactly what its own 59 numbered sections enumerate: indicators, conditions/expressions (extended with explicit series offsets), entries/exits, orders, position management (pyramiding/reversal/accounting mode), risk (Q0.2/Q0.3's `RiskSpecification`, reused verbatim), sessions/timezone, MTF/HTF availability, repainting, execution assumptions, and the provenance/unsupported-semantics/approximation machinery that makes every gap in that coverage EXPLICIT rather than silently absent.

## The Operand extension (Q0.7.7/8) — the one change to a Q0/Q0.2 frozen file

`domain/expression.ts`'s `Operand` union gains a third variant, `{ kind: "series"; ref: SeriesOffsetRef }` (`domain/strategy-ir/series.ts`), for raw price-series references at an explicit bar offset (`Close[1]`, never an implicit array index). This is the one place Q0.7 touches a file previous sprints froze — explicitly authorized by Q0.7.7's own instruction ("Extend existing Expression only where required... Ensure existing Q0/Q0.2 behavior remains unchanged"), unlike Q0.5/Q0.6's stricter never-touch policy on their own frozen simulation core. The existing `"indicator"`/`"literal"` variants and every function operating on them are byte-for-byte unchanged; `runtime/expression-evaluator.ts` gained a new `resolveSeriesValue()` branch (necessary — without it, a `"series"` operand would either fail to typecheck against `indicatorKey()` or silently misresolve) but its existing indicator/literal code paths are untouched. `test/strategy-ir-series-expression.test.ts` and the unmodified 503 pre-Q0.7 tests together prove nothing regressed.

## Structural vs. semantic validation (the same domain/runtime split every sprint has used)

`validateStrategyIRStructure()` (domain) mirrors `validateStrategySpec()`'s exact pattern: non-empty identity, no duplicate ids, well-formed expressions (reusing `validateExpression`), valid `RiskSpecification`/`ExecutionSpecification` (reusing Q0.2's validators unmodified), plus new IR-specific structural rules (source/provenance consistency, known order types, unhidden approximations, unambiguous platform-defined reversal behavior). `validateStrategyIR()` (runtime, `runtime/strategy-ir/ir-validator.ts`) layers the SEMANTIC checks Q0.7.38 enumerates on top: undeclared-indicator references, HTF lookahead safety, and repainting/unsupported-semantics-driven execution eligibility — see `docs/Q0.7_MTF_SEMANTICS.md` and `docs/Q0.7_LOOKAHEAD_REPAINTING.md`.

## What Q0.7 does NOT do

No parser for any platform. No code generation (only `SourceGenerator` interface stubs exist). No IR-to-StrategySpec REDUCER (that is the next architectural boundary, explicitly out of scope — see `docs/Q0.7_TRANSLATION_CONTRACT.md`). No variables/state/loops/arithmetic-expression IR. No D4+ tick engine. No real MT4/MT5/Pine/NinjaScript/cBot source text is parsed anywhere — every platform-tagged golden fixture is a hand-built `StrategyIR` representing what a parser WOULD produce, not the output of an actual parser.
