# Q0.7 Semantic Model

## Semantic Fidelity (Q0.7.3) — never silently translate

`SemanticFidelity` (`domain/strategy-ir/source.ts`): `EXACT | SEMANTIC_EQUIVALENT | APPROXIMATED | UNSUPPORTED` — the exact four grades `docs/Q0.4_STRATEGY_IR.md` reserved (there spelled `SEMANTICALLY_EQUIVALENT`/`APPROXIMATE`; Q0.7 finalizes the naming). Recorded once per IR at `provenance.semanticStatus`. The validator enforces this is never a decorative label: `semanticStatus: "APPROXIMATED"` with an empty `provenance.approximations` array is a structural ERROR ("hidden approximation," `test/strategy-ir-failure-catalog.test.ts` item 17) — an approximation must always be accompanied by a concrete `ApproximationRecord` naming what changed and why.

## Indicator IR (Q0.7.5)

`IndicatorIR` (`domain/strategy-ir/indicator-ir.ts`) is a union of `NamedIndicatorIR` (the 6 families AT24 already implements — `SMA`/`EMA`/`RSI`/`ATR`/`MACD`/`BOLLINGER_BANDS`) and the generic `IndicatorCall` escape hatch (name/parameters/inputs/timeframe/source/warmup/outputFields) for anything else. The validator cross-checks that every indicator a condition/entry/exit actually REFERENCES is also DECLARED in `ir.indicators` — an undeclared reference is "unknown indicator," a structural error (`test/strategy-ir-failure-catalog.test.ts` item 4), never silently tolerated.

## Price series and offsets (Q0.7.6/8/9)

`PriceSeriesField` (`OPEN|HIGH|LOW|CLOSE|VOLUME`, always assumed available) and `ReservedPriceSeriesField` (`BID|ASK|TICK_VOLUME|BUY_VOLUME|SELL_VOLUME|SPREAD|DEPTH`, never required to exist). `SeriesOffsetRef` (`domain/strategy-ir/series.ts`) pairs a series with an EXPLICIT non-negative integer offset — `validateSeriesOffset()` rejects anything else, including any attempt to represent a future offset (`Close[-1]`) — there is no valid `Operand` for that; a translator encountering one must emit an `UnsupportedSemantic` instead. `runtime/expression-evaluator.ts`'s new `resolveSeriesValue()` throws a clear "not enough history" error when an offset reaches before the available `bars` array, exactly mirroring how a missing indicator value already throws — never a silent 0/undefined.

## Orders, entries, exits (Q0.7.11-13)

`OrderTypeIR` matches Q0.5's `SimulationOrderType` exactly (`MARKET|LIMIT|STOP|STOP_LIMIT`) — reused vocabulary, not redefined, so a future reducer's mapping is 1:1. `EntryIR` carries its own condition/trigger/sizingModel (reusing Q0.2/Q0.3's `PositionSizingMethod`)/timing/executionType. `ExitIR`'s `kind` (`STOP_LOSS|TAKE_PROFIT|SIGNAL_EXIT|TIME_EXIT|SESSION_EXIT|RISK_EXIT`) carries NO execution logic (Q0.7.12's explicit rule) — whether AT24's engine can actually EXECUTE a given kind today is a separate question, answered by `computeExecutionCompatibility()` (`docs/Q0.7_TRANSLATION_CONTRACT.md`), not by the IR's own structural validity.

## Position semantics (Q0.7.14-16)

`positionManagement.accountingMode` reuses Q0.5's `PositionAccountingMode` (`NETTING|HEDGING`) directly — never redefined. `PyramidingPolicy` and `ReversalPolicy` never default silently: `allowPyramiding`/`sameDirectionBehavior`/`oppositeDirectionBehavior` must always be set explicitly by a translator, and a `ReversalPolicy` claiming `"PLATFORM_DEFINED"` for either direction MUST also set `platformDefaultDescription` — the validator rejects an unexplained "platform defined" claim as ambiguous platform semantics (failure catalog item 7).

## Execution assumptions (Q0.7.29/30)

`ExecutionAssumptionsIR` wraps Q0.2's `ExecutionSpecification` verbatim (`declared`) plus a `platformDefaultsUsed: readonly string[]` — any platform-specific default a translator had to import (e.g. "Pine order timing", "MT4 hedging") is named explicitly there, never silently absorbed. The IR never computes fees/spread/slippage/latency itself — that stays the execution engine's exclusive job (no duplication of Q0.5/Q0.6's fill logic).

## What Q0.7 does NOT do

No arithmetic-expression IR (only comparison/logical/boolean-reference — Q0.4's arithmetic-node need remains unaddressed). No variable/state modeling. No margin/settlement semantics beyond what `ExecutionSpecification` already reserves.
