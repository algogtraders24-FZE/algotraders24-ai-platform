# Q0.12 — Order Modification Failure Catalog

20 failure modes, each proven in `test/q12-failure-catalog.test.ts` against the real function that must reject it.

| # | Failure | Guarded by |
|---|---|---|
| 1 | Invalid modification | `validateOrderModification` rejects `MODIFY_PRICE` with no `newPrice` |
| 2 | Missing order | `validateOrderModification(undefined, ...)` fails explicitly |
| 3 | Modify after fill | See `test/q12-race-fixtures.test.ts`'s `TRIGGER_BEFORE_MODIFY` |
| 4 | Cancel after fill | See `test/q12-race-fixtures.test.ts`'s `TRIGGER_BEFORE_CANCEL` |
| 5 | Cancel after cancel | A `CANCELLED` order rejects a second `CANCEL` (terminal-status guard) |
| 6 | Replace after fill | A `FILLED` order rejects `REPLACE` identically to any other modification |
| 7 | Invalid price | A non-positive `newLimitPrice`/`newStopPrice`/`newPrice` is rejected |
| 8 | Wrong directional price | A BUY LIMIT modified above the reference price is rejected (Q0.12.20) |
| 9 | Invalid expiration | `MODIFY_EXPIRATION` with no `newExpiration` is rejected |
| 10 | Unsupported operation | An unrecognized `modificationType` fails via exhaustive `default` case |
| 11 | Future-information dependency | A modification scheduled for a bar index beyond the run's own bars simply never applies |
| 12 | Cancel/trigger race | See `test/q12-race-fixtures.test.ts`'s `CANCEL_BEFORE_TRIGGER`/`TRIGGER_BEFORE_CANCEL` |
| 13 | Modify/trigger race | See `test/q12-race-fixtures.test.ts`'s `MODIFY_BEFORE_TRIGGER`/`TRIGGER_BEFORE_MODIFY` |
| 14 | Duplicate replacement | Replacing an already-replaced (now `CANCELLED`) order is rejected |
| 15 | Phantom order | A `REPLACE` with nothing to change is invalid — `applyOrderModification` is never reached, no order is fabricated |
| 16 | Phantom position | See `test/q12-golden-fixtures.test.ts`'s `LIMIT_CANCEL`/`STOP_CANCEL` (cancelling before fill produces zero positions) |
| 17 | Order identity collision | A `REPLACE`'s new order always has a different `creationTimestamp` (hence a different identity) than its parent |
| 18 | D1/D2 divergence | See `test/q12-fidelity-integration.test.ts` (identical intent, identical outcome across tiers) |
| 19 | D2/D3 divergence | `D3_M1` reuses the exact same `runFidelityAwareSimulation` code path as `D2_LOWER_TIMEFRAME` — the Q0.12 mirror applies to both simultaneously, not per-tier |
| 20 | Semantic profile mismatch | Changing `PLATFORM_SEMANTIC_MATRIX` changes `computeSemanticProfileHash()` deterministically |

## A note on items discovered mid-sprint

Item 2's real-world manifestation (a modify/cancel attempt against an already-terminal order) was initially mishandled — the calling code skipped it silently instead of routing it through validation, meaning no `ORDER_MODIFICATION_REJECTED` event was ever recorded for this exact case. Found by the race fixtures (`test/q12-race-fixtures.test.ts`), not by this catalog's own unit-level test — a reminder that a failure catalog's unit-level proofs and a sprint's end-to-end fixtures each catch different classes of bug. See `docs/Q0.12_RACE_SEMANTICS.md` for the full account.
