# Q1.4 — Provenance Audit

Traces provenance through the full pipeline: source → AST/semantic node → IR → compiled object → StrategySpec → order → execution → trade → result. Every claim is proven in `test/q14-provenance-identity-determinism.test.ts`'s PROVENANCE tests.

## The chain

| Stage | Provenance carrier | Field(s) |
|---|---|---|
| Source | `MQLSourceDocument.sourceHash` | sha256 of raw source text, deterministic (`computeSourceHash`) |
| AST/semantic node | `SourcePosition` on every AST node; `PendingOrderManagementCallSite.position` | line/column |
| IR | `StrategyIR.sourceHash`/`sourcePlatform`/`sourceLanguage`/`sourceVersion` | equal to the document's own hash (proven — never diverges) |
| IR (compiled rule) | `PendingOrderManagementRuleIR.sourceLine`/`sourceExpr` | real source line + a literal reconstruction of the call (`"OrderModify(...)"`) — never fabricated |
| IR provenance block | `StrategyIRProvenance{sourcePlatform, sourceHash, sourceVersion, irVersion, translationHash, semanticStatus, unsupportedSemantics, approximations}` | `translationHash` deterministic (`computeCanonicalHash`), changes with any content change |
| Compiled object | `StrategyCompilationResult{ir, strategySpec?, reductionReport, validationReport, compatibilityReport, resultHash}` | `resultHash` ties IR hash + spec hash (or null if BLOCKED) + reducer version + status together |
| StrategySpec | No dedicated provenance field (by design — see `Q1.4_SEMANTIC_PRESERVATION.md` Part 2) | traceable via `computeSemanticStrategyHash(spec)`, tied back to `compilation.resultHash` |
| Order | `SimulationOrder.orderId` — deterministic string `${strategyVersion}:${symbol}:${side}:${orderType}:${creationTimestamp}:${sequence}` | never random/wall-clock (Q0.5.6) |
| Execution | `SimulationEvent{timestamp, sequence, eventType, payload}` | full audit trail, `EventStatistics.eventsByType` |
| Trade | `SimulationTrade` via `buildTrade()` — carries `position`, `fillModel`, `spreadModel`/`slippageModel`/`feeModel` names | unchanged Q0.5/Q0.10 |
| Result | `SimulationResult.resultHash`, `SimulationProvenance{strategyHash, datasetId, datasetVersion, dataFidelity, executionModel, ...}` | `CompilationSimulationResult` additionally carries `compilationHash`/`strategySpecHash`/`simulationResultHash`, unbroken end to end (proven directly) |

## Verified end-to-end (not merely asserted)

`test/q14-provenance-identity-determinism.test.ts`'s "full pipeline result carries strategyHash/datasetId/dataFidelity through to the final SimulationResult, unbroken" test proves `result.compilationHash === compilation.resultHash` and `result.strategySpecHash === computeSemanticStrategyHash(compilation.strategySpec)` for a REAL MQL5-imported strategy run through 200 synthetic bars — the chain is not just documented, it is checked field-by-field against live output.

## Unknown provenance is never fabricated

A `BLOCKED` reduction always carries `diagnostics.length > 0` (never an empty or silent block) — proven directly for the `mql4-25` fixture. A compiled pending-order-management rule's `sourceLine`/`sourceExpr` are only ever populated from a REAL AST node's own `position`/reconstructed call text — there is no code path that invents a plausible-looking source location.

## Minimum-required fields, confirmed present where applicable

Source file (`fileName`, carried through `MQLImportOptions`/`document.fileName`), source location (`sourceLine` on every compiled rule), original expression (`sourceExpr`), semantic classification (`semanticFidelity`: EXACT/APPROXIMATED/UNKNOWN), platform (`sourcePlatform`/`sourceLanguage`), translation identity (`translationHash`), strategy identity (`strategyId`, part of every hash where semantically relevant).
