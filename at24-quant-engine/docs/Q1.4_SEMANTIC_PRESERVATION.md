# Q1.4 — Semantic Preservation & IR→StrategySpec Field Audit

## Part 1 — Semantic loss gate

For every execution-relevant semantic, one of five classifications applies. **There is no `UNKNOWN → EXECUTABLE` conversion anywhere in this pipeline** — proven structurally (every `PendingOrderManagementRule` an `UNKNOWN`-fidelity target/condition/operation is excluded by `executableRules()` before it ever reaches the runtime evaluator; every `UNREPRESENTABLE_CONDITION` entry carries a placeholder that ALWAYS evaluates false, never executes a real trade) and by direct test (`test/q14-negative-corpus.test.ts` items 1, 2, 17, 22).

| Classification | Meaning | Example |
|---|---|---|
| `PRESERVED` | Source value carries through unchanged | A literal LIMIT price (`1.1030`) |
| `TRANSFORMED-BY-CONTRACT` | Source value is reduced to a DIFFERENT but faithful representation, per a documented rule | A `<price> ± <literal>` SL/TP expression → `DistanceSpec` |
| `WARNING` | Represented, but with a named, non-fatal caveat | Account mode ASSUMED (no custom position-selection detected) |
| `BLOCKING` | Cannot be safely represented — the AFFECTED FEATURE is excluded from execution | An unresolved SL/TP formula |
| `UNKNOWN` | Detected but structurally unprovable — never guessed, never executed | `OrderGetInteger(ORDER_TYPE)` condition (fixture 17) |

## Part 2 — IR → StrategySpec field audit

Every execution-relevant field, audited directly against `runtime/reduction/ir-to-spec-reducer.ts`'s real code:

| Field | IR → Spec | Contract |
|---|---|---|
| side/direction | `EntryIR.direction` → `EntryRule.direction` | Direct passthrough |
| order type | `EntryIR.executionType` → `EntryRule.executionType` | Direct passthrough; absent means MARKET (unchanged Q0 default) |
| quantity | Computed at simulation-decision time from `risk.sizing`, not carried on the IR/Spec entry itself | By design (Q0's sizing/entry separation) — proven unaffected by every golden fixture |
| entry price | `EntryIR.condition` (WHEN) is separate from `limitPrice`/`stopPrice` (AT WHAT PRICE) — never conflated | Q0.11.2's own rule, re-verified |
| stop price | `EntryIR.stopPrice: PriceReference` → `EntryRule.stopPrice` | Direct passthrough, `validatePriceReference` re-checked at Spec level |
| limit price | `EntryIR.limitPrice` → `EntryRule.limitPrice` | Direct passthrough |
| SL | `ir.risk.stopLoss` → `spec.risk.stopLoss` | Direct passthrough (`risk` is reused wholesale, Q0.9.17/18) — proven byte-identical in `test/q14-negative-corpus.test.ts` item 18 |
| TP | `ir.risk.takeProfit` → `spec.risk.takeProfit` | Same |
| expiration | `ir.pendingOrderManagement` operations (`MODIFY_EXPIRATION` is a valid vocabulary member but is never populated FROM source in this sprint — see `Q1.4_END_TO_END_IMPORT_MATRIX.md` fixtures 10/20) | Documented boundary, not silently dropped — `newExpirationExpr` remains visible at the semantic-model layer for audit |
| cancellation | `ir.pendingOrderManagement.rules[].operation.kind === "CANCEL_PENDING"` → `spec.pendingOrderManagement.rules[]` | Direct structural passthrough (`toPendingOrderManagementRule`, field-for-field identical shape by design) |
| modification | Same rule set, `MODIFY_STOP`/`MODIFY_LIMIT` | Same |
| target identity | `OrderTargetIR` → `OrderTargetSpec` | Direct passthrough — proven byte-identical in item 18 |
| conditions | `ModificationConditionIR` → `ManagementCondition` | Same |
| timing | `EntryIR.timing` — eligibility REQUIRES `NEXT_BAR_OPEN`, any other value is `BLOCKED` (never silently converted, Q0.9.20) | Verified by hand-built-IR proof, `test/q14-negative-corpus.test.ts` item 12 |
| timeframe | `ir.timeframes`/`timeframeSeries` → `spec.timeframes` | Direct passthrough |
| symbol | `ir.instruments` → `spec.instruments` | Direct passthrough |
| position reference | Positions are engine-internal (`Position.id`), never authored in `StrategySpec` — out of IR/Spec scope by design | N/A |
| order reference | Same — `SimulationOrder.orderId` is deterministically derived at runtime (Q0.5.6), never carried in `StrategySpec` | N/A |
| execution policy | `ir.execution.declared` → `spec.execution` | Direct passthrough (already validated upstream) |
| provenance | `ir.provenance` is NOT copied onto `StrategySpec` at all (`StrategySpec` has no provenance field — provenance lives at the IR/compilation-result layer, `StrategyCompilationResult.ir`/`resultHash`) | By design — `compileToSimulation`'s result still carries `compilationHash`/`strategySpecHash`/`simulationResultHash`, tying the chain together without duplicating provenance onto the Spec itself |

**No field is silently discarded.** Every intentional reduction (sizing/quantity computed at decision time, provenance living at the compilation-result layer rather than on `StrategySpec` itself, position/order references being runtime-only) is a documented, pre-existing Q0/Q0.9 architectural contract, re-verified here rather than newly invented.
