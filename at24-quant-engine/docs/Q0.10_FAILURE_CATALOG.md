# Q0.10 — Position Management Failure Catalog

15 failure modes, each proven in `test/q10-failure-catalog.test.ts` against the real function that must reject it — never a description of intended behavior.

| # | Failure | Guarded by | Behavior |
|---|---|---|---|
| 1 | Negative close quantity | `position-engine.ts`'s `reducePosition` | Throws for `reduceQuantity <= 0` |
| 2 | Close > position | `reducePosition` | Throws for `reduceQuantity > position.quantity` |
| 3 | Invalid trailing distance | `validateDistanceSpec` (via `validateRiskSpecification`) | Rejects `distance <= 0` |
| 4 | Invalid breakeven trigger | `validateDistanceSpec` | Rejects `trigger <= 0` (degenerate "act immediately") |
| 5 | SL moving against risk | `evaluateTrailingStop`/`evaluateBreakeven`'s "improves" check | Refuses any proposal that doesn't strictly improve on the current stop |
| 6 | Duplicate partial close | `evaluatePartialClose`'s `alreadyTriggered` guard | Never re-triggers once flagged, even if the price condition is still met |
| 7 | Holding expiry ambiguity | `evaluateMaxHoldingPeriod`'s finite-timestamp check | Non-finite timestamps produce an explicit `BLOCKING` violation, never a silently-wrong duration |
| 8 | Future timestamp | `evaluateMaxHoldingPeriod` | An `asOf` earlier than `entryTimestamp` produces a negative duration, never falsely `>=` a positive limit |
| 9 | Missing position | `evaluateRisk()`'s top-level branch | Neither `proposedEntry` nor `existingPosition` set → safe `NO_ACTION`, never a throw or a guess |
| 10 | Invalid ATR | `resolveDistanceSpec` (throws with no ATR value) + the eligibility gate's ATR-period-consistency check | An atr-multiple rule referencing an undeclared ATR period is `BLOCKED` before simulation, never silently inert |
| 11 | Zero risk distance | `computeRMultiple` | Refuses a non-positive risk distance rather than dividing by zero/negative |
| 12 | Same-bar conflict | `bar-fill-model.ts`'s `resolveProtectiveExit` | Both SL and TP reachable resolves conservatively (stop-loss), flagged `ambiguous: true` |
| 13 | Unsupported management pattern | `semantic-analyzer.ts`'s `detectManagementPattern` | A dynamic/cross-file new-SL expression is never fabricated into a management rule — silently produces nothing, not a guess |
| 14 | Cross-file unresolved state | `ir-generator.ts`'s `gatingPositionQueries` heuristic | G01's real 17 position-management calls (genuine `PositionsTotal`/`PositionGetTicket` gating) keep pyramiding/reversal `PLATFORM_DEFINED`/`REJECT`, never falsely assumed safe |
| 15 | Non-deterministic timestamp | The entire risk-evaluation/simulation pipeline (Q0.3.17/18, unmodified) | Identical management-bearing simulations produce byte-identical result hashes — no `Date.now()`/wall-clock leakage |

See `docs/Q0.10_POSITION_MANAGEMENT_AUDIT.md` for the full reasoning behind items 10 (the ATR-period-consistency gap Q0.10 discovered and closed) and 14 (verified against the real G01 source file, read-only).
