# Q0.4 Platform Decisions

Q0.4.3: classify major capabilities per researched platform as ADOPT / IMPROVE / AVOID / INVENT, with why. This is the compact, capability-first cross-reference matrix; `Q0.4_ADOPT_IMPROVE_AVOID_INVENT.md` is the fuller, platform-first narrative (Q0.4.43) — read that one for the reasoning, this one for quick lookup. AT24 does not blindly copy any platform; every row below traces to a specific, cited finding in `Q0.4_PLATFORM_R&D.md`/`Q0.4_PINE_SEMANTICS.md`.

| Capability | Best precedent | Classification | Why |
|---|---|---|---|
| Execution-concern separation (fill/slippage/fee/margin as independent, pluggable interfaces) | LEAN (`IFillModel`/`ISlippageModel`/`IFeeModel`/`IBuyingPowerModel`) | **ADOPT** | Verified directly in shipped, open-source code — not a design promise. Already matches Q0.2's reserved `reality-models.ts` interfaces almost exactly. |
| Order/Position/Deal separation | MT5 (Order → Deal → Position) | **ADOPT** | Cleaner than MT4's flat ticket model; Deal-as-immutable-record maps directly to a future Trade Ledger. |
| Position accounting mode (netting vs. hedging) as an explicit, named, swappable configuration | MT5 (account-level `ENUM_ACCOUNT_MARGIN_MODE`) + cTrader (both modes natively supported) | **ADOPT, then IMPROVE** | Adopt the explicit-mode-not-implicit-behavior principle; improve by making it swappable per-experiment (Cross-Fidelity Testing, Q0.4.32) rather than fixed per broker account. |
| Intrabar fill resolution — conservative, documented, no-assumed-global-ordering | LEAN's `EquityFillModel.cs` | **ADOPT** | Independently-shipped, code-verified proof that "OHLC cannot prove sequencing" is solvable conservatively without guessing — the strongest evidence base for `Q0.4_INTRABAR_ENGINE.md`. |
| Limit-order fill-verification default (touch vs. proven trade-through) | Pine's stricter opt-in mode (`backtest_fill_limits_assumption`) | **IMPROVE** | Pine's own STRICTER mode is the right behavior; Pine's LENIENT mode is the wrong DEFAULT. AT24 adopts the strict behavior as the only default, never opt-in. |
| Stop/limit gap-through handling | LEAN's `StopMarketFill` "unfavorable gap" check (fills at Open, not the stop price, when gapped through) | **ADOPT** | Directly matches `Q0.4_BACKTEST_FAILURE_CATALOG.md` item 14's required behavior — realistic, not favorable. |
| Tick-generation heuristic (when real ticks are unavailable) | MT5's published 3-5-3-point algorithm | **ADOPT (as one tier)** | A DOCUMENTED heuristic beats an undocumented one (contrast MT4's unpublished "wave templates" — AVOID). Slots into `Q0.4_INTRABAR_ENGINE.md`'s "Deterministic heuristic" resolution tier, never presented as equivalent to real data. |
| Separating "when the strategy recalculates" from "what price an order fills at" | NinjaTrader (Tick Replay improves calculation timing; High-Order-Fill-Resolution improves fill price; NinjaTrader's own docs state these are NOT the same problem) | **ADOPT** | Validates keeping Calculation Timing (Q0.4.6) and the Intrabar/Fill Engine as separate architecture layers, not one setting. |
| Native Walk-Forward Optimization | NinjaTrader (dedicated, automated rolling in-sample/out-of-sample UI) | **ADOPT (concept), build later** | The only platform researched with genuine native WFO — a real, buildable UI/workflow shape for AT24's future Statistical Robustness system (Q0.4.37), not built in Q0.4. |
| Bid/ask-native data model | cTrader | **ADOPT (as the top fidelity tier)** | Matches AT24's own D5 fidelity level (`Q0.4_INTRABAR_ENGINE.md`) directly; resolves spread-dependent fill questions trade-tick-only data cannot. |
| Single execution engine, multiple language front-ends | cTrader (C# and Python cBots share one `cAlgo.API` engine) | **ADOPT (as a principle)** | Directly informs the Strategy IR (`Q0.4_STRATEGY_IR.md`): any future MQL/Pine/NinjaScript translator must target ONE `StrategySpec`/runtime, never a parallel per-language execution path. |
| Explicit, honestly-named "cheat" flags for intentional lookahead | Backtrader (`cheat_on_open`/`cheat_on_close`) | **ADOPT (naming discipline)** | The strongest precedent for how to label an unsafe-but-sometimes-legitimate research mode — contrast Pine's `process_orders_on_close`, whose innocuous name hides real repainting risk (AVOID that naming style). |
| Non-standard/synthetic chart types treated as first-class, warning-free chart types | NinjaTrader (Renko/Range/Kagi/P&F as native bar types, with only a soft fidelity caveat) | **AVOID** | Pine's harder line ("not suited for strategy backtesting... unrealistic and potentially misleading") is the correct stance; NinjaTrader's own admitted fidelity caveat for the same bar types shows even platforms that support them natively don't fully trust them for backtesting. |
| Non-standard chart type real-OHLC-fill exception scoped to ONE type only | Pine (Heikin Ashi only; explicitly NOT extended to Renko/Kagi/etc.) | **IMPROVE** | AT24 generalizes the real-OHLC-fill principle to ALL synthetic types via `REAL_MARKET_PRICE`/`SYNTHETIC_PRICE` classification, not just the one Pine happened to solve. |
| Zero-by-default execution costs | NinjaTrader (slippage/commission default to zero; cited 30-50% profit-factor overstatement risk) | **AVOID** | Directly the failure mode Q0.2's `costsExplicitlyZero` guard already prevents platform-wide; never regress to a silent zero anywhere. |
| Silently degrading fidelity mid-run without flagging it | Pine's Bar Magnifier 200,000-bar cap (early bars unmagnified, later bars magnified, same run) | **AVOID** | `DataFidelity` (Q0.4.12) must be a per-result-or-per-trade field, never an assumed run-wide constant. |
| Data-windowing silently changing signals under "the same" nominal range | Pine's Deep Backtesting vs. regular backtesting (different calculation-warmup start points) | **AVOID (the silence), ADOPT (the underlying capability)** | Deep-history calculation over an arbitrary range is valuable (`Q0.4_BACKTEST_ARCHITECTURE.md`'s `DEEP_HISTORY` research mode); the undisclosed divergence between modes is not — Provenance (Q0.4.38) must make this auditable. |
| Undisclosed/unpublished tick-simulation algorithm | MT4's "predefined wave templates" (no public algorithm found) | **AVOID** | Contrast directly with MT5's published algorithm (ADOPT above) — the difference between a heuristic and a black box is disclosure. |
| Timezone display setting silently not affecting already-stored values | NinjaTrader's Trading Hours template footgun | **AVOID** | AT24's `Intl.DateTimeFormat`-explicit-zone discipline (Q0.3) structurally prevents this class of bug by never separating "stored" from "displayed" timezone. |
| MTF/HTF data availability timing | Pine's `lookahead_off` default + `[1]`-offset safe pattern for `lookahead_on` | **ADOPT, then IMPROVE** | Adopt the safe pattern's OUTCOME (an HTF value is available only once confirmed); improve by making it the ONLY behavior, not a parameter a strategy author could set wrong. |
| Settlement-delay modeling for cash-account asset classes | LEAN's `ISettlementModel` (Immediate vs. Delayed, explicit T+ simulation) | **ADOPT (interface shape)** | Directly informs AT24's reserved `SettlementModel` (Q0.4.20) — not built in Q0.4. |
| Three-way (algorithm/exchange/data) timezone distinction | LEAN | **ADOPT** | More rigorous than every other platform researched; informs the future per-instrument Session/Calendar Engine (Q0.4.29). |
| Alpha/Portfolio-Construction/Risk/Execution pipeline separation | LEAN's Algorithm Framework | **ADOPT (validates existing AT24 design)** | Independently confirms Q0.3's Decision → Risk Evaluation → Order Engine separation is the right shape — four platforms' worth of convergent design (LEAN, cTrader's Position/PendingOrder split, MT5's Order/Deal/Position split, AT24's own Q0.3 boundary) arrive at the same principle independently. |

## What AT24 invents (not adopted, improved, or avoided from any single platform)

Per `Q0.4_ADOPT_IMPROVE_AVOID_INVENT.md`'s per-platform sections, no researched platform independently originates: (1) a unified `DataFidelity` ladder (D0-D7) spanning open-price-only through microstructure, treated as a first-class, per-result field rather than an implicit consequence of which testing mode was selected; (2) an `ExecutionRealityGrade` that explicitly separates execution realism from strategy quality/profitability from AI confidence — no platform researched draws this three-way distinction at all; (3) a Strategy IR as an explicit, inspectable translation checkpoint between source platforms and a canonical spec, with per-node Source Fidelity grading (`EXACT`/`SEMANTICALLY_EQUIVALENT`/`APPROXIMATE`/`UNSUPPORTED`); (4) a `PlatformDiscrepancyReport` comparing the same strategy logic's signals/orders/fills/P&L across multiple platforms' semantics simultaneously. These four are AT24's own synthesis, informed by but not copied from any single platform's design — see `Q0.4_BACKTEST_ARCHITECTURE.md` for full specification.
