# Q0.11 — Source Fidelity for Order Semantics

## The four grades (Q0.7's own `SemanticFidelity`, reused verbatim — no new grading scale)

The sprint spec's own vocabulary (`EXACT`/`PROVABLE`/`APPROXIMATED`/`UNSUPPORTED`) maps directly onto the actual, already-shipped type (`domain/strategy-ir/source.ts`): `SemanticFidelity = "EXACT" | "SEMANTIC_EQUIVALENT" | "APPROXIMATED" | "UNSUPPORTED"` — "PROVABLE" and "SEMANTIC_EQUIVALENT" are the same concept under two names; no new grade or type was introduced.

| Grade | Meaning for an order/price mapping | Execution eligible? |
|---|---|---|
| `EXACT` | The canonical order type and price are a direct, unambiguous 1:1 mapping from a real source construct (e.g. `OP_BUYSTOP` → `STOP`) | Yes |
| `SEMANTIC_EQUIVALENT` (spec's "PROVABLE") | The mapping required one narrow, provable arithmetic/pattern reconstruction (e.g. a bare-literal limit price, or an `ATR_OFFSET` resolved via the same `RiskLegBinding` arithmetic Q0.9/Q0.10 established) | Yes |
| `APPROXIMATED` | A formal `ApproximationRecord` exists disclosing a real, named difference | Only per policy (none currently applies to order-type reduction — every non-EXACT mapping in Q0.11 resolves via `SEMANTIC_EQUIVALENT`/`WARNING` disclosure, never a formal approximation) |
| `UNSUPPORTED` | The price/order construct could not be resolved at all, or is structurally never computable (e.g. `BID`/`ASK`) | **No — BLOCKED, never executed** |

Only `EXACT`/`SEMANTIC_EQUIVALENT` may be execution eligible (Q0.11.20's own rule); `UNSUPPORTED` always blocks.

## Where each grade is actually assigned for order semantics

- **`EXACT`**: the `executionType` classification itself — `OP_BUYLIMIT`/`CTrade.BuyStop`/etc. map to their canonical `OrderTypeIR` with zero ambiguity (`ir-generator.ts`'s direct lookup, no inference involved).
- **`SEMANTIC_EQUIVALENT`**: `resolvePriceExprToReference()`'s narrow numeric-literal resolution for a LIMIT/STOP price (`ir-generator.ts`) — disclosed via a `WARNING`-level `UnsupportedSemantic` note (`markUnsupported("LIMIT order price", ...)`), matching Q0.9/Q0.10's own established disclosure pattern for SL/TP arithmetic reconstruction. Never silently claimed `EXACT`.
- **`UNSUPPORTED`**: a detected `Bid`/`Ask` price reference (`PriceReference.UNSUPPORTED`, `domain/strategy-ir/price-reference.ts`) — recorded as a `BLOCKING`-severity `UnsupportedSemantic` at import time AND independently re-checked at the eligibility gate (`runtime/reduction/eligibility-gate.ts`), a deliberate two-layer check (detect honestly at import; enforce unconditionally at reduction) matching the SAME pattern already used for unresolved SL/TP formulas. Also `UNSUPPORTED`: a LIMIT/STOP/STOP_LIMIT order whose price expression is a variable bound to an unresolved cross-file formula — `resolvePriceExprToReference()` returns `undefined` rather than guessing, and the eligibility gate blocks on the missing price.

## Provenance visibility (Q0.11.40)

Every imported entry's `executionType`/`limitPrice`/`stopPrice` rides inside `StrategyIR.entries[]`, which is included in `computeCanonicalIRHash()`'s scope (Q0.7, unmodified) — a source-fidelity downgrade for one entry's price (e.g. from `PROVABLE` to `UNSUPPORTED` because a formula changed) changes the IR's own identity hash, and (if the strategy still reduces) the resulting `StrategySpec`'s `executionType`/prices ride inside `computeSemanticStrategyHash()`'s scope too — proven directly in `test/q11-determinism-provenance.test.ts`.
