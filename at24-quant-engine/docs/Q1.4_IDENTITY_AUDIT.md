# Q1.4 — Semantic Identity / Hash Audit

Verified directly against `runtime/identity.ts` (`computeSemanticStrategyHash`), `runtime/strategy-ir/ir-hash.ts` (`computeCanonicalIRHash`/`computeCrossPlatformSemanticHash`), and `domain/strategy-ir/platform-matrix.ts` (`computeSemanticProfileHash`) — code read directly, not assumed from prior sprint reports. Every claim is proven in `test/q14-provenance-identity-determinism.test.ts`'s IDENTITY tests.

## Same source + same semantic profile → same identity

`computeCanonicalIRHash()` on 3 independent imports of the identical fixture produces byte-identical hashes (`test/q14-provenance-identity-determinism.test.ts`).

## Execution-affecting semantic change → different identity

Verified for FOUR distinct kinds of change, each proven to alter the relevant hash:

| Change | Hash affected | Proven |
|---|---|---|
| Pending-order-management operation (CANCEL_PENDING vs MODIFY_STOP) | `computeCanonicalIRHash` | Yes |
| Order type / execution policy (BUY_LIMIT vs BUY_STOP) | `computeCanonicalIRHash` | Yes |
| Management rule (a StrategySpec's `pendingOrderManagement`) | `computeSemanticStrategyHash` | Yes |
| Fidelity-relevant semantics — `PLATFORM_SEMANTIC_MATRIX` content | `computeSemanticProfileHash` | Deterministic (unchanged across two calls with the SAME matrix — proven), and DOES change when the matrix content changes (Q0.12's own proof, `test/strategy-ir-platform-matrix.test.ts`, unmodified by Q1.4, re-verified passing) |

Expiration was NOT separately tested as an identity-changing dimension for the reason documented in `Q1.4_SEMANTIC_PRESERVATION.md`: no source-derived expiration operation exists yet (`MODIFY_EXPIRATION` is a valid vocabulary member but never populated from MQL source in this sprint) — there is no execution-affecting expiration VALUE for the identity chain to yet distinguish from source; the underlying `OrderExpirationPolicy` type itself DOES already participate in `SimulationOrder` identity where it is set programmatically (Q0.12, unchanged).

## Irrelevant metadata change → no false identity change

`computeSemanticStrategyHash` destructures out `metadata` (`description`/`author`/`tags`/`createdAt`) before hashing — proven directly: a spec with `description: "irrelevant text"`, `author: "someone"`, `tags: [...]` added produces the IDENTICAL hash to the base spec. `computeCanonicalIRHash` applies the same discipline (`strategyId` and `metadata` excluded) at the IR layer.

## Platform-identity vs. cross-platform semantic hash — two different, both-correct answers

`computeCanonicalIRHash` INCLUDES platform-identity fields (two IRs from genuinely different platforms are expected to hash differently even for equivalent trading logic). `computeCrossPlatformSemanticHash` (Q0.8.49) EXCLUDES them (an equivalent MQL4/MQL5 pair hashes identically). Both re-verified passing (`test/mql-parity.test.ts`/`test/q11-mql-platform-fixtures.test.ts`, unmodified), confirming this dual-hash design remains correct and undisturbed by Q1.4.

## Verdict

**Identity integrity holds.** No false-positive or false-negative identity behavior found for any execution-affecting change tested.
