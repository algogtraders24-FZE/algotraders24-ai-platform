**Findings**:
- No circular dependencies.
- One-directional cross-import: `quant-engine/` → `quant_engine/` (Python `sys.path` hack, not a package import).
- `market.db` is a genuinely **shared resource** across three otherwise-unrelated code paths: `quant_engine/db.py` (Python module access), `quant-engine/` (via that module), and the `ea-research/marketplace-research/` M4/M12 pipeline (direct raw SQL, no module import) — this is the one real coupling point that constrains the filesystem decision.
- Hidden/broken dependency: `quant_engine/data_import.py` assumes a `data_raw/` directory relative to the process's current working directory, which does not exist anywhere in this repo — it is effectively dead code today; `quant-engine/scripts/import_exness.py` replaced it as the real data-ingestion path.
- No `requirements.txt`/`pyproject.toml` exists anywhere for the Python side — `pandas`/`numpy` availability is an unstated environment assumption across all of `quant-engine/` and `quant_engine/`.
- `at24-quant-engine/` remains independently understandable and buildable with zero knowledge of the above graph, confirmed by its own automated isolation test.
