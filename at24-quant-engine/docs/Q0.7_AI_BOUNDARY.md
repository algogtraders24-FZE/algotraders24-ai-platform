# Q0.7 AI Boundary

## The one legitimate compiler (Q0.7.46)

`compileAIStrategyToIR(input: AIStrategyCompilerInput, identity: AICompilationIdentity)` (`runtime/strategy-ir/ai-compiler.ts`) is the ONLY path an AI-generated strategy may reach a `StrategyIR` through. `AIStrategyCompilerInput` (`domain/strategy-ir/ai-boundary.ts`) is deliberately narrow: `intent` (free-text, documentation only — never parsed or acted on), `instruments`/`timeframes`, `indicators` (already-typed `IndicatorIR[]`, not free-text formulas), `entryConditions`/`exitConditions` (already-typed `Expression` trees, not natural language), `risk` (Q0.2/Q0.3's `RiskSpecification`, reused verbatim), `executionAssumptions` (Q0.2's `ExecutionSpecification`, reused verbatim). An AI generator is expected to produce THIS structured shape — the compiler does not parse natural language, and never will (that responsibility, if it ever exists, belongs to whatever produces `AIStrategyCompilerInput`, strictly upstream of this boundary).

## No confidence, ever (Q0.7.47)

Neither `AIStrategyCompilerInput` nor the `StrategyIR` `compileAIStrategyToIR()` produces contains a confidence/probability/score field anywhere in their shape — enforced by three independent tests (`test/strategy-ir-ai-boundary.test.ts`): the input's own JSON never contains "confidence"/"probability"; the compiled IR's JSON never contains either; and a static scan of every file in `domain/strategy-ir/` and `runtime/strategy-ir/` confirms neither is ever DECLARED as a field (`/\b(confidence|probability)\s*[?]?\s*:/i` — deliberately pattern-matched against field DECLARATIONS, not bare substring occurrence, so doc-comment prose explaining the deliberate absence doesn't trip a false positive the way Q0.3/Q0.5's own determinism scanners were once caught by literal-substring matches in their own comments).

## AI output MUST first become a StrategyIR

Restated from ADR-004 (Q0's own AI-boundary rule: "AI may propose a StrategySpec; AI may never assign trust, validation, or risk approval"), now extended to the IR layer specifically: `compileAIStrategyToIR()` never calls `runSimulation()`/`runMultiFidelitySimulation()`, never constructs a `SimulationOrder`, and is the ONLY function in this package that accepts an `AIStrategyCompilerInput` at all — there is no second, informal path from AI intent to executable semantics.

## Determinism (Q0.7.53)

`compileAIStrategyToIR()` is a pure function of its two arguments — no randomness, no wall clock, no environment access (statically enforced, `test/strategy-ir-determinism.test.ts`, same scanning pattern every prior sprint's determinism test uses). `sourceHash` is computed FROM the structured `input` itself via `computeCanonicalHash()` (there is no source TEXT for an AI-generated strategy — the structured input IS the source), so two textually-different AI outputs describing the identical structured intent produce the identical `sourceHash` and, given the same `identity`, the identical IR and IR hash.

## `strategyTimezone` is required, never defaulted

`AICompilationIdentity.strategyTimezone` is a required field the CALLER supplies — `compileAIStrategyToIR()` never invents a default (Q0.7.18 permits no implicit timezone anywhere in the IR, and an AI input has no natural "home timezone" to infer one from). The compiler's own choices where the input genuinely under-specifies behavior (accounting mode `NETTING`, `allowPyramiding: false`, reversal `CLOSE_THEN_OPEN`) are all documented, AT24-native defaults — recorded in `positionManagement.reversal.platformDefaultDescription` rather than silently applied, matching Q0.7.30's "platform defaults are never silent" rule even for AT24's OWN compiler.

## What Q0.7 does NOT do

No natural-language parsing of `intent`. No LLM call anywhere in this package (zero external API dependency, matching Q0.7.58's zero-third-party-runtime requirement). No AI-driven risk approval or trust assignment (ADR-004, unchanged). No feedback loop from simulation results back into AI generation (out of scope, undesigned).
