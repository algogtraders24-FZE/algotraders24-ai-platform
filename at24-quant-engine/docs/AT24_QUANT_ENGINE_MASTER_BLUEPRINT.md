# AT24 Quant Engine — Master Blueprint

This is the architectural authority for `at24-quant-engine/`. It consolidates decisions made across Q0, Q0.1, Q0.2, Q0.3, Q0.4, Q0.5, Q0.6, Q0.7, Q0.8, and Q0.9, and is the document a new sprint should read first. Individual sprint documents (`Q0_*`, `Q0.1_*`, `Q0.2_*`, `Q0.3_*`, `Q0.4_*`, `Q0.5_*`, `Q0.6_*`, `Q0.7_*`, `Q0.8_*`, `Q0.9_*`) remain the detailed record; this file is the current-state summary and must be kept current as later sprints extend the engine.

**Q0.5 is the first sprint that actually executes a strategy end-to-end** (D1/OHLC fidelity only). **Q0.6 extends it to D2 (lower-timeframe) and D3 (M1) fidelity** without modifying a single line of Q0.5's frozen simulation core. **Q0.7 builds the canonical cross-platform Strategy IR** — the semantic layer between MT4/MT5/Pine/NinjaScript/cBot/AI-generated strategies and Q0's `StrategySpec`. **Q0.8 builds the FIRST REAL source importer** — a native lexer/parser/semantic-analyzer for MQL4/MQL5, validated against the real, unmodified G01 EA research source (`ea-research/G01_LiquiditySweep_MSS_FVG/`), targeting Q0.7's IR. **Q0.9 builds the missing bridge from an imported `StrategyIR` to actual execution** — an eligibility gate, a pure IR→StrategySpec reducer, and a simulation adapter connecting compiled strategies to Q0.5/Q0.6's frozen engine, proven end-to-end on real MQL4/MQL5 source while G01 correctly remains blocked. See "Simulation Core (Q0.5)", "Multi-Fidelity Simulation (Q0.6)", "Universal Strategy IR (Q0.7)", "MQL4/MQL5 Importer (Q0.8)", and "Strategy Compilation & Simulation Bridge (Q0.9)" below.

## What this is

A fully isolated, standalone TypeScript package (own `package.json`, `node_modules`, test runner) providing a deterministic domain model, a Risk Evaluation layer (Q0.3), a real, deterministic D1-fidelity event-driven simulation engine (Q0.5), D2 (lower-timeframe)/D3 (M1) multi-fidelity execution built on top of it (Q0.6), a canonical Universal Strategy IR for representing strategies from any of MT4/MT5/Pine/NinjaScript/cBot/AT24-native/AI-generated sources (Q0.7), a real, native MQL4/MQL5 source importer targeting that IR (Q0.8), and — as of Q0.9 — a real reduction/compilation bridge that takes an imported `StrategyIR` all the way through to an executed, deterministic simulation result, for representing, versioning, and backtesting trading strategies. Independent of M-Series, the production frontend, any broker/data provider, and any pre-existing Quant prototype in this repo. Zero runtime dependencies, enforced to stay that way by an automated isolation test.

## What this is not

Not the FINAL universal multi-fidelity backtester (D4-D7 — tick/bid-ask/depth/microstructure — remain reserved, not implemented; see `docs/Q0.6_MULTI_FIDELITY.md`), not a parser for Pine/NinjaScript/cBot (only MQL4/MQL5 are implemented — see `docs/Q0.8_MQL_IMPORTER_ARCHITECTURE.md`), not a code generator (no `SourceGenerator` is implemented for any platform), not a full state-machine compiler (G01-style cross-file, multi-bar strategies remain honestly BLOCKED — see `docs/Q0.9_G01_REDUCTION.md`), not a broker integration, not an AI agent, not connected to the marketplace, not connected to M-Series Evidence/Validation/Risk/Trust, not a portfolio engine (single instrument/strategy per run), and not a migration target for the 1,764 pre-existing strategies (yet — Q0.8/Q0.9 are the first real steps). Every one of these is a deliberately deferred future sprint — see "Explicitly deferred" below.

## Architecture at a glance

```
StrategySpec  --(entryRules/exitRules)-->  Expression (AND/OR/NOT/comparison incl. cross_above/cross_below/boolean-reference)
     |                                            |
     | (risk, execution — nested fields)          v (evaluated against)
     v                                       MarketState  <--(computed from)--  MarketSeries + IndicatorDefinition.next()
RiskSpecification / ExecutionSpecification         |
                                                    v
                                                 Signal --> Decision --> OrderIntent --> Position   (contracts only; no
                                                                                          runtime beyond generateSignal())

StrategyVersionRecord (immutable, content-hashed)  |  computeSemanticStrategyHash / computeStrategyIdentityHash (research identity)
BacktestConfig / BacktestResult / ReproducibilityMetadata   (contracts only; no backtest engine)
ResearchExperiment / ResearchResult (RAW vs VALIDATED, gated by markValidated())
MetricSet (computeCoreMetrics — canonical formulas, tested)
FeeModel / SpreadModel / SlippageModel / FillModel / MarginModel / LatencyModel  (behavioral interfaces, no implementation)
MarketStructureEvent family (SwingPoint/BOS/CHoCH/MSS/LiquidityLevel/LiquiditySweep/FVG/OrderBlock/Displacement — type-only)
StrategyTag taxonomy (13 tags, informational only)

Decision --> [Risk Evaluation: evaluateRisk()] --> Order Intent          (Q0.3 — the layer between Decision and OrderIntent)
   RiskEvaluationInput (proposedEntry XOR existingPosition, portfolio/dailyLoss context)
        -> RiskEvaluationResult { outcome: ALLOWED|MODIFIED|REJECTED, action: RiskAction, violations }
   Trade Risk (geometry, R-multiple) / Position Risk (breakeven, trailing, partial-close, holding-period) built;
   Portfolio Risk (exposure, correlation, drawdown, risk budget) reserved as interfaces only, not built
```

## Pending-Order Management (Q0.13 — implemented; real MQL4/MQL5 modify/delete detection reachable end-to-end)

Connects real MQL4/MQL5 pending-order-management source into the already-proven Q0.12 execution architecture, without rewriting it. Three genuinely new layers, kept structurally separate per Q0.13's own critical rule:

```
MQL Source → Semantic Analyzer (new detection) → Strategy IR → Compilation
    → PendingOrderManagementPolicy (strategy INTENT, domain/pending-order-management-policy.ts)
    → SimulationConfig.pendingOrderManagementPolicy (only executableRules())
    → evaluatePendingOrderManagementPolicy() — "Step 0.4", new, before Q0.12's own Step 0.5
```

**Detection** (`domain/mql-importer/semantic-model.ts`'s new `PendingOrderManagementCallSite`, `runtime/mql-importer/semantic-analyzer.ts`'s new detectors): `OrderModify`/`OrderDelete` (MQL4, bare) and `CTrade.OrderModify`/`CTrade.OrderDelete`/`CTrade.PositionModify`/`CTrade.PositionClose` (MQL5) are recorded under their own literal `functionName` — never collapsed into a generic "modify/close." `PositionModify`/`PositionClose` are detected and distinguished but never compiled into pending-order execution (that remains Q0.10's `RiskSpecification.breakeven`/`trailingStop` domain). ## Non-negotiable architectural rules (accumulated across Q0/Q0.1/Q0.2/Q0.3)

1. Isolation is structural, not a promise — enforced by `test/isolation.test.ts` on every test run.
2. Signal, Decision, Order, Position are separate concepts; never collapse them (ADR-003).
3. AI may propose a `StrategySpec`; AI may never assign trust, validation, or risk approval (ADR-004, Q0.2.24).
4. `BacktestResult` is not `Evidence`; a `ResearchResult` is not `VALIDATED` until `markValidated()` says so (ADR-005, Q0.2.13).
5. M-Series (Evidence/Validation/Risk/History/Trust/Marketplace) remains authoritative; only a future, explicitly-built adapter may bridge to it (ADR-006/ADR-010).
6. Strategy versions are immutable; content-hash integrity is checked, not assumed (ADR-007).
7. Everything is deterministic and tested as such — same input, same output, every time (ADR-008).
8. Market data access is provider-independent by construction (ADR-009).
9. Indicators cannot look ahead — structurally, by being incremental step functions, and empirically, by a dedicated test (Q0.2.5).
10. Execution costs are never silently assumed to be zero (Q0.2.15/Q0.2.19).
11. Specification, Evaluation, and Execution are three separate future layers — Q0.2 builds only the first (Q0.2.8).
12. Nothing from OLD (`quant-engine/`, `quant_engine/`, `quant-engine-handoff/`) is a runtime dependency, ever — reimplement, never import (Q0.1, Q0.2.25, Q0.3.25).
13. A merge from OLD or from an AI-proposed spec requires evidence, not just "it works" (`Q0.2_FUTURE_MERGE_POLICY.md`).
14. Risk Specification, Risk Evaluation, and Execution are three separate layers — Q0.3 builds the second, never the third; `evaluateRisk()` returns instructions (`RiskAction`), it never fills an order, mutates a `Position`, or applies slippage/spread/commission (Q0.3.8, Q0.3.23).
15. Risk Evaluation is pure — `evaluateRisk(input)` never mutates `input`, never reads the wall clock or `Math.random()`, and identical input always produces an identical result (Q0.3.17/Q0.3.18, enforced by a static source scan in `risk-determinism.test.ts`).
16. Conflict resolution is explicit, never implicit — when multiple risk rules could trigger simultaneously, the priority order is documented in code and tested (`pipeline.ts`'s doc comment, `Q0.3_RISK_SEMANTICS.md`); safety constraints (max holding period) always dominate optimization/management constraints (breakeven/trailing/partial-close) (Q0.3.15).
17. Intrabar/same-bar ambiguity is never resolved silently in the trader's favor — the default resolution is always Conservative, "Optimistic" resolution exists only as an explicitly-labeled, opted-into research mode, never a default (Q0.4.10, `Q0.4_INTRABAR_ENGINE.md`).
18. No source-platform translation may claim `EXACT` Source Fidelity without deterministic differential-replay evidence — `SEMANTICALLY_EQUIVALENT`/`APPROXIMATE`/`UNSUPPORTED` are the honest defaults absent that proof (Q0.4.34).
19. Execution Reality Grade, Statistical Robustness, and Strategy Quality are three permanently separate concepts — never merged into one score, never used as a proxy for one another (Q0.4.36/37).
20. Any future construct permitting intentional lookahead (for deliberate research purposes only) must be named as bluntly as Backtrader's `cheat_on_open`/`cheat_on_close` — never given an innocuous-sounding name (Q0.4, `Q0.4_ADOPT_IMPROVE_AVOID_INVENT.md`).
21. An order created from a bar's signal is never resolved against that same bar — exactly one documented timing rule (next-bar-open eligibility), enforced structurally by the event flow AND by an explicit guard, never left to chance (Q0.5.30, `docs/Q0.5_SIMULATION_ARCHITECTURE.md`).
22. Event/order/trade identity must never depend on what data exists in the future — sequence numbers are assigned only as of what has actually been processed, not what the input contains (Q0.5, `docs/Q0.5_DETERMINISM.md` — a real bug this sprint found and fixed).
23. Historical records (Order/Trade/Position/Account) are immutable after creation — every simulation state transition returns a new object; `TradeLedger` freezes every record it stores (Q0.5.38, `docs/Q0.5_POSITION_ACCOUNT.md`).
24. A frozen, tested execution core is never modified to accommodate a new capability — a new capability is built ON TOP, reusing the frozen core's functions directly, even at the cost of duplicating outer control-flow shape (Q0.6, `docs/Q0.6_D2_D3_EXECUTION.md` — Q0.5's `simulation-engine.ts`/`bar-fill-model.ts` remain byte-for-byte unmodified by Q0.6).
25. A `BarDetailProvider` (or any future data-detail source) must filter strictly by the requested parent interval — never by what else happens to exist in its backing dataset — so a later interval's data structurally cannot leak into an earlier query, regardless of load order (Q0.6.23/24, `docs/Q0.6_MTF_SAFETY.md`).
26. Higher data detail (more granular child bars) is never conflated with higher execution realism (spread/slippage/fee/latency modeling) — they are permanently separate axes, machine-readable as separate fields (`FidelityQuality` vs. `SpreadModel`/`SlippageModel`/`FeeModel`/`LatencyModel`), never merged into one score (Q0.6.36/37, `docs/Q0.6_D2_D3_EXECUTION.md`).
27. A source parser must never directly create executable orders — the pipeline is parse -> semantic validation -> canonicalization -> IR validation -> execution compatibility -> simulation, and no shortcut across those stages is permitted (Q0.7.37, `docs/Q0.7_TRANSLATION_CONTRACT.md`).
28. An HTF observation is available to a lower-timeframe evaluation only at the instant the HTF bar CLOSES, never before — restated from `Q0.4_LOOKAHEAD_REPAINTING.md` and now enforced by the IR validator as a BLOCKING condition, with no opt-in "unsafe" execution mode (Q0.7.20, `docs/Q0.7_MTF_SEMANTICS.md`).
29. A strategy with unresolved repainting semantics (`UNKNOWN` or `REPAINTING`) must never receive a clean "validated for execution" status, independent of whether it is otherwise structurally well-formed — structural validity and execution eligibility are deliberately different questions (Q0.7.22, `docs/Q0.7_LOOKAHEAD_REPAINTING.md`).
30. Parsing and semantic interpretation are genuinely separate passes — a parser produces structure with zero trading-strategy meaning; exactly one downstream pass (the semantic analyzer) assigns meaning; no "text-to-IR regex parser" shortcut collapses the two (Q0.8's own critical rule, `docs/Q0.8_MQL_IMPORTER_ARCHITECTURE.md`).
31. A source construct this package cannot resolve (a call into an unanalyzed `#include`, an unrecognized preprocessor directive, an unprovable new-bar/cross pattern) is always recorded honestly as unresolved/unprovable — never guessed at, never silently dropped, never fabricated into a plausible-looking but invented semantic (Q0.8's critical success criterion: "DO NOT GUESS. Report it.").
32. Two IRs describing the same trading logic from different source platforms must hash identically under a hash that EXCLUDES platform-identity fields, while still hashing differently under the hash that INCLUDES them — both are correct answers to different questions, and neither is allowed to silently stand in for the other (Q0.8.49, `docs/Q0.8_MQL4_MQL5_PARITY.md`).
33. The reducer must never invent missing behavior — a `StrategyIR` shape the eligibility gate cannot prove Q0.5/Q0.6 can actually execute is `BLOCKED` with no `StrategySpec` at all, never a partial or best-effort one; the engine must prefer an honest block over fake execution (Q0.9's own critical rule, `docs/Q0.9_REDUCTION_ARCHITECTURE.md`).
34. A frozen execution core's missing runtime guarantee (Q0.5's `generateSignal()` has no warmup guard) is compensated for entirely in the NEW calling layer, never by modifying the frozen file — `compileToSimulation`'s warmup-slicing lives wholly in `simulation-adapter.ts` (Q0.9, `docs/Q0.9_SIMULATION_BRIDGE.md`), extending rule 24's "build on top, never modify the frozen core" discipline to a bug fix, not just a new feature.
35. An "assume the platform default" inference is legitimate only when its absence-of-override signal is itself directly checkable evidence (zero detected position-management calls), never a bare assumption of convenience — the moment any such call is detected, the conservative path applies unconditionally (Q0.9's netting-default rule, `docs/Q0.9_SEMANTIC_LOSS.md`). Refined in Q0.10: the checkable evidence must itself distinguish genuine gating/counting calls from pure value accessors a management pattern is required to call to compute its own trigger — an accessor is not "override logic" (`docs/Q0.10_POSITION_MANAGEMENT_AUDIT.md`).
36. A protective stop (breakeven or trailing) may only ever move in the risk-reducing direction — enforced structurally by comparing every proposal against the current stop before accepting it, never merely by convention (Q0.3's original rule, formally re-verified end-to-end through the real simulation engine by Q0.10, `docs/Q0.10_BREAKEVEN.md`/`docs/Q0.10_TRAILING.md`).
37. R-multiple is always computed from a position's risk basis AT ENTRY, never its current (management-mutable) stop — a frozen execution core's own historical field (`Position.stopLoss`, dual-purposed for both protective-exit triggering and R-multiple reporting before Q0.10) may gain an ADDITIVE field to disambiguate the two meanings when, and only when, no other extension point exists and the change is proven behavior-neutral for every existing test (Q0.10's `initialStopLoss` fix, `docs/Q0.10_POSITION_MANAGEMENT_AUDIT.md` — extending rule 24's "build on top" discipline to the narrow case where "on top" is provably impossible).
38. Every management action recorded is deterministic and ledger-auditable — no management rule may silently disappear during compilation (an unresolvable MQL pattern falls back to the existing honest "detected but unresolved" reporting, never a fabricated rule and never a dropped one) (Q0.10, `docs/Q0.10_MQL_MANAGEMENT.md`/`docs/Q0.10_FAILURE_CATALOG.md`).
39. A trigger price is never assumed to equal a fill price — every order type's gap-through behavior is explicit and asymmetric by design (a LIMIT gap is always favorable-or-equal, a STOP gap is always unfavorable-or-equal, never smoothed into one "the order filled at its requested price" simplification) (Q0.11, `docs/Q0.11_GAP_EXECUTION.md`).
40. An unsupported price reference (no live bid/ask feed exists in this simulation model) is named explicitly and BLOCKED, never approximated with an OHLCV proxy — `BID`/`ASK` exist as recognized `PriceReference` kinds specifically so they can be detected and rejected, not because they are supported (Q0.11.3, `docs/Q0.11_ORDER_SEMANTICS.md`).
41. A capability that lets an order remain PENDING across more than one bar must be re-verified against every existing "no duplicate entry" assumption built when every order resolved within one bar — Q0.11's own `hasPendingOrder` fix is the second instance of this class of gap (the first being Q0.10's R-multiple fix), establishing it as a recurring category, not a one-off (`docs/Q0.11_ORDER_SEMANTICS.md`).
42. A fidelity tier that duplicates a frozen core's outer control-flow shape (Q0.6's D2/D3 engine, rule 24) must be re-checked for parity every time that frozen core's OWN calling layer gains a new capability — duplicated control flow means a fix in one copy is invisible to the other until explicitly mirrored, proven the hard way when Q0.11's order-type threading fix, made only in `simulation-engine.ts`, silently left D2/D3 treating every entry as MARKET until Q0.11's own D1/D2 compatibility test caught it (`docs/Q0.11_GAP_EXECUTION.md`).
43. Any modification/cancellation/replacement of a pending order resolves purely from explicit step ordering — never wall-clock timing, never an incidental code-path accident — and every one of its outcomes (including "rejected because the target is missing or already terminal") must be explicitly recorded, never silently skipped (Q0.12's own race-fixture testing found and fixed exactly this silent-skip gap; `docs/Q0.12_RACE_SEMANTICS.md`).
44. A pending-order-acting contract and a position-acting contract never share a type, a validator, or an evaluation function, even when their operations are name-alike (Q0.12's `OrderModificationIntent.MODIFY_STOP` vs. Q0.10's `PositionManagementInstruction`'s `MODIFY_STOP` risk action) — two genuinely different lifecycle stages are never collapsed into one vocabulary merely because the English name matches (Q0.12.30, `docs/Q0.12_ORDER_MODIFICATION.md`).
45. A strategy-authored management/modification operation may only compile into an executable rule when EVERY one of target, condition, and operation is independently provable — a good condition never rescues an unresolvable target or price, and vice versa; the moment any one of the three cannot be resolved without guessing, the whole rule is recorded (never dropped) but excluded from execution (Q0.13's own "never convert uncertain source behavior into an executable approximation" rule, `docs/Q0.13_PENDING_ORDER_MANAGEMENT.md`).
46. A per-feature/per-rule resolution gap must never be escalated to whole-strategy-blocking severity merely for reporting convenience — `BLOCKING`-severity `UnsupportedSemantic` is reserved for genuine, IR-wide execution-eligibility failures (Q0.7.31's frozen "any BLOCKING entry fails the whole IR" rule); a single unresolved management rule uses `WARNING`, exactly matching Q0.10's own established precedent, so the STRATEGY still reduces successfully around it (Q0.13, `docs/Q0.13_COMPILATION.md` — a real regression this sprint's own test suite caught and fixed before it shipped).
47. A contract-closure/audit sprint's job is to VERIFY and PRECISELY DOCUMENT, never to silently patch — a real gap found during audit (e.g. `PyramidingPolicy.maxEntries`/`maxPositions` existing as a type field but being enforced nowhere in `src/`) is recorded as a known limitation with exact evidence, not fixed reflexively; fixing it is a deliberate, separate, future decision (Q1.4, `docs/Q1.4_FUTURE_PLATFORM_CONTRACT_CHECK.md`).
