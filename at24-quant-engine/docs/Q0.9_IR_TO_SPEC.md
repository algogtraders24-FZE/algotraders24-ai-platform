# Q0.9 IR → StrategySpec Mapping

How `reduceStrategyIRToSpec()` (`src/runtime/reduction/ir-to-spec-reducer.ts`) builds each `StrategySpec` field from an eligible `StrategyIR`. Every field is either a direct passthrough (never rebuilt) or a narrow, provable transformation — never an invented value.

| StrategySpec field | Source | Transformation |
|---|---|---|
| `identity.strategyId` | `ir.strategyId` | passthrough |
| `identity.name` | `ir.metadata.name` | passthrough |
| `metadata` | `ir.metadata` (minus `name`, which moves to `identity`) | passthrough |
| `instruments` / `timeframes` | `ir.instruments` / `ir.timeframes` | passthrough |
| `entryRules` | `ir.entries` | direction cast to `BUY \| SELL`; condition passed through as-is |
| `exitRules` | — | **always `[]`** — Q0.5's engine never evaluates `exitRules`; STOP_LOSS/TAKE_PROFIT are risk-driven, not condition-based (this is exactly why `SIGNAL_EXIT`/`SESSION_EXIT` exits are eligibility-blocking rather than silently dropped) |
| `risk` | `ir.risk` | direct reference passthrough (Q0.2/Q0.3's own `RiskSpecification`, unmodified) |
| `execution` | `ir.execution.declared` | direct reference passthrough (Q0.2's own `ExecutionSpecification`, unmodified) |

## Entry condition reconstruction (the reducer's one real inference)

`ir.entries[i].condition` for an MQL-imported strategy is either:

- a **real** `Expression` — when the semantic analyzer proved a `SimpleEntryConditionSite`: `if (indicatorA <op> indicatorB)` or `if (indicator <op> literal)` (RSI-style threshold), with the winning branch containing a resolvable BUY/SELL order call. Both sides are resolved via `EntryConditionOperand` (`{kind:"indicator",ref}` or `{kind:"literal",value}`), tracked per-function, never across function boundaries.
- the **honest placeholder** `UNREPRESENTABLE_CONDITION` (`1 == 0`, i.e. never fires) — for anything else, including G01's real cross-file, multi-bar state machine. This is what `checkReductionEligibility` detects and blocks on (the `"entry/exit signal logic"` unsupported-semantic marker Q0.8 already recorded).

There is no third option and no partial credit: a condition is either fully reconstructed as real Expression logic, or the strategy is blocked. The reducer never emits a "mostly right" condition.

## Risk-leg (SL/TP) reconstruction

`OrderCallSite.slBinding`/`tpBinding` (built by the semantic analyzer's `resolveRiskLegBinding`) recognize exactly two arithmetic shapes:

- `<price> ± <literal>` → `{ type: "fixed-distance", distance: |literal| }`
- `<price> ± (<atrVar> * <literal>)`, where `<atrVar>` is bound to a recognized ATR indicator call → `{ type: "atr-multiple", atrMultiple, atrPeriod }` (SL only — Q0.2's `TakeProfitRule` has no atr-multiple variant, so an ATR-based TP formula stays unresolved)

`ir-generator.ts`'s `bindingToRule()` converts these into real `StopLossRule`/`TakeProfitRule` values. If SL and TP are both present in the source but either fails to resolve to one of these two shapes, the whole risk leg stays unset and the strategy is BLOCKED (`ir.risk.stopLoss`/`takeProfit === undefined` triggers the eligibility gate's exit-kind check) — never a guessed distance.

## What is deliberately NOT reduced

- Trailing stop, breakeven, partial close (`RiskSpecification.trailingStop`/`breakeven`/`partialClose`) — present in Q0.2's contract and exercised by Q0.7's own golden fixtures, but not yet wired through the eligibility gate; any IR declaring one currently blocks for a different, unrelated reason (non-ACCUMULATE pyramiding in the golden fixtures) rather than for the trailing/breakeven/partial-close field itself. Extending the gate to explicitly recognize and pass these through is deferred to a future sprint.
- LIMIT/STOP/STOP_LIMIT `executionType` — accepted structurally (Q0.5/Q0.6 implement all four order types), but no golden fixture here exercises a non-MARKET entry through the full MQL import path.
