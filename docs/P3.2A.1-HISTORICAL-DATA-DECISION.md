## Implementation

`frontend/services/algo-test/historical-data/twelve-data-provider.ts` — `TwelveDataHistoricalDataProvider implements HistoricalDataProvider`:
- Calls `https://api.twelvedata.com/time_series` with `symbol`, `interval`, `start_date`, `end_date`, **`timezone=UTC`** (verified below to matter — omitting it silently shifts bar alignment), and the existing `TWELVEDATA_API_KEY` (via the existing `loadTwelveDataEnv()` helper — no new credential).
- Symbol/interval mapping is a small, explicit, manually-kept-in-sync mirror of `twelve-data.provider.ts`'s own internal `SYMBOL_MAP`, matching this codebase's own established convention for that adapter (per `instrument-catalog.ts`'s own header comment: "twelve-data/alpha-vantage adapters... never rewritten to read from this catalog... a truthful, manually-kept-in-sync mirror").
- Runs every bar through the **same** `validateBars()` P3.2A already built and verified — zero new validation logic.
- No volume data from Twelve Data for XAU/USD (confirmed empty in the real response) — `volume: 0`, disclosed, never fabricated (matches this platform's existing honesty convention for spot FX/metal volume elsewhere).

### A real correctness bug caught by testing, not assumed away

An initial test call **without** `&timezone=UTC` returned 1,272 bars for the target week; the same call **with** `&timezone=UTC` returned 1,344 bars, with the oldest bar landing exactly on the requested `2024-01-08T00:00:00Z` boundary. Twelve Data's `/time_series` `datetime` field is documented as exchange-local by default, not UTC — omitting the parameter would have silently misaligned every bar's timestamp against the engine's UTC-assumed `OHLCVBar.timestamp`. Every request in the shipped code passes `timezone=UTC` explicitly; never assumed.

## Known limitations, disclosed not hidden

1. **Single-request range cap**: this implementation issues one HTTP request per backtest run; very wide date ranges at fine timeframes could hit Twelve Data's per-request bar cap. Not hit in this sprint's tested range (1,344 bars, comfortably within typical vendor limits). Pagination is a real, named future task if P3.2B needs multi-month backtests — not built here (Gate 5: "do not over-engineer").
2. **API cost/rate limits**: every Algo Test run now costs real Twelve Data API credits. Acceptable for this foundation sprint's proof; a caching layer (mirroring the existing `TtlCache` pattern the live-quote adapter already uses) is a reasonable, cheap future addition once usage volume is real.
3. **`market-db-provider.ts` remains real and useful for local/offline dev** (P3.2A) — not removed, not deprecated, just no longer the production path. Both implementations satisfy the identical `HistoricalDataProvider` interface, so P3.2B's API layer can select either without any other code changing.
