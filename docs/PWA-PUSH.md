# AT24 installable app (PWA) and push notifications

The site is now an installable web app, and Live Sync alerts can arrive as notifications on a phone or computer. No app store, no native app. The push part is **dormant** until the owner generates a key pair and sets the variables below; the installable-app part works as soon as it is deployed.

## What users get

- **Install:** Android/Chrome/Edge show an "Install" offer (and a slim bar on phones, dismissible for 30 days); iPhone/iPad users get the steps (Share > Add to Home Screen). The app opens full-screen on the dashboard with the AT24 icon and has shortcuts to Live Results, Live Sync and the marketplace.
- **Notifications (Live Sync > "Notifications on this device"):** after allowing notifications, the user's Live Sync alerts (margin, daily loss, drawdown, EA offline, no stop loss) and "a watched page stopped reporting / is back" notices also arrive as push notifications; tapping one opens the right page. Two switches per device, a test button, "turn off on this device". Up to 5 devices per user. Free. It only informs.
- **iPhone note:** iOS (16.4+) only delivers web push to an app that was added to the Home Screen, so the panel tells iPhone users to install first.

## Safety design

- **The service worker caches nothing and has no fetch handler** (a signed-in dashboard must never be served from a cache: stale numbers, or one user's data left on a shared device). It only shows a notification and opens a page. The tap target is only ever a **path on this site** (anything else falls back to the dashboard); title/body are untrusted text, cut and shown as plain text.
- **SSRF guard:** the server later POSTs to a subscription's endpoint, a URL the browser (or an attacker with a login) supplies. An endpoint is accepted only if it is **https, no credentials, port 443, no IP literal and a host of a real push service** (`fcm.googleapis.com`, `updates.push.services.mozilla.com`, `web.push.apple.com`, `*.push.apple.com`, `*.notify.windows.com`). The check runs when it is stored and again when it is used (tested against localhost, 127.0.0.1, 169.254.169.254, private IPs, IPv6, look-alike hosts such as `fcm.googleapis.com.evil.example`, userinfo tricks, wrong ports and wrong schemes).
- Delivery is best effort and **never blocks or fails an alert**; a push service answering 404/410 deletes the subscription, and 5 failures in a row drop it. An endpoint belongs to exactly one user.
- The VAPID **private key** is a secret (Vercel only). The public key is served to signed-in users by `GET /api/private/push`.

## Owner setup for push (about 5 minutes, once)

1. Generate a key pair on your PC (PowerShell or cmd, in `frontend`): `npx web-push generate-vapid-keys`. It prints a **Public Key** and a **Private Key**. The private key is a secret: only Vercel, never chat/git/screenshots.
2. On **Vercel (Production)** add:
   - `PUSH_ENABLED=true`
   - `VAPID_PUBLIC_KEY=<the Public Key>`
   - `VAPID_PRIVATE_KEY=<the Private Key>`
   - `VAPID_SUBJECT=mailto:<a support email you read>` (push services use it to contact you if there is a problem)
   then redeploy.
3. Open *Live Sync* on your phone (or computer), press **Turn on notifications**, allow them, then **Send a test notification**.

Until then the panel is hidden and nothing is sent. Installing the app works without these variables.
