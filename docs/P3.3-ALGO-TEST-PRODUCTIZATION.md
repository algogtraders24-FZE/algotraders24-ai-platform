**Status:** Implemented and regression-verified locally; production merge/live-E2E tracked in §9 below (updated once merged, per this program's established `feat/... -> compare-URL PR -> user merges -> post-merge live smoke test` workflow — direct push to `main` remains blocked by this environment's own classifier).

## 1. Objective

Upgrade P3.2B's single-Golden-Strategy demo path into a reusable Algo Testing foundation, **without building a second backtest engine**. Every backtest still runs through the existing `at24-quant-engine` (`runSimulation()`/`buildGoldenStrategySpec()`), the existing Twelve Data historical-data abstraction, and the existing Native Chart renderer. This sprint is productization — registry, versioning, validation, reopen — not new execution capability.

## 2. Mandatory scope boundary — Quant Lite

`app/quant-lite/**`, `services/quant-lite/**`, `quant-engine/**` were **not touched** — verified by `git diff --stat -- frontend/app/quant-lite frontend/services/quant-lite frontend/quant-engine` producing zero output at every commit of this sprint, the same discipline every prior P3.x sprint has followed. No requirement in this sprint needed a Quant Lite change.

## 4. API contract (canonical request shape, per spec §6)

```ts
interface AlgoTestRunRequest {
  strategyId: string;
  strategyVersion?: string;   // optional pin - server always resolves+records the exact version either way
  symbol: string;
  timeframe: string;          // SignalTimeframe-shaped, e.g. "5m"
  startTime: string;          // ISO 8601
  endTime: string;            // ISO 8601
  initialBalance?: number;
}
```

No execution configuration is invented client-side beyond this — spread/slippage/fee/margin remain the engine's own zero-cost/unenforced placeholders, disclosed verbatim via `AlgoTestAssumptions` exactly as P3.2B established (unchanged this sprint, per the sprint's explicit "do not silently add broker costs" instruction).

## 5. Authentication & Authorization

- **Authentication**: every `app/api/private/algo-test/**` route calls `getUserOrNull()` first and returns `401 UNAUTHORIZED` if absent — unchanged pattern, reconfirmed for the new `strategies` route.
- **Authorization**: `algoTestService.getAlgoTestRun(userId, testId)` filters by `{ id: testId, userId }` — a run belonging to a different user is indistinguishable from a nonexistent one, both returning `404 NOT_FOUND`. This is a **deliberate pre-existing pattern** (documented in `runs/[id]/route.ts`'s own header comment since P3.2B: "never leaking existence"), preserved as-is this sprint as **the project's established equivalent** of a 403, per the sprint spec's own permissive language ("403 or the project's established equivalent"). Verified live in `scripts/validate-algo-test-service.ts`: a real second user cannot fetch another user's real run id.

## 6. Provider / data error handling

Unchanged from P3.2B, reconfirmed this sprint: `toAlgoTestErrorCode()` maps "no historical bars" / Twelve Data's own "no data available" response to `NO_HISTORICAL_DATA`; every other provider failure (auth/rate-limit/transport/parse) stays the more honest, less specific `PROVIDER_ERROR` — no credential, provider secret, stack trace, or filesystem path is ever surfaced in an error message returned to the client (unchanged code path, `algoTestService`'s own `catch` blocks only ever forward `err.message`, and the provider layer itself never includes secrets in a thrown `Error`'s message).

## 7. Out of scope (explicitly not built)

Exactly as the sprint spec's own exclusion list: AI/natural-language strategy generation, MQL importer UI, marketplace integration, live/real trading, paper trading changes, broker execution, optimization/genetic search/parameter sweeps, walk-forward, Monte Carlo, tick/L2 simulation, multi-symbol portfolios, multi-timeframe strategy expansion, a new execution-cost model, a new market-data provider, any Quant Lite migration, a TradingView dependency, or a second backtest engine. Nothing in this sprint's implementation required crossing into any of these.
