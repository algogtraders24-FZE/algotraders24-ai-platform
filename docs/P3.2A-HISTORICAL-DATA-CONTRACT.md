# P3.2A — Historical Data Contract (Blocker 2)

**Status:** Implemented and verified against real data.

---

## Step 1 — What was inspected before building anything new

Per the brief's "do not create a new market-data system if an existing suitable source is available" instruction, three existing sources were inspected before writing any new code:

1. **Native Chart's live-quote providers** (Twelve Data / Alpha Vantage / Binance / Angel One / MT5, via `MarketDataService.getTimeSeriesWithProvenance()`) — confirmed (again, directly) to support only latest-N-bars queries, no `startTime`/`endTime` range parameter anywhere in any of the 5 adapter files. Not suitable as-is.
2. **The MT5 bridge** (`mt5-bridge/bridge.py`, the platform's real, VPS-hosted, PRIMARY market-data provider) — its one `/candles` endpoint calls MT5's `copy_rates_from_pos(symbol, timeframe, 0, count)`, which is explicitly position-based ("give me the last N bars"), not `copy_rates_range(symbol, timeframe, date_from, date_to)` (MT5's own date-range API, which exists but is not exposed by this bridge today). Extending the bridge to add a range endpoint is a real, viable *future* option — but it requires modifying and redeploying a live, VPS-hosted production service (paper trading and the live chart both depend on it), which is a materially different risk profile than a local, additive code change, and was not attempted in this foundation sprint.
3. **Quant Lite's existing dataset** (`quant_engine/market.db`, a 2GB local SQLite file, real Exness-tick-derived OHLCV) — inspected directly via its own schema (`candles` table: `symbol, timeframe, ts, open, high, low, close, volume`; `symbols` table listing `XAUUSD_EXNESS`, `EURUSD_EXNESS`, `GBPUSD_EXNESS`, `USOIL_EXNESS`, `BTCUSD_EXNESS`). Confirmed real, substantial coverage for `XAUUSD_EXNESS` at `5m`: **116,387 bars, 2024-01-01T23:05:00Z → 2026-05-31T23:55:00Z**.

## Decision: an isolated adapter over `market.db`, not a new data-acquisition system

Chosen because it is the only one of the three that is (a) real, (b) already covers a genuine date range for XAUUSD at M5, and (c) requires zero deployment risk to use — it is a local file the current environment already has. The "not allowed: Pro Engine → Quant Lite database internals" rule (per `P3.2A-QUANT-LITE-BOUNDARY.md`) is satisfied because the new provider (`services/algo-test/historical-data/market-db-provider.ts`) opens its **own** read-only SQLite connection and runs its **own** query — it imports zero code from `services/quant-lite/**`. `market.db` is read exactly as raw data, the same way a CSV would be.

**A real, disclosed limitation**: `market.db` is a 2GB file, gitignored (confirmed — it does not exist in any `git worktree`, including the one used to build and test this sprint's own code, which required pointing `AT24_MARKET_DB_PATH` at the real machine-local file to run the Golden Run). This provider therefore only works where that specific local file is reachable — the current dev machine, not a fresh clone, not CI, not a Vercel deployment. This is not solved in this sprint (out of scope — the brief's target is proving the pipeline, not shipping production data infrastructure) and must be solved before P3.2B ships anything to real users: either by extending the MT5 bridge (option 2 above, now the clear front-runner for a real deployment story) or by hosting `market.db`'s data somewhere reachable from a deployed environment.

## Provider boundary

```ts
// services/algo-test/historical-data/types.ts
export interface HistoricalDataProvider {
  readonly id: string;
  getBars(request: HistoricalBarsRequest): Promise<HistoricalBarsResult>;
}

export interface HistoricalBarsRequest {
  symbol: string;        // canonical AT24 symbol, e.g. "XAUUSD" - never broker-suffixed
  timeframe: Timeframe;  // at24-quant-engine's own enum, e.g. "M5"
  startTime: string;     // ISO 8601 UTC
  endTime: string;       // ISO 8601 UTC
}

export interface HistoricalBarsResult {
  bars: readonly OHLCVBar[];       // at24-quant-engine's own type, imported not redefined
  rejected: readonly BarRejection[]; // every rejection surfaced, never silently dropped
  source: string;
}
```

The engine receives `OHLCVBar[]` — `at24-quant-engine`'s own type, imported directly from the package — and has zero knowledge that a `HistoricalDataProvider` or `market.db` exists. `MarketDbHistoricalDataProvider` is one implementation of the interface; a future MT5-bridge-backed implementation would be a second, interchangeable one, with no changes needed anywhere downstream.

## Historical Bar Contract

| Field | Definition |
|---|---|
| `timestamp` | epoch **milliseconds**, UTC — matches both `at24-quant-engine`'s `OHLCVBar.timestamp` and Native Chart's `ChartCandle.time` exactly (no conversion needed downstream) |
| `open`/`high`/`low`/`close` | `number`, whatever precision the source provides (market.db stores full float precision from the original Exness tick feed) |
| `volume` | `number`, `>= 0`, defaulted to `0` if the source row has `NULL` (never `undefined` — the engine requires a real number) |
| **Timezone** | UTC throughout, no exceptions (market.db's own `ts` column is stored as ISO 8601 with an explicit `+00:00` offset) |
| **Ordering** | strictly increasing timestamps, enforced by `validateBars()` (see below) — not just assumed from the SQL `ORDER BY` |
| **Symbol normalization** | canonical AT24 symbol (`"XAUUSD"`) ↔ market.db's broker-suffixed key (`"XAUUSD_EXNESS"`), via a fixed, explicit lookup table (`symbol-timeframe-map.ts`) — an unmapped symbol is refused, never guessed |
| **Timeframe normalization** | engine's `Timeframe` enum (`"M5"`) ↔ market.db's lowercase shorthand (`"5m"`), same fixed-table approach |
| **Price precision** | passed through as-is from the source; this provider does not round or coerce precision |
| **Volume semantics** | tick-count-style volume as stored in market.db (`tick_volume`-equivalent), not a claim of real traded lot volume — same honesty caveat this platform already applies elsewhere to spot FX/gold volume |
| **Missing candles** | legitimate gaps (market closed, feed outage) are left as gaps, never fabricated/interpolated |
| **Duplicate candles** | rejected by `validateBars()`, first occurrence kept |
| **Invalid OHLC** | rejected by `validateBars()` (see below), never silently corrected |

## Validation (`services/algo-test/historical-data/validate-bars.ts`)

Runs on every bar returned by a provider, before the engine ever sees it. Enforces exactly what the brief specifies:

- `timestamp[n] < timestamp[n+1]` — strict increase; a violation is rejected as `OUT_OF_ORDER`, not silently reordered.
- `high >= max(open, close)`, `low <= min(open, close)`, `high >= low` — a violation is rejected as `INVALID_OHLC` with the exact reason in the message.
- Duplicate timestamps — rejected as `DUPLICATE_TIMESTAMP`, first occurrence kept.
- Symbol/timeframe mismatch against the request — rejected as `SYMBOL_MISMATCH`/`TIMEFRAME_MISMATCH`.
- Non-finite values and negative volume — also rejected as `INVALID_OHLC`.

Every rejection is returned to the caller (`HistoricalBarsResult.rejected`), never silently dropped or fabricated over. Verified by 8 dedicated unit tests in `scripts/validate-algo-test-foundation.ts` (synthetic bars specifically engineered to trigger each rejection reason) plus a 9th confirming the real `market.db` XAUUSD/M5 data for the chosen validation window produces **zero rejections** (it's real, clean data).
