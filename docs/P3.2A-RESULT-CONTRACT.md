# P3.2A — Pro Algo Test Result Contract (foundation-scope)

**Status:** Minimal composition implemented and verified (`services/algo-test/run-golden-backtest.ts`). This is deliberately NOT the full P3.2B `runBacktest(request)` HTTP API/Prisma-backed contract — no routes, no persistence, no UI were built in this sprint (Hard Scope Boundary). This document defines the shape now so P3.2B has a stable target, and records what was actually proven to work.

---

## `runBacktest`-shaped composition (foundation implementation)

```ts
// services/algo-test/run-golden-backtest.ts
export interface GoldenBacktestRequest {
  symbol: string;
  timeframe: Timeframe;
  startTime: string;
  endTime: string;
  initialBalance: number;
}

export async function runGoldenBacktest(
  request: GoldenBacktestRequest,
  provider: HistoricalDataProvider,
): Promise<GoldenBacktestOutcome>
```

This calls the **existing** deterministic simulation engine directly (`runSimulation()` from `at24-quant-engine`) — no new simulator was written, per the brief's explicit instruction. The full P3.2B contract (`strategy`, `symbol`, `timeframe`, `startTime`, `endTime`, `initialBalance`, `riskConfig`, `executionConfig`, `historicalData`) is already specified in `docs/P3.1-QUANT-CHART-CONTRACT.md` §1 — nothing about that specification changed; this sprint only implements and proves the narrow slice needed to close Blocker 2 (fixed Golden Strategy, fixed historical range, real bars).

## Result shape

```ts
export interface GoldenBacktestOutcome {
  result: SimulationResult;   // at24-quant-engine's own real, unmodified result type
  barsUsed: number;
  barsRejected: number;
  dataSource: string;
  equityCurve: readonly { timestamp: number; balance: number }[];  // DERIVED, see below
}
```

Maps directly onto the minimum result contract requested (`testId`, `status`, `strategy`, `symbol`, `timeframe`, `period`, `assumptions`, `metrics`, `trades`, `equityCurve`) — the foundation implementation proves `metrics`, `trades` (as `result.tradeLedger`), and `equityCurve` are all real and internally consistent; `testId`/`status`/persisted `assumptions` metadata are P3.2B concerns (they require the Prisma model and API route this sprint does not build).

**`equityCurve` is derived, not engine-computed** — confirmed again in this sprint (per `P3.1-QUANT-CHART-CONTRACT.md` §2): the real `SimulationResult` has no `equityCurve` field. `deriveEquityCurve()` builds one as a running balance sum over `result.tradeLedger`'s own `netPnl` values, in ledger order — a pure display projection of already-final numbers, not a second calculation path. Verified equal to `finalAccount.balance` at its last point (see Result Consistency below).

**Native Chart must consume this, never recompute it** — nothing in this sprint's code recalculates P&L, win rate, or any metric independently; every number displayed anywhere downstream must trace back to `result.tradeLedger`/`result.metrics`/`result.finalAccount` as-is.

## Trade Contract

`at24-quant-engine`'s real `SimulationTrade` was used **exactly as-is** — no second, chart-specific trade ledger was created, per the brief's explicit instruction:


**`stopLoss`/`takeProfit`/`exitReason` are still not present on `SimulationTrade`** — this was flagged as a known, small, additive gap in `P3.1-QUANT-CHART-CONTRACT.md` §3 and remains unresolved here (out of this sprint's scope; the foundation's Golden Run doesn't need per-trade SL/TP/exitReason to prove the pipeline, only P3.2B's chart-marker rendering will). Documented again here so it isn't lost.

## Result Consistency — verified against a REAL Golden Run

Run against real XAUUSD M5 data (`2024-01-08T00:00:00Z` → `2024-01-13T00:00:00Z`, 1,368 bars, the engine's own unmodified Golden Strategy):

```
resultHash:  44e618e7b96f3874aa320774a75dc039f9bafa8ea65e8ec30ad2f7f5771d10da
trade count: 27
winRate:     33.33%
netProfit:   -0.211
finalAccount.balance: 9999.789
```

Verified programmatically (`scripts/validate-algo-test-foundation.ts`, "Result consistency" section):
- `metrics.netProfit` equals a hand-summed `Σ tradeLedger[].netPnl` (within float tolerance).
- `metrics.tradeCount` equals `tradeLedger.length` exactly.
- `metrics.winRate` equals a hand-computed win rate from the ledger.
- The derived `equityCurve`'s final point equals `finalAccount.balance` exactly — same number, confirming the derivation introduces no drift.
- `finalAccount.balance === initialBalance + realizedPnl` — the same identity the P3.1 Backtest Truth Audit verified on synthetic data, now reconfirmed on real market data.
